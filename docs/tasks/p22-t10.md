## Deliverable

Own `messages.store_groups`, bounded correspondence ingestion and durable sender-group persistence.
Expose authorized thread references for T25 to consume. T24 supplies shared plan authoring for
end-to-end task entry; correspondence runtime and storage can be developed independently.

Read a bounded window across every correspondence connection the user is authorized to use in
settings, including multiple accounts and providers across email, social correspondence and
messengers. All connected correspondence is the default without per-source enablement. Allow
explicit narrowing in the same task. New authorized connections enter the default scope on the
next use, including scheduled runs. T24 resolves and pins the exact scope for each run.

Upsert through the UnifiedMessage and MessageThread managers. Group by verified identifiers
linked to the same contact across providers and accounts. Keep unresolved or ambiguous
identities separate by source account and sender identifier. Matching display names supply
no identity evidence. Offer sender lookup in «Общение» → «Переписка» and link task results to
the authorized group. Show permitted messages chronologically, keep their original thread
membership and link to their source. Pass authorized thread references to [P22-T15](p22-t15.md)
and [P22-T25](p22-t25.md). Direct sender lookup includes all permitted ingested correspondence regardless of which task or connector ingested it. Opening a specific run shows its coverage and links into the same sender history.

## Implementation sequence and handoff

1. Inventory user-connected correspondence readers and their account authorization, bounded
   windows and retained metadata. Implement each missing reader needed for those connections.
2. Feed each source through the existing ingestion path and merge message evidence into the
   same sender view. Use each upstream message's source and account in its durable identity.
3. Give T08 and T12 a complete Tasks → Messages journey with verified and unresolved sender
   identities, per-source receipts, unavailable readers and repeat runs.

## Acceptance

One task reads permitted email, social correspondence and messenger accounts together. A
sender with verified identifiers appears in one group across these sources. Sender lookup
opens the group's chronological correspondence with original threads and permitted source
links. Ambiguous or same-name senders remain separate. Repeating a run or replaying its evidence
introduces no duplicates. Source coverage distinguishes successful reads with zero messages
from unreachable sources and absent readers. Report absent readers and track them as unmet
delivery. Hide revoked sources and their evidence from results when access is lost. Apply
existing retention policy and keep message bodies and attachments out of task rows and prompts.

across provider types. Include a new connection after publication, colliding upstream IDs,
