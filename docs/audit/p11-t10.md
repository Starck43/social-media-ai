## Delivered contract

The task CLI is now labelled and enforced as an operator-only, database-bypass
tool, and its machine contract is stable.

- `cli/commands/tasks.py` holds the task commands extracted from `cli/main.py`
  over the same use-cases; `cli/main.py` keeps its callbacks and platform
  helpers, and no task behaviour was dropped in the move.
- `_run_task_platform` re-reads the ambient actor (`User.objects.get(id=actor_id,
  is_active=True)`) and requires `is_platform_admin` at execution time, then binds
  the fresh actor with `permission_scope(fresh_actor)`. Authority is never taken
  from a stale session, and `tenant_scope(bypass=True)` is used only for access,
  never as a substitute for a permission check.
- `_require_explicit_tenant` makes `--tenant` mandatory for tenant-scoped task
  commands: absent or empty is a usage error (exit 2), an unknown workspace is
  exit 3, and a name that matches several tasks in one workspace is exit 3.
  Task lookups always carry `tenant_id=tenant_id`, so a foreign task is not
  resolvable from another workspace.
- `cli/commands/task_output.py` provides a versioned JSON envelope, stable
  exit-code mapping (`human|json` output only), and secret-conscious rendering
  (`_SENSITIVE_KEY`, `_DIAGNOSTIC_KEY`, `_SECRET_VALUE`). `docs/CLI.md` documents
  the exit codes, the `--tenant` requirement and the operator-only distribution;
  `docs/generated/cli-commands.md` and `cli-options.md` are regenerated.

Behaviour change recorded for consumers: `task list`, `task result` and
`task plan` moved from `_run_platform` to `_run_task_platform`. They now require
an active platform-admin identity and exit 4 otherwise. That is the intended
operator-only hardening, and it breaks any read-only automation that ran them
without an operator identity. The transition is documented in `docs/CLI.md`.

No customer CLI, HTTP client, new permission grant or migration was introduced;
the future customer surface remains a token-authenticated HTTP adapter per the
card's scope.
