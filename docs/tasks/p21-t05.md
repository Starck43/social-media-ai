# P21-T05 — Provider rate limits and circuit-breaker wiring

Registry: [ROADMAP](../../ROADMAP.md); parent: [P21](../phases/p21-ai-operations.md).

## Goal

Apply one shared, cross-process provider budget to LLM dispatch and add bounded
failure quarantine without creating a second scheduler or serialization system.

## Dependencies and scope

- Depends on P21-T02; coordinate with P21-T03 so admission denial and provider
  throttling remain different outcomes.
- Reuse `app/integrations/ratelimit/` PostgreSQL serialization and its
  `blocked_until`/Retry-After semantics where applicable.
- Replace or deliberately retain the process-local `LLM_REQUEST_DELAY` only after
  measuring compatibility; do not silently claim Redis is the LLM limiter.
- Circuit-breaker state must have an explicit owner, TTL, failure taxonomy and
  fail-closed behavior; no new table unless a reviewed schema contract requires it.

## Steps

1. Define provider/model/workspace keys, token/request units and Retry-After floor.
2. Wire the limiter at the dispatch seam and test multiple runtime processes.
3. Classify 429, 5xx, timeout, auth, validation and budget failures separately.
4. Add bounded breaker open/half-open/closed transitions and fallback behavior.
5. Verify lock timeout/unavailable-store behavior does not bypass controls.

## Acceptance

- Concurrent callers cannot exceed the configured provider bucket in the tested
  window; Retry-After is a floor, not shortened by refill math.
- Limiter outage/lock timeout fails closed or follows an explicitly reviewed
  bounded policy; it never silently bypasses spend/authorization.
- Circuit breaker opens only on the recorded transient-failure class, expires
  deterministically and does not turn budget/permission errors into fallback.
- No duplicate runtime owner, Redis queue, or unbounded retry is introduced.
- Multi-process and focused adapter tests, configuration contract and rollback
  switch are recorded.
