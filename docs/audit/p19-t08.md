## Outcome

Version history, diff and restore are no longer web-and-API only. One unchanging
`VersionService` now sits behind a CLI and a chat surface, with the permission, ACL and
`data_boundary` checks inherited from the service instead of re-derived.

## Delivered

| Surface | Entry points | Injection scope |
| --- | --- | --- |
| CLI | `documents history\|diff\|restore [--dry-run]` (`--tenant`, `--actor`) | `tenant_scope(tenant_id)` + `permission_scope(user, member_grants)`; the bypass/operator scope used to resolve the actor is dropped before the call |
| Chat | `documents_history`, `documents_diff`, `documents_restore_preview` | `collection.source.view` through the registry gate; read-only |

- CLI refusals map to exit codes 1/3/4/5 (refused / not found / conflict / invalid); no command
  opens a raw session.
- The chat surface cannot append a revision: the preview returns the body a restore would create
  plus the approval link, and the approval stays on the web decision surface.
- No migration; no change to `/api/v1` or web behaviour.

fixture guard and were therefore unrunnable on an isolated schema. They now assert an isolated,
non-empty schema; `resolve_and_redirect` already refuses the working schema, so the safety intent
is intact. Rollback is the single assertion, with no application code involved.
