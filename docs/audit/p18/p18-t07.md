## Delivered

- `local_connector/packaging/build.py` — unsigned PyInstaller standalone
  development bundles, version and `--self-test` probes, an authenticated
  update-archive layout and an optional native desktop build.
- `local_connector/packaging/updates.py` — Ed25519 verification over the exact
  manifest bytes before any parsing, closed schema, product/platform/version
  and lifetime checks, artifact size and digest checks.
- `local_connector/packaging/updater.py` — the automatic updater: a signed
  release is installed into an owner-private version slot, the staged binary
  must pass the `--self-test` health probe before the active pointer flips, and
  a failed probe leaves the current slot, the local index and user data
  untouched. Rollback re-activates the previously installed, still
  authenticated slot; the version floor only rises, so a rollback cannot
  re-open a downgrade path. State (`active`, `previous`, high-water) is written
  atomically and durably.
- `local_connector/packaging/updater.py` (feed) — a read-only HTTPS feed at a
  fixed base baked into the build: no credentials, query, fragment, non-443
  port or redirect; manifest, signature and artifact URLs are derived from the
  signed digest, never from manifest content; bounded reads with a total
  deadline.
- `local_connector/packaging/key_store.py` — device credentials in the
  operating system key store. Only the explicitly approved backend for the
  running platform is loaded (macOS Keychain, Windows Credential Manager, Linux
  Secret Service); there is no plaintext fallback and no backend
  autodiscovery, so `PYTHON_KEYRING_BACKEND`, `keyringrc.cfg` and plugin
  priority cannot redirect material into a file backend. Enrollment material is
  operator-supplied: no CA, key or certificate is generated here.
- `local_connector/packaging/tls_probe.py` — a no-data mutual-TLS diagnostic:
  one handshake against an explicit hostname allowlist with a caller-supplied
  CA and the OS-stored device key. No application data, no file or database
  write, and the temporary key material is unlinked on every exit path.
- `local_connector/packaging/windows_fs.py` — the native Windows adapter:
  component-wise pinned opens without delete sharing,
  `FILE_FLAG_OPEN_REPARSE_POINT`, reparse/junction/UNC/device denial, identity
  and size checks around reads, owner-only protected DACL enforcement for the
  private cache and a `MAXIMUM_ALLOWED` retry for a denied access mask.
- `local_connector/packaging/desktop.py` — optional native tray controls
  (choose folder, delete/resume the local index, check for an update, roll the
  application back).
- `local_connector/packaging/bootstrap.py` — the frozen entry point: it selects
  the authenticated slot, exposes `--self-test`, `--verify-update`,
  `--install-update` and `--rollback`, and reads the trust anchor and the feed
  from the frozen bundle only.
- `docs/LOCAL_CONNECTOR.md` — install, update, rollback and complete-removal
  instructions per D6, including the data locations and the SmartScreen /
  Gatekeeper steps.

### Route and its limit

The earlier cycle used the configured build parent and the configured River
tester without a model override. In the final cycle every delegated route
failed before execution: the configured tester and the external Perch executor
with `Billing: insufficient_funds`, and `free-pi` because its CLI is below the
required minimum version 0.6.21. The focused checks were therefore executed in
the parent session instead of being delegated, and this is recorded rather than
hidden. The delegated cycle must be repeated when billing works; the code under
test does not change with that repetition.

## Corrected during review

Three real defects were found in the delivered increment and fixed before
acceptance; the fixes are part of the accepted source:

1. The updater did not refresh its in-memory state after a successful install
   and did not re-authenticate the extracted files before activation. Both were
   added, so a modified slot cannot be activated or reported as active.
2. The Windows adapter opened a file with a fixed access mask without the
   documented `MAXIMUM_ALLOWED` fallback, and it did not pin the ancestor
   directories while a file was read. A directory replaced during a read is now
   detected by resolving the ancestor path again afterwards.
3. The private-directory check trusted a status code instead of the security
   descriptor, so an object without a protected owner-only DACL could be
   accepted. The descriptor is now proved, and the private cache additionally
   requires read sharing.

## Recorded gates — UNRUN, not waived silently

These remain required for installable production support and were accepted
only as recorded open work, not as evidence:

1. **Three-OS native evidence.** CI artifacts for Windows/macOS/Linux and the
   native execution of the slot installer, the feed client, the rollback path,
   the OS key store and the mTLS diagnostic. The Q-13 master-only Actions
   policy prevents PR CI and was neither changed nor bypassed here.
2. **Windows runtime enablement.** The native adapter exists, but the Windows
   bootstrap still denies a normal launch and the selected-root/private-cache
   integration is not switched over. The exact call sites are listed in the
   archived card; the change touches `local_connector/paths.py` and
   `local_connector/index.py`, which belong to the accepted P18-T03 contract
   and need their own coordinated commit and native Windows evidence.
3. **Real OS key store and real mTLS deployment** on every OS, coordinated with
   [Q-19](../../tasks/q-19.md) R-4.
4. **A real update feed and signing key.** No feed URL, trust anchor, signing
   key or release publication is provisioned here; the release operator
   supplies them, and key rotation/revocation must be reviewed first.
5. **Installer and tray user-flow acceptance** on the three desktop platforms.

D6 defers Windows code signing and macOS notarization only; it does not cover
any item above.
