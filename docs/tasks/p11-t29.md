## Delivered contract

- Platform `WorkspaceOffboardingEvent` survives workspace/actor deletion: plain
  numeric identities, operation UUID, UTC time, allowlisted reason/policy,
  expired-audit count and success only. No raw form, secret or workspace content.
  DB guards reject UPDATE/DELETE/TRUNCATE; manager checks the real guard function
  definitions and active trigger signatures before append/read/export.
- Superuser-only console action **Удалить с аудитом**: single-workspace setup,
  CSRF-protected preview, signed actor/target/version/reason/policy/UUID review,
  then explicit checkbox confirmation. Legacy CRUD/bulk DELETE is disabled.
- Retained task-admission audit always blocks deletion. Default preserve mode
  retains all audit. Explicit expire-elapsed mode removes only events older
  than the current workspace plan policy; protected financial references block.
- Fresh active SU and workspace FOR UPDATE are rechecked in the transaction.
  Eligible expiry, deletion and journal append commit together or all roll back.
  Repeated still-valid confirmation returns its existing receipt. Concurrent
  competing reviews cannot record duplicate deletion.
- Journal HTML/CSV requires fresh SU even with manually assigned non-SU grants;
  HTML/CSV results are bounded to 100/1000. Minimal journal retention is indefinite.
- Alembic 0119 adds the journal/guards/catalog references, leaves task-admission
  audit intact and grants no ordinary role authority. Normal non-empty downgrade
  refuses; explicitly guarded disposable local test teardown supports validation.
- [WORKSPACE_OFFBOARDING](../WORKSPACE_OFFBOARDING.md) describes the exact policy,
  rollback, read/export and migration boundaries. Public apply is not authorized
  by repository acceptance and was not performed.
