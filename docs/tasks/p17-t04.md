## Goal

Create/post documents and update catalog items only after explicit approval.

- —

## Plan

1. Capabilities `onec.document.create.v1`, `onec.document.post.v1`, `onec.catalog.update.v1`, all off by default, require the separate write connection method (`odata_write_credentials`), with single capability spec registration in `app/services/commands/registry.py`.
2. Preview: typed payload validated against metadata, human-readable diff for updates, current object version (`DataVersion`) captured.
3. Approval via command ledger (per item); execute rechecks `DataVersion` (optimistic concurrency) and rights, and commits terminal failure/unknown states (`failed` with `error_code` or `unknown` with `ActionAuditEvent.objects.record_unknown`) before raising `OneCCommandError` to the API caller.
4. Idempotency: write a unique external reference (comment/attribute) and check for it before retrying a reconcile; timeouts → `unknown` + reconcile query via `POST /api/v1/integrations/1c/command/reconcile`.
5. API `POST /api/v1/integrations/1c/command/preview|approve|execute|reconcile`, `GET …/audit-log` (actor-scoped audit log of the current user's 1C commands combining `action_audit_events` + `business_commands`, matching `P17-T01` connection ownership and `P17-T03` `/query/history`; workspace-wide RBAC-filtered audit views across users/connections/operations belong to `P17-T05`).

## Acceptance

- TZ AC: write operations require approval; audit log of all operations.
- Changed object version after approval → refused (`state="failed"`, `error_code="data_version_conflict"` persisted in DB and exposed in `GET /api/v1/integrations/1c/audit-log`).
- Transport timeout on write → `state="unknown"` persisted in DB + `unknown` audit event recorded; `POST /api/v1/integrations/1c/command/reconcile` queries 1C by `external_ref` / `target_guid` and settles the command without duplicate writes.
