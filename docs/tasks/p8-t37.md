The worker re-queries current active/tenant/platform scope and intersects it with that collected set; mutable links, arbitrary payload keys and uncollected admitted sources cannot widen a planned unified run. - `prepare_task_plan_update` is the shared pure policy for API/CLI/chat replacement, preservation and conversion to digest/prune/learn/reflect. It rejects inline/protected-field overrides, keeps explicit replacement relationships/trigger coherent, and retires plan-owned collection/date/scenario projections on conversion. Unrelated payload data and an explicitly requested new legacy scenario are preserved. A retired plan timezone cannot leak into the new legacy schedule. Transactions, actor/payer/permission and execution checks remain at their existing boundaries.
- `apply_parsed_task_plan` projects an already validated typed plan, avoiding reparsing inside the same binding check. The manager still validates persisted state at writes/admission. The two equivalent scenario inequalities become one; API preview serializes once. Admission and worker share one pure platform predicate.
