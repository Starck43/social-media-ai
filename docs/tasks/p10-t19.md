### Fix (2026-10-26, `b8eddfd`)

- **Harness (`tests/conftest.py`)**: the operator grant now covers *arrange
  only* — a `tenancy`/security test gets neither `is_bypass` nor the grant. For
  async tests the grant is closed at the start of the driver task
  (`tests/conftest_async.py` + `tests/shared/async_test_scope.py`), because
  pytest-asyncio copies the runtest context into the coroutine and from there
  into every transport task: a fixture generator cannot unset it. Source-only
  doubles keep it (they read the actor from it, never storage).
- **Product defect found by a failing case (`app/models/managers/base_manager.py`)**:
  under superuser bypass, `_apply_tenant` ignored the tenant already in context
  and stamped the *bootstrap* workspace. A request that selected a workspace
  wrote its row into the wrong tenant — created, then invisible to its own
  scoped read, with the success flash already rendered. It now prefers the
  contextual tenant and falls back to the default only when there is none. This
  was the real cause behind `test_web_permissions.py::test_owner_may_create_a_task_and_sees_the_button`.
- **Authorization (`app/core/permissions.py`, `app/web/nav.py`)**: `member_decision`
  abstains without a stated preset; a platform grant answers only outside a
  tenant; `permission_scope(is_owner=True)` always replaces the owner preset;
  `nav.allows()` resolves catalog keys (`scheduling.task.view`) via
  `resource_for`, with `resource.key` as the fallback the nav stub uses.
- **Stale expectations updated to the current contracts**: role controls are
  `popover_select` (hidden input + `aria-selected`), the dashboard section is
  `data-home-tasks` («Ближайшие запуски»), chat is the separate `ai_chat_enabled`
  grant rather than a role right, `_is_superuser_role()` is only `superuser`,
  role-grant writes need an active platform admin, and workspace rights come
  from `workspace_grants(<role>)`. The invite helpers now follow the revoke
  redirect as one request — the extra `?tab=team` GET used to consume the flash
  the assertion was looking for — and read the list from the on-demand dialog.
- **New guards**: `tests/security/test_p10_t19_harness_scope.py` (the grant is
  visible to arrange, absent in async body and children),
  `tests/security/test_p10_t19_member_presets.py` (preset decisions per
  workspace role, and abstention without one).
