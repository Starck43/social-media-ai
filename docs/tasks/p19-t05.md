### Owner storage decision and DDL allocation request

The owner decided: rendered attachment bytes are stored encrypted in PostgreSQL by P19-T05; no reusable byte store or hash-read API exists. P15-T14 stores references only and calls a new, tenant-scoped P19-T05 read service by exact attachment hash. S3 is out of scope under D9/R-18. This request is for auditor allocation; **no migration revision is allocated and no migration has been written**.

Proposed complete DDL (schema supplied by `DB_SCHEMA`, never hard-coded `public`):

```sql
CREATE TABLE <schema>.document_export_artifacts (
  tenant_id integer NOT NULL,
  document_id integer NOT NULL,
  revision_id integer NOT NULL,
  revision_body_hash varchar(71) NOT NULL,
  payload_sha256 varchar(71) NOT NULL,
  payload_encrypted text NOT NULL,
  size_bytes integer NOT NULL,
  mime_type varchar(127) NOT NULL,
  created_at timestamptz NOT NULL DEFAULT now(),
  CONSTRAINT pk_document_export_artifacts PRIMARY KEY (tenant_id, payload_sha256),
  CONSTRAINT fk_export_artifact_tenant FOREIGN KEY (tenant_id)
    REFERENCES <schema>.tenants (id) ON DELETE CASCADE,
  CONSTRAINT fk_export_artifact_revision FOREIGN KEY (tenant_id, document_id, revision_id)
    REFERENCES <schema>.document_revisions (tenant_id, document_id, id) ON DELETE CASCADE,
  CONSTRAINT ck_export_artifact_revision_hash CHECK (revision_body_hash ~ '^sha256:[0-9a-f]{64}$'),
  CONSTRAINT ck_export_artifact_payload_hash CHECK (payload_sha256 ~ '^sha256:[0-9a-f]{64}$'),
  CONSTRAINT ck_export_artifact_payload_nonempty CHECK (length(payload_encrypted) > 0),
  CONSTRAINT ck_export_artifact_size_positive CHECK (size_bytes > 0),
  CONSTRAINT ck_export_artifact_mime CHECK (mime_type IN
    ('application/pdf', 'application/vnd.openxmlformats-officedocument.wordprocessingml.document'))
);
```

No other table, column, index (apart from the primary-key index), constraint, trigger or catalog change is proposed. Downgrade must refuse while any artifact rows exist. No fixed ciphertext/size ceiling in SQL: propose application setting `DOCUMENT_EXPORT_MAX_BYTES`, default 26214400, minimum 1 and maximum 26214400 (existing outbox ceiling), checked before encryption and after decryption. `payload_sha256` hashes exact plaintext bytes; encrypted text is an authenticated token, never plaintext. Duplicate `(tenant_id, payload_sha256)` writes must re-read and require identical revision, hash, size and MIME; a conflicting binding fails closed. Cross-tenant lookups are opaque. The read service verifies authenticated decryption, size and SHA-256 against the saved row and requested hash, rechecks revision/approval and current rights as appropriate at its call boundary; it is not a public unauthenticated hash endpoint. Revision-body hash is not interchangeable with payload hash. Filename can be safely derived from stored revision and format, not used as evidence.

Encryption should use a purpose-separated authenticated key derived from the existing configured encryption key, without reusing the `PrivateCipher`'s canonical-JSON-only format; unavailable/rotated key fails closed. Key rotation/re-encryption and cleanup/retention require explicit handling before READY. Request to auditor: allocate a revision and parent against live dev for exactly this DDL.
