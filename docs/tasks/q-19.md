## Why this exists

`docs/connectors/LOCAL_CONNECTOR_PROTOCOL.md` was accepted as the contract P18 implements
against. Acceptance covered the document, not a security verdict, and no line of
it has been exercised by a running system. This question keeps those gaps visible
until a second party closes them, so "accepted" is never mistaken for "verified".

## What is already done

A first-party review by the accepting auditor, against the eight questions that
were published as the review brief. Results are in [the P18-T01 audit](../audit/p18-t01.md#independent-review-of-the-eight-questions).
That review is a reading of the text: it finds the obligations that a later
implementation would have to meet, it cannot show that any of them holds.

## Owner decision for P18-T02 (2026-11-04)

The owner explicitly replied "Согласую эти параметры" to the concrete implementation proposal:
restricted canonical UTF-8 JSON with ASCII schema keys, sorted keys, no floats or duplicate keys;
Ed25519 signatures; explicitly configured operator-owned CA and client certificates valid for at
most one hour; five-minute pairing codes; and a digest-only replay ledger retained for 24 hours,
bounded to 4096 entries per device. Deployment private keys are never generated implicitly.
The feature remains default-off until the independent review and a real trusted mTLS deployment
are verified. This decision resolves R-2 for these parameters; it does not claim R-1, R-3 or R-4
evidence or authorize activation for real users.

## P18-T02 second-party source review (2026-11-04)

Native helper `p18_t02_protocol_tests`, distinct from the accepting auditor, reviewed the
gateway source at `f7259b49f84d5439bf7ce43d69a327d8761ce9d1`. Pairing serialization,
fingerprint binding, owner/tenant isolation, consent/epoch checks, replay bounds and the
search release/revoke fence were reviewed. The review found a missing pre-ASGI message
limit in the Docker image's default CMD; the correction and deployment guard passed
targeted review. No blocking source finding remained for the default-off single-process
scope. Source review is separate from execution evidence.

The channel registry and release fence are process-local. A trusted mTLS adapter,
operator key distribution/rotation/recovery and real device/key-store/path evidence
remain gates before real-user activation. No reviewed Uvicorn/Nginx configuration
currently supplies authenticated ASGI TLS identity, so missing identity denies admission.
R-3 remains subject to the implementation evidence in each delivered task; desktop
traversal, OS access and real-platform behavior are not claimed by this server review.

The chat implementation was independently reviewed by native helper
`p18_t02_ws_frame_limit`; its reviewed source blobs match the accepted server/chat
implementation. The final coordinator review covered source
`8618eeb0634fa2600be558fb611c3433f51b109b`, including malformed-response sanitization.
The [P18-T02 audit](../audit/p18-t02.md) records 56 passing focused tests, 93.41%
coverage and the isolated migration cycle. This does not close the real-platform
and activation requirements below.

## Boundary

Nothing here blocks P18 implementation from starting: the protocol is accepted as
the design. It blocks treating the protocol as security-verified, and it must be
resolved before any connector is enabled for a real user.
