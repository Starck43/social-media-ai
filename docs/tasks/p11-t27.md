# P11-T27 — Admin console audit and operator tooling hardening

Registry: [ROADMAP](../../ROADMAP.md#p11). Parent: [P11](../phases/p11-structure.md) (navigation only).

## Scope, evidence and acceptance

**Evidence:** a full read of `app/admin/` (~6k lines), its templates and
[ADMIN.md](../ADMIN.md) surfaced four groups of defects in the operator console:

1. **CSRF posture is inconsistent.** `edit.html` renders a hidden `csrf_token`,
   but no generic SQLAdmin create/edit/delete route verifies it
   (`verify_token` runs only on login, catalog edits, password routes and the
   LLM test POST); `create.html` does not render a token at all. Protection of
   every CRUD write currently rests on the Starlette session cookie's implicit
   `SameSite=Lax` default, never declared explicitly. The token itself is a
   process-global 30-minute signature, not bound to the session it protects.
   Two more CSRF implementations are dead code: `CSRFMiddleware` (csrf.py) is
   never registered and `csrf_middleware` (middleware.py) is commented out in
   `app/main.py`.
2. **State-changing custom actions run on GET.** `run-now`, `toggle-active`,
   `send-to-messenger` and `test-connection` mutate state or spend provider
   tokens from a bookmarkable, CSRF-free GET URL; `send-to-messenger` also
   takes `recipient_id` from the query string, against the console rule that
   identity never comes from path/query. The LLM model test already shows the
   correct pattern (GET renders, explicit CSRF-checked POST executes).
3. **Secrets and identity handling.**
   `LLMProviderAdmin`/`UserCredentialAdmin` encrypt secrets in
   `after_model_change`, i.e. *after* the plaintext value has been flushed to
   the database once, and the edit form round-trips ciphertext through the
   browser. Operator identity resolution (`token -> fresh user -> role ->
   has_admin_access`) is implemented four times: `auth.authenticate`,
   `authorization.resolve_user`, `scope._session_user` and inline copies in
   `endpoints.py`. `change_password_form_path` mutates the global
   `admin.title` per request (leaks "Смена пароля" onto every later console
   page). `verify-current-password` has no rate limit — an online password
   oracle. Login leaves stale keys (`return_url_*`, `_messages`) in the
   session.
4. **Maintainability/performance.** `AgentTaskAdmin.on_model_change` is a
   ~150-line god method mixing payload validation, task-plan reconciliation,
   source guards and cron scheduling. `AdminSession._scope_reads` recomputes
   per-model criteria for every mapper on every SELECT; `AdminScopeMiddleware`
   re-reads memberships with per-membership grant queries and re-derives the
   view classification on every request; `build_table_registry` rescans
   metadata per request. `csrf.py`/`widgets.py` use tabs and Russian
   docstrings against the English/Black rule; `notifications.py` carries
   mojibake ("Краткая сут уведомления"); `BaseAdmin` keeps two no-op hook
   overrides; `setup.py` keeps commented-out code and builds a second
   `CSRFTokenManager` next to the one in `app/main.py`.

**Change:** harden and simplify the console in reviewable slices, keeping every
existing access rule and regression green:

- **S1 hygiene:** delete dead CSRF implementations and commented code; convert
  `csrf.py`/`widgets.py` to spaces/English; fix the notifications mojibake;
  drop no-op hooks; render the change-password title via template context
  instead of mutating `admin.title`; single `CSRFTokenManager` instance.
- **S2 CSRF:** one console-scoped verification point for every mutating
  `/admin/*` POST (SQLAdmin CRUD included), session-bound tokens, explicit
  `same_site="lax"` on the session cookie, token field in `create.html`,
  rate limit on `verify-current-password`, session hygiene on login.
- **S3 secrets:** encrypt-before-write in `insert_model`/`on_model_change`
  through one shared helper; blank secret field keeps the stored value and
  ciphertext never round-trips to the browser.
- **S4 actions:** move mutating/paid custom actions behind explicit
  CSRF-checked POSTs with a confirmation step, following the model-test
  pattern; drop the query-string `recipient_id` from `send-to-messenger`.
- **S5 structure:** one operator-identity resolver used by auth, authorization,
  scope and the standalone endpoints; decompose
  `AgentTaskAdmin.on_model_change` into named helpers without behavior change.
- **S6 performance:** cache per-request row criteria, the workspace-page
  classification and the table registry; read membership grants without the
  per-membership N+1.
- **S7 UX/docs:** group the flat 17-entry menu by domain (SQLAdmin
  categories); update [ADMIN.md](../ADMIN.md) to the resulting contract.

**Acceptance:**
- No behavior change to scope/ownership rules: the existing admin test suites
  (`tests/admin/`) stay green, with focused new regression tests for S2/S3/S4.
- Every mutating console POST requires a valid session-bound CSRF token; no
  state change or paid/provider call remains reachable via GET.
- Plaintext secrets never reach an INSERT/UPDATE; ciphertext never renders
  into a form.
- One identity resolver, one CSRF implementation, one token manager.
- ADMIN.md describes the resulting behavior; Black/isort (line 120) clean.
- Rollback is a revert of the scoped branch; no DB or schema change.

**Dependencies/risk:** P11-T11 (web/admin decomposition) and the scope
regressions of P8-T30/T31/T32 bound this work. S4 changes operator muscle
memory (actions become two-step POSTs) — flagged in ADMIN.md. No migration,
no runtime topology change, no merge without the owner's explicit choice.

S2 gotchas (both cost a full console outage when missed, both fixed on the
branch — keep them fixed):

- sqladmin mounts itself as a Starlette sub-application at `/admin`, so inside
  console routes `request.app` is that sub-app, not the FastAPI app. Anything
  read from `request.app.state` (the CSRF manager, the admin instance) must be
  published on the mounted app too — see `setup.py`.
- `AdminCSRFMiddleware` parses the request form; Starlette's form parser drains
  the body stream, so the body has to be cached *before* parsing and replayed
  to the route. `tests/admin/test_p11_t27_csrf_middleware.py` pins this.
