## Goal

One tenant-scoped contact model that Bitrix24, the communication hub, the planner and documents all reference.

## Baseline

- No business contact model; messenger identities exist only for chat membership (`app/agent/identity.py`).

## Plan

1. Model `contacts`: tenant, display name (encrypted), preferred channel, last active channel/time, birthday/anniversary (encrypted date or month-day + year flag), notes, `merged_into_id`, timestamps.
2. Model `contact_identities`: tenant, contact, kind (`email`, `phone`, `telegram_id`, `telegram_username`, `max_id`, `bitrix24_contact`, `bitrix24_company`, `bitrix24_lead`), source connection, encrypted value, blind index, verified flag, source native ID; unique `(tenant_id, kind, blind_index, connection_id)`.
3. Model `contact_consents`: channel, purpose (`transactional`, `greeting`, `marketing`), basis, granted/withdrawn at, source evidence; default none.
4. `ContactManager` with tenant-scoped CRUD, identity attach/detach, lookup by normalized identifier, and a merge journal table used later by [P15-T03](p15-t03.md).
5. `/api/v1/contacts` read/list/detail (no merge yet) and a minimal `/app/contacts` list behind the existing nav group (coordinate nav edits as a separate small commit).
6. Retention/offboarding: register tables with workspace offboarding and privacy export/delete flows (P6 contracts).
