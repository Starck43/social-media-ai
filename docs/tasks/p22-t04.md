## Deliverable

Bind existing jobs to a durable task run and revision. Share admission between manual, chat and automatic starts. Derive scheduled keys from trigger identity and occurrence, manual keys from intent. Lock scope and enforce overlap policy. Snapshot authorized principal, payer, limits and permitted effective inputs. Preserve retries, fencing, idempotent receipts after job pruning, cancellation and unknown-outcome handling. Isolate scheduled system maintenance from user Tasks.

## Implementation sequence and handoff

1. Trace app/services/task_launch.py and app/tasks/runner.py into the queue. Identify the transaction that assigns the occurrence key and the worker claim that fences completion.
2. Admit the same published revision manually and on schedule. Persist the run and enqueue intent atomically. On a replay return the original receipt; on a key reused with different inputs return a conflict.
3. Give T05 and T07 the run receipt and permitted result projection. Include an example with a manual run immediately before a scheduled fire and specify what the scheduler does when the manual run is still active.

## Acceptance

A manual launch on an enabled schedule leaves next due time intact. A scheduler race, repeated request or worker recovery cannot duplicate one occurrence, cost or external effect. A failed/partial run returns bounded progress and evidence and leaves the human work state meaningful. A revoked connection between preview and execution stops the affected step.

## Verification at implementation
