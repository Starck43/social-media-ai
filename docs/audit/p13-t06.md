# P13-T06 — Accepted coverage gate and mock-provider test kit

**Verdict: ACCEPTED — 2026-11-03.** Accepted source `215dd57c` on `fix/p13-t06-audit-findings`, merged to `dev` as `89ec26bb` (PR [#348](https://github.com/Starck43/social-media-ai/pull/348)).

Scope accepted: the per-target coverage CLI and manifest, synthetic provider doubles with a socket/DNS tripwire, two-actor/two-tenant fixtures and their focused tests. This closes the task card, not the P13 phase.

## What was delivered

- `scripts/ci/package_coverage.py` measures each source target independently, fails on missing coverage, zero executed tests and missing statements, and prints a per-target table. `--changed-from` selects manifest entries; the manifest starts empty because no business package exists yet.
- `tests/shared/provider_http.py`: explicit `(METHOD, exact URL)` `httpx.MockTransport` that rejects unregistered requests, plus `deny_network()` as a socket/DNS tripwire. `MailDouble` is a scripted in-memory double, not an IMAP/SMTP implementation.
- `tests/shared/business_tenancy.py`: DB-free two-actor/two-tenant fixtures, `assert_cross_tenant_not_found`, and a `business_db_world` wrapper over the existing manager-backed `personal_world`.
- `tests/shared/README.md` usage section.

## Findings raised and closed

The independent audit (PR [#344](https://github.com/Starck43/social-media-ai/pull/344) comments) found four issues; three were corrected before acceptance:

- **F-1 (blocked READY):** the DB fixture test sat in `tests/security/`, so any directory-wide run there would bootstrap `DB_TEST_SCHEMA` and take exclusive ownership of a shared schema. Moved to `tests/tooling/test_p13_t06_db_fixtures.py`.
- **F-2:** renamed to `test_business_db_world_exposes_manager_backed_identities`; it asserts the wrapper exposes manager-readable identities, not cross-tenant isolation.
- **F-3:** the card now states why a per-package gate coexists with the project-wide coverage setting in `pyproject.toml`.
- **F-4:** a merge of `dev` inside an open PR; resolved by merging current `dev` before the fix commit.

## Limits

- Synthetic provider bodies are examples, not recordings and not evidence of a real provider API contract. No real provider was called.
- The DB fixture validates the wrapper's wiring; proving authorization isolation needs the application's own flow (P13 business modules).
- The gate is invoked explicitly. Until a package is registered in `scripts/ci/coverage_packages.toml`, an empty selection means *no coverage measured*, not a pass.
