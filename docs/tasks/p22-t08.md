Keep a link to the current section after login or legacy redirect.

## Implementation sequence and handoff

1. Start at app/web/task_surface.py. Map each branch of the editor to the T07 preview fields and action response. Draw the shortest path for a title-only save.
2. Implement title → optional timing/people → save, then the automation branch. When switching mailbox accounts on Back, retain the title and deadline, clear the old folder and request a new authorized selection.
3. Provide rendered create/edit journeys and keyboard/mobile evidence, including an edit conflict and deletion confirmation. Later verticals supply their own capabilities through this same flow.

## Desktop handoff

Follow the [prototype](../product/prototypes/workspace.html). Title alone saves. Multiple sources, a reusable or newly authored scenario and a run schedule are optional. For Platform-backed sources progressively reveal scope, time window, authors, phrases and scenario-specific targets. Preserve compatible long-text drafts on Back. The drawer edits title and description directly. «Изменить задачу» opens the full editor with one Back arrow in the header and space before footer actions.

Use [T18](p22-t18.md) for intersecting filters, calendar and Today data. «Все» clears the chips. Calendar belongs inside Tasks. Show timed entries in order and open the full day from overflow. Use [T17](p22-t17.md) for confirmed closure, including scheduled work. Render «✓ Задача закрыта» after success. Show T14 delegation only for eligible open tasks without a scenario across all task surfaces.

## Acceptance

From the same entry create a deadline note, a team assignment and a scheduled collection. Run now on a scheduled task, inspect a run, accept/reject and preview/confirm deletion from detail. Buttons follow available actions. Show an unavailable source explicitly. Today, calendar, chat and notifications link to the correct canonical card and distinguish due dates from run times.

From chat, create a title-only task, add an assignee and a scheduled read on the same ID, then run it manually. Confirm that saving the edit adds no immediate run, the cron cursor survives manual launch, and the work status stays distinct from run status. Open a legacy planner and agent URL with the same numeric ID and verify each resolves to its own mapped target. Compare visibility for a planner-only actor and an agent-only actor before and after migration.
