## Why one shared double instead of 20 fixture patches

Twenty-one files failed for one structural reason: `base.html` and its partials read
a fixed surface — `user.has_admin_access`, `perms.can`, `perms.can_open_chat`,
`perms.workspace_role`, … — and every isolated template test built its own
`SimpleNamespace`. Each new attribute read by a template broke the whole directory
at once, and nothing told the author which attribute they had just made mandatory.

`tests/shared/template_shell.py` now declares that surface once
(`SHELL_USER_ATTRIBUTES`, `SHELL_PERMS_ATTRIBUTES`) with **deny-by-default**
`shell_user()` / `shell_perms()`. A test that wants a privileged surface must pass
the grant explicitly, so a fixture can no longer accidentally render an admin entry
or a chat launcher.

`tests/unit_web/test_q17_shell_contract.py` is the drift guard: it scans every
`app/web/templates/web/*.html` for `user.X` / `perms.X`, asserts each attribute is
declared, asserts the defaults deny, and strict-renders `base.html` through the
doubles. Adding a template attribute without declaring it now fails immediately with
the attribute name instead of breaking twenty files with `UndefinedError`.

## Intent restored, not weakened

Several assertions described behaviour that genuinely moved; those were rewritten
against the new owner of the guarantee rather than deleted:

- `test_admin_entry_follows_platform_admin_access_not_workspace_role` — the admin
  entry is gated on `User.has_admin_access()` (platform role), not on a session or a
  workspace role. The two tests that asserted "every authenticated role sees the
  entry" described the pre-`eb6cad6c` contract and now assert the opposite, and the
  shell double denies admin access by default.
- `test_every_chat_route_carries_the_deny_guard` — the old test pinned a fixed set of
  three chat routes, so six new attachment/context routes were added without any
  guard check. It now walks `app/web/chat.py` and fails if any decorated route lacks
  `_chat_denied`.
- `test_yandex_disk_pilot_stays_read_only_without_the_write_capability` — the Yandex
  Disk card left the generic "unavailable" branch for the read-only pilot partial;
  the replacement asserts the pilot copy and that no method field and no
  `/app/settings/workspace-connections` form appears without workspace write
  capability.
- `OAUTH_MECHANICS_ONLY = {"google_calendar"}` — that catalog entry exists for its
  token endpoints only (`app/web/settings_oauth.py` refuses it with
  `calendar_selection_required`); the test now states that explicitly instead of
  forcing presentation fields onto a non-presentable provider.
- `test_communications_jinja_template_strict_rendering` — the old assertion pinned
  copy from the pre-P20-T09 outbox lifecycle section. The inbox no longer claims
  delivery at all, so it now asserts no "отправлено" state can appear there (the
  outbox lifecycle itself is asserted earlier in the same file).
- `test_analysis_result_ids` keeps its tenant-scoping assertions; only the
  entitlement ledger and capability helpers are doubled, because the ledger has its
  own tests and the failure was the missing double, not a scoping change.
- `test_task_source_picker` / `test_template_autoescape` keep every XSS payload
  parametrization; the loader namespace gained `Path`/`__file__` and the context
  gained the two keys the editor now serializes.

One application edit was needed: `app/web/templates/web/commands.html` rendered an
`<h1>` inside a page body (the shell owns the single `h1`) and carried a task-ID
suffix in user-visible copy. It is now an `<h2>` reading «Единый инбокс
согласований». No behaviour change.
