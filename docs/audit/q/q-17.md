## What was wrong

The card quoted `1b470838` numbers (28 failed / 4 errors). The measured baseline on
`dev` `8f0149e1` was **109 failed / 686 passed / 4 errors** across 21 files. The card's
own numbers had gone stale, which is exactly the debt it describes.

One structural cause: `app/web/templates/web/base.html` and its partials read a fixed
`user.*` / `perms.*` surface, while every isolated template test carried its own
`SimpleNamespace`. Any new attribute read by a template therefore broke the whole
directory at once with `UndefinedError`, and nothing told the template author which
attribute had just become mandatory. Twenty-one files, one cause.

## What was delivered

- `tests/shared/template_shell.py` — the shell contract declared once
  (`SHELL_USER_ATTRIBUTES`, `SHELL_PERMS_ATTRIBUTES`) with deny-by-default
  `shell_user()` / `shell_perms()`. A test that needs a privileged surface passes the
  grant explicitly, so a fixture can no longer accidentally render an admin entry or a
  chat launcher.
- `tests/unit_web/test_q17_shell_contract.py` — drift guard: scans every
  `app/web/templates/web/*.html` for `user.X` / `perms.X`, asserts each attribute is
  declared, asserts the defaults deny, and strict-renders `base.html` through the
  doubles. A new template attribute now fails immediately with its own name.
- The remaining files fixed against the code they describe: moved helpers
  (`resolve_operator_identity` → `app/admin/identity.py`, `_is_personal_connector_path`),
  new view keys (`channel_filter`, `triage_category_filter`, `target_fields`,
  `source_groups`), changed dep surface (`ensure_csrf`/`perms_can`), the loader
  namespace (`Path`, `__file__`), and the `app.web` package initializer's dependencies.
