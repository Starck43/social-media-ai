# P13-T03 — Shared external-API rate limiter and retry policy

Accepted 2026-11-04 on `dev` `c51847dc` (PR [#370](https://github.com/Starck43/social-media-ai/pull/370)).
The draft [#366](https://github.com/Starck43/social-media-ai/pull/366) was closed on a base
that had already been merged and could not be reopened; #370 re-cuts the same tree directly
on `dev`.

Owner decision 2026-11-04: budgets are **tenant-scoped**. The first revision asked
for a platform-wide row, which is not what the tenant rule allows and not what this
task needed — see [the tenant rule](../BUSINESS_MODULES.md) and
[the authorizations that outlive the register](q-18-owner-decisions.md#authorizations-that-outlive-the-register).

## Delivered

- `app/integrations/ratelimit/store.py` — one PostgreSQL token bucket per budget:
  atomic first insert, `SELECT … FOR UPDATE`, server time, short transactions, so
  the API and runtime processes share state without a broker.
- `catalog.py` — code-owned policies (Bitrix24 2 req/s burst 50, 1C 10/min, Google
  Calendar and CalDAV conservative per connection) and `budget_for`, which turns a
  verified canonical account into a domain-separated HMAC digest under
  `RATE_LIMIT_KEY`. A budget never carries the provider identifier.
- `signals.py` / `retry.py` — HTTP 429 and `Retry-After` (seconds and HTTP-date),
  Bitrix24 `QUERY_LIMIT_EXCEEDED` and 1C 503 feed one shared cooldown; reads retry
  with bounded jitter, writes are never retried automatically and surface
  `WriteOutcomeUnknown`. Exhaustion is `ProviderDeferred`, not an error or an empty
  result.
- `app/models/integrations/rate_budget.py` — `TenantScopedMixin`, primary key
  `(tenant_id, provider, account_key)`, FK to `tenants` and a composite FK to
  `workspace_connections`, both `ON DELETE CASCADE`.
- `workspace_connection_manager.py` — disabling a connection deletes its budgets in
  the same transaction, so a cooldown cannot outlive the connection that earned it.
- `migrations/versions/0131_provider_rate_budgets.py` — follows `0130`.

`RATE_LIMIT_KEY` is its own secret: rebuilding account digests from `PII_INDEX_KEY`
would have refilled every bucket on an index-key rotation.

relation (`provider_rate_budgets`) and its row types; `alembic_version` moved
`0130 -> 0131`, and `model_types` gained nothing, which is why `migrations/env.py`
needs no new skip entry for `0131`.

The database tests cover concurrent acquirers across two sessions never exceeding the
budget, tenant isolation of cooldown and revocation, and the connection cascade
deleting only the disconnected tenant's budget.

## Fixed during acceptance

`test_connection_fk_cascades_only_its_tenant_budget` carried the revocation half of
its neighbour and referenced `first`/`second`, which that test defines and this one
never did. The PostgreSQL run failed on `NameError` after its own assertions had
passed. #370 moves that block into `test_cooldown_and_revocation_do_not_cross_tenants`,
where the names exist; the cascade test now asserts only the cascade.

## Not covered

- `tests/integrations/test_p12_t08_workspace_connections.py::test_migration_round_trip_preserves_legacy_vault`
  and `test_p12_t12_private_storage.py::test_credential_rotation_requires_explicit_private_result_purge_and_rolls_back`
  fail identically on `dev` `c51847dc`: the run needs a synchronous psycopg2 DSN, not
  the asyncpg URL. Pre-existing, unrelated to this task.
- No adapter is wired yet. `p14-t01`, `p16-t03` and `p17-*` must authorize the
  connection and pass a verified canonical account identifier before calling the
  limiter; the package itself makes no external call.
- `RATE_LIMIT_KEY` is not set in any deployed environment. It has to be generated
  and kept stable alongside `PII_INDEX_KEY`, otherwise every workspace starts with a
  full bucket on each process restart.
- Concurrent load above the vendor limit between two workspaces on the same portal is
  accepted with the owner decision; the vendor limit itself is not shared.
