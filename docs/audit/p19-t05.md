## Delivered behavior and corrections

- EXPORT-authorized current-revision DOCX/PDF export through
  `POST /api/v1/documents/{id}/export/{docx|pdf}`; explicit base64 response model
  carries revision id, body hash, file hash and size. Stale expected revisions
  or hashes are refused. Literal content is escaped; renderer resource fetches
  remain forbidden. PDF preserves Cyrillic text and revision metadata.
- `POST /api/v1/documents/{id}/send/email` requires an Idempotency-Key, source
  EXPORT and outbox CONFIGURE. It checks the exact approved revision, renders
  once, binds the attachment reference, writes the same bytes to the encrypted
  transient spool, schedules and records provenance in one transaction.
  Failure rolls back the draft and cleans the newly owned spool scope.
- Fixed delayed/restart replay: resource-scoped keys find the existing approved
  attachment before rendering. Exact replay returns the saved state without
  rendering or recreating a purged spool, including after delivery. Changed
  intent, revision, schedule or TTL is refused; TTL is never extended.
- Durable `BusinessCommand.preview_snapshot.document_export` records document
  id, revision id/body hash and attachment hash/size/MIME with the original
  schedule/TTL. Joining the outbox target's command preserves revision tracking
  after transient bytes are discarded. This is informational provenance, not
  another approval authority; approved command payload/hash and dispatcher
  fences are unchanged. Delivery/tracking and dispatch-time byte verification
  reuse the accepted P15-T14 outbox. No new table or migration.
- Closed partial-audit F-1..F-3: explicit spool position; PDF availability guard
  restricted to missing dependency errors; knowledge/attachments coverage
  packages registered. Added real Idempotency-Key enforcement tests and native
  Pango/HarfBuzz/font packages in Docker, with local setup documentation.
- Pre-existing knowledge test repairs from the executor were reviewed: direct
  template renders supply the existing `perms` context, and obsolete direct
  approve/reject transitions use the accepted revision-bound approval service.
  The audit's three failing unit doubles were completed without weakening
  assertions in the final test-only commit.
