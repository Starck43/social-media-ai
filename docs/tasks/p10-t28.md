# P10-T28 — retire root-level model compatibility modules

Registry: [ROADMAP](../../ROADMAP.md#p10). Parent: [P10](../phases/p10-audit-hardening.md).
Related: [P10-T26](p10-t26.md), [P10-T16](../audit/p10-t16.md).

## Scope and acceptance

`docs/MODELS.md` declares domain packages canonical, yet `app/models/*.py`
still holds ≈25 root compatibility modules (`agent_task`, `job`, `source`,
`user`, `tenant`, `llm_*`, `digest_run`, …) plus `analysis.llm_*` and
`scheduling.digest_run` aliases; ≈100 imports in `app/models/managers` and
several app/tests modules use them. Several layout tests pin legacy paths,
symbols and even a pickle reference.

Plan (one domain per commit to limit conflicts with parallel lanes):
1. Switch managers/app/tests to `from app.models import X` or the domain leaf.
2. Reduce each root module to a pure re-export (pattern from P10-T26).
3. Owner decision: delete re-exports after one release, or keep them as
   documented aliases; update the pinned layout tests accordingly (with P10-T16).

Owns: root compatibility modules in `app/models`, their manager/app/test import
sites, pinned layout tests and `docs/MODELS.md`; select one domain before claiming
paths shared with other agents. No schema or new domain reorganisation is implied.

Accept: `rg "from \.\.(<root module>) import" app/models/managers` is empty;
fresh-process import tests pass; no mapper/schema change. Depends: P10-T26.
