# P12-T07 — Settings connections page: one connector list

Status: IN_PROGRESS · owner: opencode · branch `p12-t07-connectors-page`

## Why

`/app/settings?tab=connections` rendered **two** lists over the same registry:
the pre-P12 card list (`connections`, human wording, working buttons) and the
P12 catalog block (`workspace_connectors`, technical wording, read-only). Every
connector appeared twice, and the second block exposed internal vocabulary
(`PlatformType`, `UserCredential.meta.tenant_id`, `SourceType.DRIVE_FOLDER`,
watermarks, capability names) to a non-technical operator.

## Scope

- One list. The P12 catalog decides which connectors exist and supplies the
  display facts; the pre-P12 entries keep supplying the interactive parts
  (status badge, authorize/disconnect buttons, manual key entry).
- Operator-facing wording only in the visible card. Technical facts move into a
  collapsed "Технические детали" block.
- Responsive grid: one card per row on narrow screens, two from `sm`, three
  from `xl` — the workspace may hold many connectors.
- Personal credential rows are filtered by the active workspace
  (`credential_matches_workspace`); the old list showed every workspace's rows.

## Out of scope

Connector behaviour, OAuth flows, `Platform.params`, the P12 catalog contents.
