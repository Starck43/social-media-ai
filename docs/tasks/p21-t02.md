# P21-T02 — Single LLM dispatch seam and resolution contract

Registry: [ROADMAP](../../ROADMAP.md); parent: [P21](../phases/p21-ai-operations.md).

## Goal

Define and implement one internal preflight/dispatch boundary through which every
actual LLM HTTP attempt passes, while preserving existing provider adapters,
fallback semantics, tenant ownership and journal evidence.

## Dependencies and owned scope

- Depends on P21-T01. P21-T07 may supply audit findings before implementation.
- Inspect `app/services/ai/llm_client.py`, `chat_with_fallback`, all `chat()` and
  `analyze()` adapters, `app/services/ai/attempt_journal.py` and personal billing.
- Define typed context for tenant/payer, purpose/stage, model/provider identity,
  execution references and dispatch identity.
- Put authorization, credential availability, admission, rate-limit and
  pre-dispatch checks before HTTP; keep terminal evidence after the call.
- Distinguish denial (no fallback/bypass) from retryable provider failure
  (fresh attempt identity and eligible fallback).

## Steps

1. Inventory all provider call paths and write a route matrix before editing.
2. Specify the seam contract and redacted error taxonomy.
3. Adapt each adapter/caller to the seam without changing public schemas.
4. Preserve one journal record per actual try, including fallback and transport
   failure; never hold a DB lock over network I/O.
5. Add focused mock tests for every route class and a no-HTTP denial assertion.

## Acceptance

- Every observed provider attempt enters the seam exactly once.
- Missing payer/authorization/credential or budget denial happens before HTTP and
  cannot fall through to another model or payer.
- Fallback/retry gets a new dispatch identity; persistence replay retains its own.
- Tool, image, analysis, digest, learning, prompt-suggest and admin-probe paths
  are either covered or explicitly excluded with a reason.
- Error responses contain no raw provider body, prompt, credential or token.
- Focused tests and route matrix are recorded with the tested SHA; no production
  activation or migration is implied.

## Rollback and boundaries

Keep adapter compatibility shims until all callers migrate; rollback is a revert
of the seam wiring. Do not add a second scheduler, rename tables, or enable
personal billing/production admission in this card.
