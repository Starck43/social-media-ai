## Finding and fix

New opt-in read-only `/runtimez` probes same-host `app.runtime` presence:
exclusive local owner lock held by the sole runtime plus a running heartbeat
<=60 seconds old. It is distinct from `/livez`/`/readyz`/`/health` (API+DB),
never claims component progress, DB health, cross-host uniqueness or production
readiness. `RUNTIME_STATE_DIR` is unset by default; enabling it requires a
trusted same-host POSIX directory, OS user and kernel lock namespace shared by
API and runtime. The runtime acquires exclusive nonblocking ownership before
default-task bootstrap, writes a bounded strict JSON record via atomic replace
while retaining the stable lock inode, heartbeats every 15 seconds, and
releases only after the component drain — repeated shutdown cancellation
cannot cut the drain short. Unset deployments keep the previous behavior.

Files: `app/core/runtime_presence.py` (new), targeted `app/core/config.py`,
`app/core/health.py`, `app/runtime.py`; `tests/runtime/test_p8_t10_runtime_presence.py`
(54 cases) plus the exact route-set expectation in
`tests/models/test_bootstrap_readiness_unit.py`; targeted `docs/API.md`,
`docs/CONFIGURATION.md`, `docs/DEPLOYMENT.md`. No schema, deployment profile or
service change.

- Code review: the probe opens the lock/record with `O_NOFOLLOW|O_NONBLOCK`
  plus `S_ISREG` verification, so symlinks/FIFOs/devices cannot hang or fake a
  probe; a shared probe lock never masquerades as ownership; record validation
  is strict and fail-closed (exact key set, `version==1`, 32-hex runtime id,
  finite timestamp within [0, now], <=4096 bytes, duplicate keys rejected;
  corrupt/oversized/stale/future states never report green). 200 only for
  `state == "fresh"`; all responses `Cache-Control: no-store`; file reads run
  off the event loop via `asyncio.to_thread`. Failures raise content-free
  `RuntimePresenceError` values; no PID/hostname/path/DSN in any output.
