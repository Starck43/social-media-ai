## Deliverable

Return available actions and actor-specific pending decision summaries from current task, run and ledger state. Delegate command/document reviews to their existing ledgers. Implement a versioned local decision only for genuinely local acceptance. Carry reason, reviewer, expiry, target revision and decision outcome. Keep annotation/completion of existing delegated work explicit. Add preview and version-bound confirmation for delete, including occurrence/series scope and in-flight execution.

## Implementation sequence and handoff

1. Start with app/services/commands/approval_inbox.py and the planner result confirmation service. Identify the authoritative handler for each supported decision.
2. Project a pending action for one eligible reviewer, preview its target version and dispatch confirmation to that handler. Exercise rejection and a stale confirmation after the task changes. For delete, preview the effects before accepting the same version-bound request.
3. Give T07/T08 an action reference, display label, eligibility, expiry and refreshed outcome for each action. Specify which decision closes a proposal and which explicitly completes the task.

## Acceptance

Accept or Reject is visible only to the eligible actor while actionable. Concurrent or stale decisions have one durable outcome and no duplicate effect. Rejection identifies the affected proposal. Deleting a local task suppresses future runs and preserves required receipts. Unlinking an external reference never deletes upstream.

## Service handoff to T06–T09 and T11

- `canonical_task_actions(task_id, perms=..., boundary=...)` returns work
  status, last run identity/status, next trigger, available actions and
  actor-specific pending decisions. The read is task ACL scoped. Each owning
  mutation rechecks live rights.
- `task_decision_service.pending/preview/decide` uses stable
  `local:<id>`, `command:<id>` and `document:<approval_id>` references.
  Preview signs the actor, scope, exact target revision and choice. Pass the
  caller's existing Inbox permissions and document data boundary. Bind an
  independent ledger review only from the trusted producer that knows the
  association. Never expose `bind_produced_review` as a generic user action.
  Local acceptance closes the proposal. The explicit Complete action closes
  work. For legacy assigned Jobs, keep using `result_preview` and
  `apply_result` with the explicit annotate/complete choice.
- `task_deletion_service.preview/confirm` binds the occurrence or series,
  task versions, affected schedules and execution state. A stale or busy
  preview can be refreshed. Deleting a single open recurring occurrence
  advances the existing recurrence. Series deletion stops it. Cancelled and
  uncertain run receipts remain durable. A local deletion only hides local
  links. T11 owns actions on external task references and upstream commands.
