## Implementation decisions

- `onec.data` VIEW/EXPORT and `onec.command` CREATE/CONFIGURE are capability-only
  catalog identities; the requested `onec.*` keys resolve as explicit aliases.
  Presets follow the card. Owner/admin remain identical. Each service reloads
  active workspace/account/membership authority and retains connection ownership.
- Optional `allowed_entity_sets_by_role` intersects the accepted connection list.
  Absence preserves it; malformed/omitted/unknown roles grant no entities. No
  role-name bypass. No connection editor change is part of this delivery.
- T04's evidence and actor-scoped view stay unchanged. The filtered projection
  reuses `ActionAuditEventManager.list_events` and joins the existing command
  connection for filtering; `onec.audit_export` uses the existing success writer.
  Export audit is committed before returning CSV; failure prevents the download.
- Denials use structured, source-owned non-receipt logs (`permission_denied`),
  not invented success/unknown events. No payload or credential fields.
- Placeholder migration expands the closed audit CHECKs and seeds the two
  capability-only catalog resources, permissions and role links (required by
  `tests/conftest.py` reference validation). No provider-data tables are added.
  Rollback locks the audit table and refuses while export evidence exists;
  empty rollback removes only its own metadata. The integrator assigns its
  number at merge. This migration remains UNRUN until the local isolated cycle.
