## Recorded budget policy

The provider budget is keyed by tenant/provider/account but stored per connection, where the account identity is the SHA-256 of endpoint host, port, base path and login. Two connections or two actors in one workspace using the same 1C account therefore contend for one budget row, and the second attempt fails closed with `BudgetConnectionUnavailable` → `404 connection_unavailable` instead of receiving a silent second allowance.

Decided 2026-11-11 by owner instruction: keep this fail-closed behavior as the documented policy. One 1C account backs one active connection per workspace, and a second connection with the same account is refused at use time rather than served from a separate budget. The budget is never relaxed implicitly by a connector.

Rollback if the limitation becomes subscriber-facing: widen the binding so a single `(tenant, provider, account)` budget row is shared by every connection of that account, which means migrating `provider_rate_budgets` ownership and dropping the per-connection `BudgetConnectionUnavailable` refusal. The cheaper alternative is an explicit creation-time refusal of a duplicate account inside the tenant, which needs the same unique-key change on `workspace_connections`. Neither is part of this revision.
