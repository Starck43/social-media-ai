## Verdict

Delivered and verified: `local_connector/search/` adds the device-side search service, ACL-aware
file references, bounded snippets, the durable replay ledger and the signed command receiver
that matches `app/services/local_connector/wire.py`; `session.py` gains a default-off
`DeviceCommandSession` while `OutboundSessionClient` stays fail-closed. No schema, no server
route and no cloud activation is touched.

The single acceptance blocker was a portability defect in one test, not in the module:

- At the delivered head `fbd0ff7b` the deferred host run measured **120 passed, 1 failed**:
  `local_connector/tests/search/test_p18_t05_protocol_and_replay.py::test_response_payload_stays_within_64kib_and_marks_partial`
  -> `OSError: [Errno 63] File name too long`. The fixture built `"segment_" * 15` plus
  `"/".join(["d" * 120] * 10)`, i.e. a ~1.3 KiB relative path; the absolute path exceeded
  `PATH_MAX` 1024 on APFS while Linux (4096) accepted it, so the container never exercised the
  limit.
- Shortening the path alone could not fix it: `MAX_HITS = 50`, at most 8 snippets per response
  and `PATH_MAX` 1024 cap a macOS response near 50 KiB, so the 64 KiB ceiling is unreachable
  there. `ad086dd4` exercises the same truncation branch with a 4096-byte budget patched through
  `local_connector.search.protocol.MAX_RESPONSE_BYTES` plus the matching signed envelope
  `max_response_bytes`, and keeps the real 64 KiB case for Linux behind
  `skipif(sys.platform != "linux")`.
- The two failures the lane explained as container-only
  (`test_p18_t04_ocr.py::test_cpu_limit_rlimit`,
  `test_p18_t03_safe_index.py::test_root_and_ancestor_replacement_fail_closed`) do pass on host,
  so that explanation holds.
