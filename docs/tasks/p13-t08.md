## Goal

A provider-neutral OAuth flow for business connections (Bitrix24, Google Calendar, Yandex) that stores tokens only as connection secrets and refreshes them safely.

## Baseline

- `workspace_connections` + encrypted secrets with explicit owner/tenant (P12-T08); provider catalog `app/integrations/catalog/`.
- VK OAuth flow (personal), being hardened in P12-T14.

## Plan

1. Catalog extension: `OAuthMethod(authorize_url, token_url, scopes, pkce, redirect_path, client_config_keys)`; client ID/secret come from deployment configuration per provider, never from forms.
2. Start endpoint creates a single-use `state` bound to actor, tenant, provider and PKCE verifier (short TTL); callback validates state, exchanges the code via fixed allowlisted hosts (reuse the P12-T08 network policy: global DNS only, TLS verified, no redirects).
3. Store access/refresh tokens and expiry in `workspace_connection_secrets`; connection state transitions `unverified→verified|reauth|error`.
4. Refresh with a row lock per connection to avoid concurrent refresh races; refresh failure → `reauth`, notification to the owner.
5. Disconnect revokes at the provider when supported and clears the secret.
6. Tests with mocked providers: forged/replayed state, cross-tenant callback, concurrent refresh, revoked refresh token, non-global DNS.
