## What was accepted

One canonical task, one contract, three transports. `/api/v2/tasks` is a new
namespace because `/api/v1/tasks` remains the social-monitoring (VK) surface: a
mixed call would have launched the wrong job, so the wrong call now fails closed.
The `worktasks` CLI group and the fourteen `work_task_*` agent tools call the
same handlers and the same accepted T03–T06 services; no surface re-derives
rights, versions, confirmation or admission.

- Rights: `planner.task.view|create|update|delete`, rechecked at execution by
  `PlannerService._actor`, `TaskDecisionService` and `TaskDeletionService`.
- Versions: every mutation carries `expected_version`; a stale one raises a
  bounded refusal rather than an overwrite.
- Confirmation: the six write tools require one-use confirmation; deletion and
  decisions use signed preview tokens with a 600 s TTL.
- Admission: run-now binds actor + `Idempotency-Key` + `(task, revision)`; a
  replay returns the first receipt with `replayed: true`, a different revision
  under the same key is refused. The API resolves the published revision itself,
  so the caller never supplies a version to run.
- Refusals are bounded: `403` rights, `404` absent-or-invisible (one answer, no
  existence oracle), `409` stale or conflict, `422` rejected plan or page.
- Parity is enforced, not asserted: one operation table is checked against the
  API route set, the Typer command set and `TOOL_REGISTRY`, so a surface that
  gains or loses an operation fails the suite.

## Recorded limitations

1. No test isolates the CLI's grant derivation from the service-level membership
   check: the shared `_platform_scope` fixture installs an operator grant for the
   whole session, so the evidence is the code path plus the viewer-refusal test.
   The scheduler, the tools and the CLI share that same harness gap.
2. A live HTTP happy path with a bearer token and the browser stands were not
   executed; the DB suites call the services directly.
3. `Idempotency-Key` is accepted on the other mutations for symmetry but has no
   ledger-backed replay until the T12 command ledger.
4. `scripts/setup_test_db.py` cannot seed a fresh schema
   (`tenants.plan_holder_user_id` NOT NULL), so `p22_t07` needed a manual
   `alter table ... drop not null`; filed as a registry follow-up.
