**Follow-up fix (PR #294).** The sidebar categories are collapsible submenus, as
sqladmin renders them: `app/static/css/custom.css` keeps the panels inline
instead of the Tabler floating popover, which needs a navbar wrapper the console
has none of. The initial `app/static/js/admin_menu.js` folded other groups and let
Bootstrap toggle the clicked one, while preserving model navigation and the
remembered group. That ordering had a live defect, described and fixed below;
the final behavior is pinned by `node tests/js/p11_t27_admin_menu.cjs`.

**Live defect found after #294: a header collapsed but never expanded.** The
`defer`red sidebar script attached its click listener to `documentElement` in
the capture phase, assuming it runs before Bootstrap's data-api. The shipped
Tabler bundle binds its own dropdown to `document` capture, and the capture path
is `window → document → documentElement`, so the bundle flipped the panel
*first*: the sidebar then read the category as already open, decided to close
it, and hid the panel it had just opened. Collapsing worked only because the
bundle's second flip cancelled the sidebar's.

The fix owns the state instead of racing for it: the listener moved to `window`
capture (first on every path), it toggles the panel itself, and it ends the
event so the bundle can never answer from its own stale instance (its
`data-bs-auto-close="false"` categories would otherwise stack). The stub now
mirrors the real order — a `window` capture listener, then a `document` capture
handler with per-toggle instance state, and no dispatch once the event is
stopped. Checked in real Safari against `test_schema` (throwaway operator):
expand, switch, collapse, re-expand, model navigation keeping its category, and
reload restoring one group. `node tests/js/p11_t27_admin_menu.cjs` 32 checks and
`tests/admin/test_p11_t27_menu_categories.py` 4 passed; removing the
`stopPropagation()` makes the folded-category check fail.
