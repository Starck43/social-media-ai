## Deliverable

Design a versioned bounded sequence of read, transform/analyze and sink steps with named typed ports. Keep dates, limits, trigger and explicit selected/discovery/all scope. Link reusable scenarios only on LLM steps, pin effective methodology for a run and define behavior on subsequent scenario edits/deletion. Retain legacy trigger/action/dry-run fields. Validate read versus write capability, schemas, permissible routes and per-step failure policy.

## Implementation sequence and handoff

1. Consume T01 task identity and T02 capability resolution. Map one saved social plan from app/services/task_plans.py into ordered steps before adding new shapes.
2. Publish an immutable revision only after validating ports, resource direction, scenario and tenant. Editing the scenario affects future admissions through an explicit revision policy; historical runs retain their effective methodology.
3. Give T04 and T07 a callable preview and revision lookup with examples for a title-only task, deterministic correspondence grouping and scheduled VK analysis.

Preview rejects incompatible ports, stale/revoked selections and unsupported plan versions before execution. Edits preserve old-run explainability.

## Consumer handoff

- Call `execution_plan_service.preview(task_id, raw_json)` for an existing
  editable task. `publish(task_id, expected_version, raw_json)` appends an
  encrypted revision after resolution and bumps the existing Task version.
  `get_reference(task_id, revision=...)` returns view-scoped revision metadata.
  A title-only task has no revision. Consumers submit strict execution-plan
  version 1 JSON. Legacy social plan versions 1 and 2 are separately versioned.
- T04 uses `load_for_admission(task_id, expected_revision, session=session)`
  inside its admission transaction. Pin its plan and methodology in protected
  run state and honor scoped resources and `dry_run`. The return value is
  internal. Use the registered operations' ordered ports and recheck leases,
  permissions, payer and resource policy before dispatch.
- T06 uses `map_social_plan` with the saved payload, job type, dry-run and
  legacy effect fields. Supply the exact source selections and effective
  workspace timezone. A legacy row without `task_plan` retains its legacy
  behavior. An explicit empty selected list fails normalization. Old VK
  plans without an explicit account can be mapped and require selection on
  preview/publish. Telegram discovery and unsupported writes fail closed.
- The deterministic correspondence route has a bounded mail read, sender
  grouping, and internal Messages sink. A scheduled VK plan preserves its
  collection/digest windows and cron timezone. Scenario edits take effect on
  explicit republication. Revocation or deletion prevents new admissions.
  Admitted runs retain their encrypted methodology and renderer version.
- Ordered steps are held as a single encrypted revision document. Resource
  references are typed FK rows with deletion tombstones. This gives port order
  and step/port uniqueness without a second mutable step representation.
  Rollback leaves unused additive tables in place. The down migration refuses
  to drop populated revisions.
