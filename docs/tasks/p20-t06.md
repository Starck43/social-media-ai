Registry: [ROADMAP](../../ROADMAP.md#p20); status, owner and dialogue live there. Parent: [P20](../phases/p20-proactive-assistant.md). Design: [WORKSPACE_UX](../WORKSPACE_UX.md). Request: https://app.notion.com/chat?t=40fa7457748980d094a100a930619250

## Goal and dependencies

Make the four daily entry points («Сегодня», «Чат с агентом», «Входящие», «Задачи») obvious and keep the sidebar from growing one item per module. Builds on the accepted [P12-T01 grouped sidebar](../audit/p12-t01.md) and [P12-T17](../audit/p12-t17.md); no new data or service.

## Scope

- Regroup `NAV_ITEMS` per the [target navigation](../WORKSPACE_UX.md#target-navigation): «Работа», «Клиенты», «Знания», «Мониторинг», «Система». Keep every existing route, permission check and `ready` flag; move items, do not remove pages.
- Mobile bar carries «Сегодня», «Чат», «Входящие» (when ready), «Задачи» and «Ещё»; chat is included because it is the primary workspace and is missing today.
- Labels follow owner decision O-1. Until decided, keep today's labels and add only the regrouping and mobile change. Coordinate the planner item with the active [P16-T01](p16-t01.md) owner instead of editing their paths.
- Add the sidebar-admission rule from WORKSPACE_UX to the `nav.py` docstring so later modules follow it.

## Acceptance and checks

- Focused nav tests: every existing item is still reachable for the same permissions, hidden for missing ones, and appears once; mobile bar fits 360px with full labels; keyboard and screen-reader order follow the groups.
- Template/unit evidence only unless an authenticated browser check is available; record which.

## Open doubts
