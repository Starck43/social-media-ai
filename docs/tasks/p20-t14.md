# P20-T14 — Web shell restyle toward the console direction (base palette preserved)

Registry: [ROADMAP](../../ROADMAP.md); parent: [P20](../phases/p20-proactive-assistant.md).

Owner request (2026-11-18, local session): implement the approved "console"
("Пульт") direction from the three delivered web-design mockups, keeping the
base slate/cyan palette in the existing style variables. The mockups live in
the owner's workspace (原型/ folders) and are not part of this repository.

## Goal

Give the stable shell and shared components the console-direction presentation:
compact instrument navigation with mono group labels, a denser navbar strip,
mono numerals and meta lines, sharper radii (4-6px), hairline separators,
cyan accent usage and uppercase section rubrics on the dashboard. Every color
keeps coming from the existing theme variables; no new palette values.

## Scope (increment 1)

- Add `app/static/css/console.css`: a presentation-only overlay referencing
  existing variables (`--color-*`, `--ui-accent*`) only.
- Link it from `app/web/templates/web/base.html` (one `<link>` line, the same
  versioned pattern as `shell.css`).
- Base style files stay byte-identical: `theme.css`, `ui.css`, `shell.css`,
  `dashboard.css`.
- No template structure or behavior changes, no Python changes, no new data.

Out of scope: per-page redesigns (chat composer and inline cards, task hub,
scenarios), telemetry surfaces that need context data the shell does not carry
(model budget, queue depth), Tailwind removal, folding the overlay into the
base files (a follow-up after visual acceptance).

## Honest-state boundaries

The overlay is presentation only: it adds no badges, counters or statuses and
must not imply data the backend does not provide. The pending-approval badge,
collapsed sections and status texts keep their current sources and behavior.

## Acceptance and checks

1. Offline lane on the branch head: `python -m scripts.ci.checks` and
   `python -m scripts.ci.run_offline` (exit 0).
2. Template integrity: `pytest tests/web/test_web_ui_components.py` when the
   application venv allows it outside the primary checkout; otherwise a direct
   Jinja compile pass over `app/web/templates/web/*.html` (the actually used
   command is recorded in the PR body).
3. Preservation proof: `git diff --stat <claim-base>..HEAD -- app/static/css/theme.css
   app/static/css/ui.css app/static/css/shell.css app/static/css/dashboard.css`
   is empty.
4. CSS sanity: balanced braces in `console.css`; no `@import`, no external URLs.
5. Visual review in a running application is the auditor/owner step; this
   environment has no running application and does not claim a visual pass.
