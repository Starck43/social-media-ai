# P20-T04 — Bounded specialist delegation for research

Registry: [ROADMAP](../../ROADMAP.md#p20); status, owner and dialogue live there. Parent: [P20](../phases/p20-proactive-assistant.md). Request: https://app.notion.com/chat?t=40fa7457748980d094a100a930619250

## Goal and dependencies

Pilot one evidence-backed social research task where a coordinator assigns bounded collection, analysis and report-drafting steps to specialist roles. Build on the accepted [P8-T40 composition](../audit/p8-t40.md), [task-plan contract](../AGENT_TASKS_PLAN.md#explicit-task-plans), existing jobs and [typed tool registration](../audit/p11-t09.md), rather than introducing a second orchestration engine. Q-5/P8-T41 remain separate live-provider and journey gates.

## Scope

- Start with a fixed, versioned workflow and typed inputs/outputs: bounded authorized collection → evidence-linked analysis → draft synthesis. Reuse existing task/run history, receipts and progress; identify each step's source, version, outcome and evidence. Roles are implementation roles, not new privileged identities or unrestricted agents.
- Child scopes may only narrow the originating actor/workspace, source and model/data boundaries; recheck authorization at admission and execution. Cap depth, fan-out, runtime, retries, token/spend and concurrency; enforce existing payer and quota checks. Prompt or fetched content cannot grant tools or permissions.
- Show steps, progress and cancel in the chat «В работе» tab and progress cards ([P20-T08](../audit/p20-t08.md)) through existing run history, not a second status store. Web research steps become available only after [P20-T12](p20-t12.md) is accepted.
- Provide cancellation, partial/error reporting, idempotent resume and an explicit human decision for external effects. A Bitrix24 report is a draft until an independently authorized existing command/approval workflow performs any write; no new CRM integration or automated posting is implied.
- Compare a fixed multi-step pilot against the current single/composed path on labelled quality/evidence coverage, completion, latency and cost; keep the simpler path when the added delegation lacks measured benefit. No general agent marketplace, rooms or unrestricted model-selected team creation in the pilot.

## Acceptance and checks

- Test provenance and citations, permission revocation between steps, tenant isolation, child privilege escalation, hostile source prompt injection, budget exhaustion, cancellation, repeated work and partial failure. Prove no writes or sends without the existing separate confirmation, using mocked providers.
- Record fixture set, measured baseline and results, tested SHA and exact focused checks. Any persistence or schema change needs its own reviewed migration/rollback and isolated test-schema evidence.

## Open doubts

Additional model use may change user cost. Default to a bounded mocked/offline design, present an estimated cost and obtain owner approval before enabling paid use or changing infrastructure. Roll back by disabling the optional workflow and retaining the existing composed path.
