# P11-T44 — Formatting baseline drift on untouched files

Registry: [ROADMAP](../../ROADMAP.md); parent: [P11](../phases/p11-structure.md)
(accepted phase, registered follow-up from [P11-T38](../archive/tasks/p11-t38.md)). No prerequisites.

## Goal

Reconcile `.ci/format-baseline.json` with the current checkout — by fixing the
files or by revoking stale per-file exceptions after review — so the format gate
stops reporting debt that no task owns. No blanket reformat commit.

## Evidence (observed 2026-11-16 during P11-T38)

Full gate comparison of `scripts/ci/checks.py` on the P11-T38 solution revision
(`fef8b5f4` + baseline change) reported:

```
formatting findings: 187, secret candidates: 374
failures: 31
Format changed/new file with Black/isort 120: app/api/v1/endpoints/communication.py
... (31 paths, all with the same "Format changed/new file" message)
```

All 31 are Black/isort findings; none is a secret finding (the P11-T38 baseline
change brought secret failures to zero). The paths were untouched by P11-T38 —
the baseline stores an exact SHA-256 per frozen exception, so any later change
to those files invalidates it by design. This is inherited drift, not a
regression of the gate.

## Scope and acceptance

- Enumerate the current 31 findings with the same check command and group them
  by cause (edited file, formatter-version drift, missing-but-clean file).
- For each: either bring the file to Black/isort line 120 or remove the stale
  exception with a recorded reason. A file changed by this task must pass both
  formatters, per `.ci/README.md`.
- Re-run the comparison and show zero formatting failures on the accepted head.
- Do not auto-refresh the inventory or add exceptions for new changes.

## Rollback

Baseline edits and formatting fixes revert independently; a move-only reformat
of an unrelated file is out of scope.
