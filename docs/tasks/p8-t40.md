## Scope and acceptance

Extend the existing task contract from separate collect/analyze launches and
the existing digest job into one bounded social research plan that can collect,
analyze and generate a digest, either once or on an explicit schedule. Reuse
existing jobs, digest services and delivery controls; do not introduce a general
workflow engine. Keep the task definition and each run's effective snapshot
versioned and inspectable.

Model the schedule window separately from the digest reporting period. Support
fixed and rolling windows, workspace timezone, repeat/pause/edit and cancellation
using existing lifecycle rules. Report collected, analyzed, digest-generated
and delivered counts/status separately, with provenance, partial coverage,
unsupported categories and failures preserved. Provide a preview that does not
send. Delivery target permissions are checked freshly; external send remains
separately confirmation-gated and idempotent. Respect connector entitlements
where configured and existing personal payer consent, quotas and caps.

Accept when the shared definition is used by chat, management web pages, API,
CLI, admin and agent tools; one-off and scheduled runs create inspectable jobs
and results; pause/edit/revoke and retry states are truthful; duplicate starts
do not create duplicate work or charges; delivery preview and confirmation obey
the established permission contract; and dates, timezone and partial results
are covered by focused tests.

## Ownership and dependencies

Uses the integrated code foundation in P8-T29 and depends on the task-journey
contract from P8-T39; it does not wait for P8-T29's live VK evidence gate. Use
existing personal payer consent, workspace quotas and spend caps. When P2-T15 entitlements
exist, enforce them here, but do not block this social milestone on commercial
plan work or live subscription checkout. Preserve accepted digest contracts in
P3-T01/P10-T07. No external write without explicit confirmation.
