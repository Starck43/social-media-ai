## Owner request and scope

Audit and correct the supported social collection → persisted post records →
analysis input/result → agent response/render path. Keep each post's canonical
source permalink, original media URL references, source identity and tenant
provenance associated with the exact post being analyzed. The analysis agent must
be able to cite/link the post and present its media through the source URLs.

First map the actual supported collection paths and canonical tables/relations;
then make the smallest needed persistence, projection, agent-output and rendering
changes. Do not assume a table/property name before inspecting the current schema.

## Acceptance

- Record the end-to-end field/relation map from each supported collector through
  persisted analysis-eligible records, analyzer context/results and rendered agent
  output; identify where links are normalized, dropped or associated with a post.
- Each analyzed post retains its correct canonical permalink and its associated
  media URL references (or an explicit missing/unsupported state), with source
  identity and tenant scope preserved through analysis.
- Agent context and response expose the post link and corresponding media links
  for the same evidence item. The UI renders a clickable post permalink and
  URL-backed media presentation for supported types, with a safe link fallback
  when preview is unavailable.
- Missing, malformed, duplicate, expired or unsupported URLs do not fabricate
  evidence or prevent analysis of otherwise usable post text. Validate/escape
  external URLs and do not render arbitrary HTML or unsafe schemes.
- Media is reference-only: no backend fetching/downloading, proxying, rehosting,
  byte persistence, file attachments or duplicate media copies. Tests verify the
  media download/storage path is not invoked.
- Focused mocked/synthetic checks cover URL extraction and post association,
  persistence/projection into analysis, agent result serialization, rendered
  links/previews and cross-tenant isolation. Do not make live provider calls or
  fetch actual media in tests.
- Add a schema/migration change only if inspection proves URL references cannot
  be represented by the existing contract; follow the repository's test-schema
  validation and database approval rules. Do not apply a public migration here.
- This task does not certify live platform capability, close Q-2's single-post
  source investigation, or accept the separate P8-T41 live journey.
