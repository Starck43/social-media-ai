## Scope and acceptance

This is an optional extension after the minimum VK pilot in P8-T41; it is not
required for that pilot to close. Before implementation, choose one bounded set
of categories from the capability matrix and record it here. Any unselected
category that the owner still wants must get its own task ID/card and phase link
before this card can close; do not let closing this card erase deferred
requests. Candidate categories from the original request are people search,
video, apps/games, and owner-scoped market items. Add each only after its official
API method, parameters, credential mode and app profile have verified capability.
Music requires separate permission evidence. Clips have no promised public
search method; channels are only partially represented by communities.
Unsupported or unverified categories stay disabled and are labelled accurately.

Return category-specific typed results with the correct owner/account/app IDs,
stable provenance/links, bounded paging/fan-out, partial failure and explicit
unavailable-category details. `All` aggregates only enabled categories and
preserves each result type. People discovered by search are people results, not
Sources; an app or market item is also not a Source unless the user explicitly
adds a supported target. Preserve existing task UX and surface semantics from
P8-T39. Use only official VK API methods; no browser scraping.

Accept the explicitly selected category set with method-level parameter/scope
evidence, mocked success/permission/partial/error tests, bounded concurrency and
quota behavior, and web/API/CLI/admin/agent contract parity. Record all remaining
requested categories as unsupported/deferred, with separate cards before T33
closes, so task closure cannot silently drop them.
