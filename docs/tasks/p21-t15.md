# P21-T15 — Atomic LLM admission and quota reservation wiring

Registry: [ROADMAP](../../ROADMAP.md); parent: [P21](../phases/p21-ai-operations.md).

Prerequisites: [P21-T14](p21-t14.md), [P2-T17](../audit/p2/p2-t17.md) accepted
dormant holder/allowance definition; operational activation choices remain gated in P2.

## Goal

Make the P21-T12 seam admission atomic: a reviewed worst-case cost ceiling is
reserved before HTTP and settled to actual (releasing the remainder) after, so
concurrent callers cannot overshoot a cap by read-then-compare, and platform plan
allowance stays distinguishable from external provider cost.

## Allowance storage and atomic scope

Reserve tokens against one `(plan_holder_user_id, period, allowance_pool)` balance
across all owned workspaces and owner-sponsored invitee calls. No bucket keyed
only by tenant/member and no fresh allowance when a new workspace is created.
P2-T17 defines the counting/period/finite-or-unlimited policy; this task owns dispatch-
unique token reservations and P21-T16 settles actual usage. Store nonnegative BIGINT
token quantities separately from Decimal USD amounts. Explicit NULL token limit
means unlimited, zero means denied, and missing policy denies target activation.

The immutable admission evidence binds holder, workspace, actor, model/catalog,
credential version, payer/consent version, policy version, period and reserved
token ceiling. State/leases are separate mutable records. Admission atomically
commits token reservation, the applicable monetary reservation and its receipt;
failure/denial rolls back both, including failure across different payer scopes.
Consume P21-T14's lock order; no monetary reservation sits in a rate-limit queue.

Current `LLMBudgetManager.reserve_receipt` owns its commit and accepts no external
session. Define an internal shared transaction primitive before combined token/
USD wiring; two independently committed manager calls are not atomic. Preserve
the fresh-admission versus exact-replay return contract: replay never permits HTTP.

## Steps

### Executor sequence and handoff

Require P21-T14 quota/lease/lock-order handoff and P2-T17's resolved allowance
period/counting policy. Start at `app/services/ai/budget_admission.py`,
`dispatch_receipts.py`, `app/models/managers/llm_budget_manager.py` and the personal
USD ledger. Publish the token balance/reservation and missing tenant settlement
state/lease/event schema contract, including dispatch/payer/period uniqueness and
replay/unknown outcomes, for P21-T16. Implement one UOW with internal session-aware
primitives, then wire admission into the dormant seam; never compose independently
committed managers and call that atomic.

This task accepts pre-HTTP reservation, denial and exact replay with isolated
concurrency tests. Settlement transitions below are its required interface, tested
with doubles/reference state; P21-T16 implements and verifies real settlement.
No admission-only rollout may start HTTP while terminal accounting is absent.

1. Select the authoritative admission path per payer/funding class and document why
   the other remains compatible or dormant.
2. Compute a reviewed worst-case ceiling per attempt from validated params; model
   `max_tokens` alone does not bound input, media or other output costs, so state
   every bounded component and the uncovered remainder explicitly.
3. In one owned transaction: append the immutable receipt before FK-dependent
   reservations, reserve the applicable token and USD ceilings, then commit before
   HTTP. No lock spans HTTP. A partial reservation is never acknowledged.
4. After the attempt, settle actual and release the remainder; a conditional UPDATE
   after usage alone is not sufficient. Retain liability when actual is unknown
   (P21-T16).
5. Replace the effective daily-cap read-then-compare admission in the seam with the
   reservation result; never sum journal/projection rows as a second ledger.
6. Record plan allowance and provider cost as separate figures on the same attempt;
   name `reserved_tokens`/actual token-use evidence separately from `ceiling_usd`/
   actual provider cost. `cap_usd` is not included tariff tokens; do not use a Float
   workspace cap as the ledger or infer tokens from dollars. Normalize legacy
   Float monetary settings through an explicit Decimal policy, never silent zero.
7. Cover fallback, retry, tool, digest, learning, analysis and prompt-suggest
   callers with distinct payer-bound attempts.
8. Add two-session PostgreSQL race tests; evidence is local mocked + isolated schema.

## Pricing policy

- Preserve the accepted FREE/PRICED/UNDEFINED contract: missing/unresolved price
  is UNDEFINED, separately recorded and admitted under the owner's existing
  explicit undefined-price policy outside cap-bounded spend. Do not re-ask that
  answered pricing decision or convert it to zero/free. New subscription allowance
  and charging terms are a separate activation decision.
- No amount is silently rounded to free; prices come from the existing snapshots.

## Acceptance

- At the cap, concurrent reservations admit no intentional overshoot; settlement
  reconciles reserved-ceiling to actual with a released remainder.
- A denial produces no provider request and cannot select a paid fallback.
- Receipt and reservation are acknowledged only after commit; no lock spans HTTP.
- Plan allowance and provider cost are separately visible; absence of a tariff
  price produces UNDEFINED, never zero. This does not bypass a finite token quota
  or authorize dispatch with missing plan/allowance policy.
- Two-session races across different owned spaces and invited members exhaust
  ONE owner token pool; another owner remains independent. Test zero/unlimited,
  combined token/USD denial rollback, exact replay and period/plan change.
- Separate tenant/personal payer isolation, idempotency and exact replay
  demonstrated; legacy projections remain adapters.
- Flag-off / missing-foundation behavior is stated honestly: the current path is
  not magically fail-closed merely because the flag is off - record what it still
  permits.
- Isolated schema checks, synthetic-record cleanup and exact test commands
  recorded. No public migration or production cutover.

## Rollback and boundaries

Rollback freezes new admitted dispatch and leaves existing liabilities intact -
disabling a feature flag alone never releases an unknown charge. Do not delete
historical evidence, rewrite tariffs or merge payer contracts.
