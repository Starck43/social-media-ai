  mock was not awaited.

## Blocking finding — the privacy suite

Acceptance requires "both suites green in a documented invocation, which means
the privacy suite must actually be runnable". It was **never touched** by the
fix (`git diff 07853fa b8eddfd -- tests/api/test_http_user_response_privacy.py`
is empty), and it was half the task's scope.

- Under the root conftest: **47 errors**, all
  `AssertionError: assert 'app.core.database' not in {...}` — the exact blocker
  the card itself names.
- With `--noconftest` (the only working invocation): 44 passed, **3 failed** —
  `test_existing_route_rights_matrix` cases where an `operator` with **no
  grants** (and one `VIEW`-only operator on `PUT`) gets `200` and real user
  data instead of `403`.

Cause of the 3 failures: the isolated harness mounts `app/api/v1/endpoints/user.py`
without the `api_scope` middleware, so it never enters
`platform_request_scope()`. `has_permission` then takes its trusted-entrypoint
branch (`is_bypass()` and no ambient user → `True`, `app/core/permissions.py:103`).

**Not a live vulnerability.** In production `app/core/api_scope.py` rejects a
non-admin operator with `403` in middleware *before* the endpoint for every
`/api/v1/users*` path except `/me`, and only then enters `tenant_scope(bypass=True)`
+ `platform_request_scope()`. The suite's expectation is right; its harness is
missing the layer that enforces it. This is a harness-fidelity gap that must be
closed in the suite (or recorded explicitly as a boundary), not waived.
