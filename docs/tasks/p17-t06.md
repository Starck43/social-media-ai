## Goal

Make the second page of a 1C question reachable without asking the model twice.

## Baseline

- [P17-T03 accepted](../audit/p17-t03.md): `POST /api/v1/integrations/1c/query` returns `next_page_token` and accepts `page_token`, but the service re-runs the planner and binds the token to the new plan's fingerprint.

## Plan

1. Continue from the stored plan: accept `history_id` next to `page_token` in the query input, load the actor- and tenant-scoped stored plan (`history.load_plan` → `plan_from_json`), check the connection, attach the token and skip the planner.
2. Keep the token bound to the executed plan: a token whose fingerprint does not match the stored plan stays `invalid_page_token`.
3. First page keeps the planner path and records the history row the client continues from.
