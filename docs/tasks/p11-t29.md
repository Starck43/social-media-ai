## Work plan and acceptance

1. Define a platform-scoped permanent offboarding record that survives deletion
   of its subject workspace. Specify actor identity, bounded resource identity,
   timestamp, reason/outcome, retention, privacy and read/export authority.
   Do not store credentials, raw forms or provider responses.
2. Define explicit preview/confirmation and handling of retained task-admission
   audit; require a policy-compliant expiry/archive decision before deletion.
   Preserve immutable evidence and platform-superuser-only deletion.
3. Implement through the existing managers/services with an atomic transaction
   boundary: successful deletion and durable audit agree; failures cannot be
   recorded as successful. Define race/idempotency guarantees.
4. Add a reviewed Alembic migration if the selected schema needs it. Validate
   only test_schema first. Public application requires separate owner approval.
5. Test SU allowance, fully granted admin/operator refusal, CSRF, concurrent
   attempts, protected retention, failures/rollback, surviving audit readback and
   Safari confirmation/error UI with synthetic test-schema-only records.
6. Record exact SHA, schema/reference inventories before/after, cleanup, actual
   checks and rollback. Independent audit before acceptance.
