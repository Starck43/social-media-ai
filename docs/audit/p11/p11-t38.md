## What was wrong

The secret gate compared a fresh scan with a frozen inventory that had not moved since P11-T03, so
`dev` carried **94 candidates outside `.ci/secret-baseline.json`** across 53 touched-by-nobody
files. That is not a leak by itself; it is worse than one, because a permanently red gate teaches
reviewers to ignore the only signal that would catch a leak. Two of the 94 sat in application code
(`app/api/v1/endpoints/onec.py`, `app/services/calendar/service.py`), which is exactly the class a
blanket "docs noise" excuse would have missed.

## Accepted change

- `.ci/secret-baseline.json`: **287 → 381** entries, one reviewed rationale per added fingerprint.
  Set comparison against the base revision: **+94 added, 0 removed, 0 existing rationale changed**
  (the file's diff line count comes from re-sorting, not rewriting).
- `docs/tasks/p11-t38.md`: reproduction, classification table, decision, residual noise.
- No scanner, detector, filter, workflow or source edit. No directory exclusion, no auto-refresh.

## Recorded, not decided

33 of the 94 entries are the same structural pattern (`account_key` quota/routing identifiers). A
narrowly scoped plugin filter would remove that noise, but a filter also hides the pattern for
future files; the baseline keeps it per-value instead. Revisit if the count grows materially.
