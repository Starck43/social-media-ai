# P20-T12 — Web research source: search and public page fetch

Registry: [ROADMAP](../../ROADMAP.md#p20); status, owner and dialogue live there. Parent: [P20](../phases/p20-proactive-assistant.md). Design: [WORKSPACE_UX](../WORKSPACE_UX.md). Request and owner decision: https://app.notion.com/chat?t=40fa7457748980d094a100a930619250

## Goal and dependencies

Cover everyday research («найди в интернете», «разбери сайт») with a search API and plain HTTP fetch of public pages before any browser automation ([COLLECTION](../COLLECTION.md#collection-layers)). Uses the existing task plans, evidence and egress seam ([P14-T09](../audit/p14-t09.md)); a prerequisite for deciding whether [P20-T05](p20-t05.md) is needed.

## Scope

- Owner decision O-5: for now use a stub, with Yandex Search API the priority for a future real provider. No paid provider integration or live calls until the owner approves provider use and spending. Design a typed connector capability with per-account budget, rate limits and redacted errors.
- Public page fetch: destination validation (no private/metadata addresses, redirect and rebinding checks), size/time/content-type limits, robots and terms respected, page text treated as untrusted data, evidence snapshot with URL, time and hash under current retention.
- Agent task step and chat tool for search → fetch → evidence-linked summary; no login, form submission or CAPTCHA handling. Stub search results must be clearly marked and never presented as live evidence.

## Acceptance and checks

- Mocked provider and local fixtures: SSRF/redirect/rebinding refusal, oversize and slow pages, prompt injection in pages, budget exhaustion, cross-tenant evidence isolation, citation coverage. No live provider calls without owner authorization.

## Open doubts

Future real-provider activation and spend limit remain unapproved; Yandex Search API is the priority, not authorization to incur charges.
