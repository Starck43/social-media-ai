# P11-T12 — Durable action-audit contract and support correlation

Registry: [ROADMAP](../../ROADMAP.md#p11). Parent: [P11](../phases/p11-structure.md) (navigation only).

## Scope, evidence and acceptance

**Evidence:** per-attempt/usage, job, entitlement and delivery evidence exists;
no general cross-surface action audit model identified in `app/models`.
`app/core/logger.py` provides logging, not a substitute for an action ledger.
**Change:** define the minimal actor/workspace/action/resource/outcome/request/job
metadata contract and retention/access/redaction policy, then add use-case audit
hooks and read-only support views/export. Successful transactional changes should
have transactional audit evidence; denied/rolled-back attempts need a distinct
safe logging path. Never log secrets/raw tool arguments or equate logs with receipts.
**Acceptance:** denied/success/rollback/unknown outcome distinction, tenant-filtered
reads/export, retention and immutable-event permissions. An Alembic migration is
authorized only against `test_schema`, with full test-schema validation; no
production/public-schema apply or backfill is authorized. Cleanup checks remain
separately gated pending explicit authorization. Reuse existing billing and
delivery identities instead of a parallel money ledger.
**Dependency/risk:** P11-T04/03; maps to PRD-02/06/08 without claiming those gates passed.

## Owner decisions

Recorded 2026-10-28. These are decisions, not implementation:

- **Migration authorized.** The owner explicitly allows the implementation task to
  add and validate an Alembic migration only against `test_schema`. Production or
  public-schema apply and data backfill are not authorized.
- **Separate logging paths approved.** The owner approved the split the card
  requires: transactional audit evidence inside the successful change, a distinct
  safe logging path for denied/rolled-back attempts, and a separate category for
  unknown outcomes. One shared sink would blur the distinction the acceptance
  criteria test for.
- **No production, no public-schema apply, no data backfill** is authorized by
  this decision.
