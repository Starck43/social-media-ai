# P11-T53 — Test-schema `--reset` loses the capability-only catalogue rows

Registry: [ROADMAP](../../ROADMAP.md); parent: [P11](../../phases/p11-structure.md)
(accepted phase, this is a registered follow-up). No prerequisites.

## Goal

`python -m scripts.setup_test_db --reset` must leave a migrated schema as usable
as it was before the reset, or refuse the reset with the reason.

## Why this exists

Reproduced 2026-11-22 on `dev` `782b12bb` with an isolated schema created by
`alembic upgrade head` to `0162`:

```
DB_TEST_SCHEMA=<scratch> python -m scripts.setup_test_db --reset
  -> existing schema truncated, then "reference rows seeded"
DB_TEST_SCHEMA=<scratch> pytest -q tests/planner/test_p22_t07_work_task_api_db.py
  -> RuntimeError: The test schema is missing required reference rows:
     access resources: onec.command, onec.data; access permissions: ...
```

Cause: migration `0156` (`migrations/versions/p17t05_onec_audit_export.py`)
inserts two capability-only `model_types` rows whose `table_name` values
(`onec_data`, `onec_command`) name a contract, not a physical table. The re-seed
path `_seed_permissions` -> `scripts/migrations/register_model_types.py` registers
a resource only when `resource.table_name in tables`, so after the truncate those
two rows are gone and nothing restores them; `tests/conftest.py` then refuses the
schema for every suite.

The bootstrap therefore reports success while leaving a schema that fails the
session fixture — the same class of silent half-seed that P11-T52 fixed for the
payer column.

## Scope

- Restore the capability-only catalogue rows in the re-seed from the same
  registry migration `0156` uses (single source, not a copied literal list), or
  make `register_model_types` register capability resources without a table.
- Prove `--reset` on a migrated schema and on a metadata-created schema, then run
  one DB suite and the conftest reference check on both.
- Keep the reset destructive-only: no automatic reconciliation of other drift.

## Out of scope

- The payer column and the nullability preflight (P11-T52).
- `public` or the shared `test_schema` beyond a normal bootstrap.

## Evidence (reproduction)

See the command pair above; the schema inventory before the reset contains
`model_types` rows `onec.data` and `onec.command`, and after the reset it does
not, while `permissions` still has its 133 rows.

## Verification at implementation

```bash
DB_TEST_SCHEMA=<scratch> python -m scripts.setup_test_db --reset
DB_TEST_SCHEMA=<scratch> pytest -q tests/planner/test_p22_t07_work_task_api_db.py
DB_TEST_SCHEMA=<scratch> pytest -q tests/infra
```

## Risks and rollback

Restoring catalogue rows is additive; a wrong registry source would insert rows
`0156` does not own, so the check is an equality assertion against the migration's
list. Rollback is reverting the seed change; the schema stays usable because the
rows are additive.
