## Owner decision and delivered boundary

The owner approved deleting the local index with a durable pause until explicit
Resume, requiring re-selection after a missing/replaced folder, and closing an
**intermediate local-only scaffold** instead of the full desktop product.
[Decision record](https://github.com/Starck43/social-media-ai/pull/425#issuecomment-6685420638).
This changes this increment's acceptance, not the accepted security protocol or
its requirements before activation.

The separate `local_connector/` distribution is version **0.1.1**. It provides
private local SQLite/FTS5, selected-root identity and safe POSIX no-follow reads,
incremental indexing and default/user exclusions, persisted selection, a
serialized watcher with polling fallback, and a working loopback development
page for selection/status/confirmed deletion/resume. No source files are deleted.

The cloud-session seam always raises without invoking a transport or signer.
There is no cloud connection, actual device protocol, installer/tray, native
Windows file/ACL implementation, or real-user activation. Unsupported safe
semantics deny execution. Cache must be private and outside runtime-selected
folders. `IndexStore.search` is an internal unfiltered storage primitive; it is
not an authorized search/result-release API.

## Findings and corrections

The [initial rejected audit](https://github.com/Starck43/social-media-ai/blob/38610c976c2a4657a907c403bcfb9d05137eaa77/docs/audit/p18-t03.md)
reviewed `dfcae9e8883294b102172a2c334efe51fbd157d9`. Its nine findings are resolved
for the revised scope:

| Finding | Final disposition |
| --- | --- |
| Validate-then-reopen file race | One handle for hashing/text; no-follow opens per component; file/root identity and stat revalidated before insertion. |
| Root retargeting | Pinned device/inode, persisted approvals and verified restore; replacement requires explicit re-selection, including after restart. |
| Lost watcher exclusions | Initial/event/periodic scans receive the same exclusions; direct indexing also rejects excluded paths. |
| Incompatible/unsigned protocol | Removed as a live implementation; disabled seam cannot call transport. Actual device protocol stays T05/T06. |
| Deletion repopulates index | Stop/drain watcher, serialize store, advance durable generation and persist deleted pause until explicit resume; FTS clear, secure-delete/checkpoint/vacuum. |
| Failed traversal prunes good rows | Only completed roots are eligible for pruning. |
| UI selection leaves old roots active | One coordinated selection operation stops old work, clears old scope and persists new approvals. |
| Runtime opens socket without serving | Runtime-owned HTTP serving thread, bounded JSON controls and local HTML page. |
| Cache broadens file permissions | Owner-private cache/database/sidecars and process-exclusive cache lock; unsafe existing permissions or unsupported platforms are denied. |

Independent follow-up additionally found an unclosed directory descriptor and a
`..` cache-separation bypass. Both were fixed and regression-covered: scandir
uses its existing directory descriptor, and runtime cache checks use the store's
normalized path. Current-ACL validation before retrieving cached results remains
P18-T05's explicit requirement; the scaffold has no content-release callpath.
