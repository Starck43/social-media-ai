## Audit findings on the repair itself

Three places looked like weakening on first read; each was checked against the code rather than
the commit message:

- **Raw-text assertion replaced by a media-type assertion.** `PersonalInbox.snapshot` returns
  `e.event.title` / `.message` as stored, so a stored-text-absence assertion can only pass by
  failing the shipped contract. The two guarantees it carried are pinned separately and were
  re-read: producer scrubbing (the collector scrubs before `notify.create`, and
  `tests/notifications/test_notification_delivery.py:427` asserts neither the provider exception
  nor the private source name reaches the stored row) and render escaping
  (`tests/unit_web/test_attention_feed.py:303` requires `x-text="n.message"` and no `x-html` in
  `_shell_notifications.html`).
- **`platform_type` added to the collector stub.** The collector reads `source.platform_type`;
  the stub was the thing missing the field, not the collector over-reading a stub. Stub is now a
  real `PlatformType.VK`.
- **`Tool` replaced by `SimpleNamespace` in the shared digest harness.** The frozen dataclass made
  the "old contract" replay impossible. The stand-in carries exactly the four fields the
  confirmation path reads, so any future read of another attribute fails loudly instead of silently
  passing.

The `409`-to-`200`/`401` changes in `test_stale_context_and_csrf_reject_writes` were verified
against `app/web/notifications.py`: `_active_user` rejects only an `X-App-User` mismatch (401
`reset`), the active workspace is server-owned from `tenant_users` (a posted or query workspace is
ignored, as the handler's own comment states), and `data-invite-open` renders only under
`can_manage_workspace` (owner/admin), so the `operator` level was doubly wrong.
