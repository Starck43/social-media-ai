# P7-T07 — Clarify local development and server startup commands

Registry: [ROADMAP](../../ROADMAP.md#p7). Parent: [P7](../phases/p7-operations.md).

## Scope, evidence and acceptance

**Evidence:** `README.md` points operators to `docs/DEPLOYMENT.md`, which contains
supported staging/production paths alongside historical development and systemd
sketches. The root `docker-compose.yml` is a legacy web stack; the checked-in
`docker/docker-compose.yml` is a local db/API sketch that runs Alembic at API
startup and publishes port 8000. There is no supported `dev` VPS profile.

**Change:** Add a concise command selector that distinguishes local development,
remote staging and gated production; name the actual Compose wrappers and release
command, note migration/runtime behavior, and warn that generic `docker compose`
selects the legacy root file. Keep all scripts and Compose configuration unchanged.
No host, deployment, migration, provider or external write is authorized.

**Acceptance:**
- The guide states there is no supported `dev` server profile and recommends the
  isolated staging profile for remote validation.
- The local, staging and production commands match the checked-in Compose files
  and `scripts/ops/deploy_vps.sh`; production gates and optional runtime behavior
  are explicit.
- Historical examples cannot be mistaken for current copy/paste procedures.
- Markdown/static documentation checks pass; no application tests are applicable.
