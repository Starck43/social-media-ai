## Behaviour reviewed in source

- Requests and decisions resolve the actor and tenant themselves, lock tenant, user, active web
  membership, workspace role and the exact role-to-permission rows, and check the dedicated
  `documents.approval` `CONFIGURE` right plus document ACL scope.
- Decisions require the assigned approver, the exact current revision ID and hash, `pending` status
  and a live deadline; a comment is stored encrypted (`pii:v1:`), never in clear.
- Idempotency: requests are serialized on an advisory lock keyed by tenant/actor/key and compared by
  intent digest; decisions replay exactly or fail closed; a superseded pending request is expired
  and notified rather than duplicated.
- Web inbox notifications are published in the decision's own transaction (`notify.create(session=…)`);
  messenger send inside a caller transaction raises `ValueError("messenger_send_requires_post_commit")`,
  and a forced notification failure rolls the decision back (covered by test).
- The temporary owner-only decision path in `DocumentService.transition` is removed; the legacy route
  now returns `approval_request_required`.
- Readiness boundary the owner set — web inbox only; TG/MAX/email delivery of an approved document is
  P19-T05 on top of P15-T14 — is stated in the card, the PR body and the code (`send_to_messenger=False`).
