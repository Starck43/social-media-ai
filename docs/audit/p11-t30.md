# P11-T30 — Test-schema bootstrap carries every migration-only trigger

Card: [docs/tasks/p11-t30.md](../tasks/p11-t30.md)
Branch: `dev` (auditor-owned tooling fix, committed directly)
Revision: see the `fix(tooling): p11-t30` commit in `git log`

## Finding

`scripts/setup_test_db.py` builds a fresh schema from `Base.metadata.create_all` and then replays
the guard objects kept in `scripts/schema_guards.py`, because the metadata path emits no trigger
and no trigger function. That module had drifted from migration history:

- missing `bump_contact_pii_marker` and its `contact_pii_marker` trigger on all 11 tables that
  0130 and its followers cover;
- missing `detach_document_contact` / `document_detach_contact`;
- missing `detach_document_case_evidence` / `document_detach_case_evidence`;
- missing `set_document_current_revision` / `document_revision_current`;
- stale `guard_document_revision_content`: the pre-0142 body, which does not pin
  `change_description` and has no authorship-erasure exception.

Consequence: a schema built by the bootstrap path lost the PII marker bump and the
`current_revision_id` pointer maintenance, so document create/restore and history pages fail on it
and PII mutation tracking silently does not run. `test_schema` was unaffected because migrations
built it — which is exactly why the gap stayed invisible.

The drift test `tests/tooling/test_p11_t24_schema_guards.py` existed but aborted before comparing:
`for table in TABLES` in 0130/0139 was not followed to the module-level constant, and a single
`op.execute` creating several triggers (0142 detaches two) was read as one block.

## Fix

- `scripts/schema_guards.py`: added the four objects and replaced the document-revision guard body
  with the 0142 contract (change description immutable, authorship change refused except the
  FK-driven erasure of a deleted user).
- `tests/tooling/test_p11_t24_schema_guards.py`: resolve `for <name> in <CONSTANT>` against a
  module-level literal tuple, apply conditional `if flag:` replace/append refinements to a local
  before it reaches SQL, resolve `fields.replace("NEW.", "OLD.")`, and split an `op.execute` text
  into per-`CREATE TRIGGER` blocks so multi-trigger statements are fully compared.

that should have caught the omission compares in full and names both directions. No application
code, no migration, no shared-schema reset was needed.
