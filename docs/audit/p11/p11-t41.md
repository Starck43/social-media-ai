(46 insertions, 51 deletions) and this task's card.

check and `apply_collection` canonicalization, then the entry point itself runs
`resolve_task_plan_create` + `project_task_plan_create` for a new task and
`parse_task_plan` + `apply_task_plan` for an existing one.

unchanged, including clearing `data["sources"]` when the plan is not
`source_scope=selected`. `validate_vk_access_retained`, the owner-activation
hold, tenant/source validation, scheduling and `super().on_model_change` keep
their previous order, and `CollectionIntentError`/`ValueError` are still
translated to `ValueError` the same way. The removed helper had no other caller
(`_prepare_task_payload` appears nowhere in the merged tree), so nothing depends
on the old name.

The five-writer assertion is untouched: `tests/tooling/test_p8_t41_surface_contracts.py`
still expects `{resolve_task_plan_create, project_task_plan_create}` from the
admin entry point, and the fix satisfies it rather than relaxing it.
