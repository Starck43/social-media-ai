## Goal

Server side of pairing and federated search.

## Baseline

- P12-T12 file catalog, admission and evidence contracts (PR #327).

## Plan

1. Model `local_connectors` (tenant, owner, device name, fingerprint, platform, version, state, last seen, revoked at) and pairing codes.
2. Endpoints `POST /api/v1/files/connectors/register` (pairing), `GET /api/v1/files/connectors`, `DELETE …/{id}` (revoke), WebSocket endpoint for connector sessions owned by the API process with bounded connections.
3. `POST /api/v1/files/search`: authorizes the actor, picks the owner's online connectors, fans out with timeout, and merges ranked observations with file references. Only explicitly consented company roots may transit cloud; local-only search remains unavailable here.
4. Chat integration: a separately invoked company-root search displays references outside the model context, with no snippets, automatic model call or local-only fallback.

## Implementation decisions / security gates

- On 2026-11-04 the owner explicitly approved Q-19 R-2 parameters: closed UTF-8 JSON with ASCII schema keys, sorted keys/no floats/duplicate-key rejection; Ed25519 signatures; explicitly configured operator-owned CA/signer and X.509 client certificates valid for at most one hour; five-minute pairing codes; digest-only replay retention of 24 hours, at most 4096 entries per device. Private keys are not generated as deployment defaults or committed. See the [recorded decision](q-19.md#owner-decision-for-p18-t02-2026-11-04).
- Replay ledger: durable request ID + digest per device, 24-hour window, bounded capacity, no payload/result persistence; uncertain or missing prior outcomes return unknown/deny, never a blind retry. Search-only scope; fetch/index deletion remain unavailable.
- The authenticated ASGI TLS extension supplies device identity; public identity headers are never trusted. Activation remains disabled until independent security review and a real trusted TLS adapter deployment are verified. Owner approval of the parameters does not substitute for that verification.
- Second-party source review of the server increment is recorded in [Q-19](q-19.md#p18-t02-second-party-source-review-2026-11-04) and the P18-T01 follow-up. Independent chat-source review found no actionable issue in authorization, CSRF, tenant/consent bounds, projection, release fencing or text-only rendering. Desktop key-store/OS-path and real mTLS transport evidence remain future real-user activation gates; Q-19 stays open for those platform requirements.
