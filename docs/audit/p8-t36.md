## Finding and fix

One opt-in `FilteredSelectMultipleField(QuerySelectMultipleField)` plus a
shared `FilteredSelect` JS class replaces the hand-rolled role-permission
chooser presentation without replacing anything SQLAdmin-owned: offered
choices, bound PKs, empty-selection meaning, server-side validation,
permission hooks, CSRF and related-record controls stay with the original
multiple select, which remains the sole form value source and the no-JS
fallback. The field declares the existing `permission-transfer.js/css`
filenames through `FieldMedia`, so `collect_form_media` deduplicates asset
loading on create, edit and validation-error renders; the role template's
former hardcoded asset includes were removed. `RoleAdmin.permissions` uses
`transfer_mode="permissions"` (grouped code/name presentation, group
filter); `AgentTaskAdmin.sources` uses the plain mode with ordinary record
labels. No new catalog queries, persistence endpoints or permission grants;
the pending P9-T07 actor-scoping policy is untouched and not certified.
