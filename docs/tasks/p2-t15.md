## Scope and acceptance

Define how purchased service plans grant product entitlements to typed connector
operations, then enforce those entitlements at both admission and execution.
Reuse existing `Tenant.PLAN_LIMITS`, `effective_limits()` and tenant ownership
where they fit. Keep `MAX_WORKSPACE_MEMBERS` as a deployment ceiling that a
paid/business plan cannot override. Do not conflate a subscription with the
existing personal LLM payer consent, account
balance or spend caps. A plan may enable this product capability but never grants
VK's API permission or access to a user's account by itself.

Accept when each plan has an inspectable, versioned set of connector operations,
quotas and workspace/user boundaries; preview explains unavailable operations;
denied, expired or downgraded entitlements fail closed at both task admission
and execution, including already queued work; ownership and usage are auditable;
and web/API/CLI/admin/agent tools return consistent outcomes. Include migration
or compatibility behavior only if existing plan records require it. Use mocked
payment and provider evidence; this is not production billing verification.
