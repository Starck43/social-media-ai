authorization. Nothing is activated: no managed HTTP, no public apply, no

- **A** — one platform catalog plus one personal catalog per user, custody on
  providers and models, model metadata columns (`capabilities`, prices,
  `pricing_state`, output/context ceilings), per-plan capability grants and the
  owner-only grant management service.
- **B** — a typed `CatalogGrantResolver` that re-reads the holder context, the
  custody rows and every required grant on each attempt, a secret-free
  content-revision metadata cache, an explicit funding-aware read scope for the
  AI consumers, output hard ceilings, and a second fresh grant read after the
  reservation so a revoked grant denies the attempt before HTTP.
- Personal compatibility is unchanged: retained owner columns, CSV capabilities,
  Float prices, `tenant.plan_limits()["model_types"]` and the legacy owner/FK
  constraints stay readable, and no runtime caller binds the new scope.

## Accepted behaviour

- A grant names a numeric `llm_models.id` in a **platform** catalog, one row per
  capability; the holder's fresh policy list (`resource_limits["model_types"]`)
  is the only authority on routable capabilities, and the row's **whole**
  capability set must fit it.
- Every required capability needs its own active grant for the holder's plan; an
  invitee's own plan never widens or narrows the holder's rights.
- A personal row needs the holder, or an invited actor with a positive delegated
  consent version.
- Grants are re-read independently of any cache: metadata caching never
  authorizes, and a revoked grant, a downgraded policy or a retired model denies
  the next attempt. After a committed reservation the seam resolves the grant
  again; a refusal settles `not_dispatched` and releases the lease.
- Managed rows are deactivated, never deleted; the custody guards refuse the
  deletion.

## Rollback

Revert the added model/service/admin files and the catalog storage revision.
`down_revision` moves back to the previous head; the migration's downgrade
refuses to erase platform catalogs, explicit pricing decisions or grants, and
restores the retained owner constraints for personal rows. No existing runtime
path is re-pointed, so the legacy personal path stays valid throughout.
