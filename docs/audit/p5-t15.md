## Premise rechecked in current source

The task allowed two outcomes: normalize derived envelopes, or record why no
change is needed. The second applies, and the reason is verifiable rather than
asserted:

- `SummaryPayload` / `AnalysisPayload`, the models the historical finding named,
  no longer exist anywhere in `app/`; `grep` returns nothing.
- `validate_output` in `app/services/ai/output_contracts.py` raises
  `OutputContractError("invalid_structured_output") from None` for every failure
  path, so the normalisation happens for inherited models too. Confirmed
  independently: a test-only subclass of `DigestSummary` receiving an error
  envelope raises the content-free boundary error and does **not** leak the
  payload, while a valid derived payload still validates.
- `extra="forbid"` on `StrictOutput` is what makes "smuggled `error` beside
  valid content" fail, and the digest builder checks `response["error"]` before
  calling `validate_output`, so provider errors keep their precedence.
- `app/services/digest/builder.py:102` returns `summary_provider_failed` without
  reaching validation; the delivered test pins exactly that ordering.

No production patch is required under the scope's explicit alternative. The PR
changes **only** `tests/ai/test_p5_t15_derived_error_envelopes.py` (+150), which
matches the "owns `output_contracts.py` and its focused test" ownership without
touching production behaviour.

## Findings (not blocking)

- The test imports `source_import_isolation` from `tests/`. Under a bare
  `--noconftest` invocation the module is not on `sys.path`, so the documented
  command only runs with the project root layout (`PYTHONPATH=.:tests`) or the
  root conftest. Not a defect — every sibling `tests/admin/*` module imports it
  the same way — but the exact command should be reproducible, so record the
  `PYTHONPATH` part alongside it.
- The digest case loads real builder source with only provider/journal/storage
  doubles. That is honest and its journal assertion is useful, but it is not a
  durable-DB proof; the card already states this and does not overclaim.
