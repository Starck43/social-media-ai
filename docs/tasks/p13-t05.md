## Goal

Make every new module audited and documented the same way.

## Baseline

- `action_audit_events` with allowlisted codes ([ACTION_AUDIT](../ACTION_AUDIT.md)).
- FastAPI OpenAPI and generated route tables ([generated](../generated/README.md)); bounded API lists (P11-T08).

## Plan

1. Extend the audit action allowlist with namespaced codes (`crm.*`, `comms.*`, `planner.*`, `calendar.*`, `onec.*`, `files.connector.*`, `documents.*`, `commands.*`) and safe `reason_code`s; registration helper so modules add codes in one place. The allowlist is enforced by the `ck_action_audit_events_action` CHECK constraint, not by application code alone, so this step also ships the migration that widens it and the matching model/manager update (next free revision after rebasing on `dev`; `0124` is taken by #308). Tracked as finding F-1 of the [P13-T01 audit](../audit/p13-t01.md).
2. Define API conventions in `docs/API.md#business-modules`: `/api/v1/<domain>/…`, auth dependency, tenant context, pagination envelope, error model (`code`, `message`, `request_id`), idempotency header for POSTs that create commands, no personal data in examples.
3. Shared Pydantic base schemas and an OpenAPI tag registry; contract test that every new route has a tag, response model and documented errors.
4. Decide and document `/docs` and `/openapi.json` exposure per environment (configuration flag, default off in production).
5. Regenerate route tables and add the check to the module task templates.
