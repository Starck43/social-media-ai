## Deliverable

Shadow-read representative workspaces, compare visibility and results, freeze or fence writers at the watermark, catch up and switch the sole authority per workspace. Compare all projections and queued occurrences, confirm provider-owned tasks remain remote, preserve old IDs and link redirects. Make the new Tasks flow the default across surfaces only after parity. Retire each legacy writer/column separately after callers, in-flight jobs and retention windows are accounted for.

**Follow-up cutover dependency.** [P22-T15](p22-t15.md) gates the removal of follow-up entry links and the redirect.

## Surfaces to retire and logic to keep

Retirement is per surface, after its replacement shows the same work and the same refusal:

| Surface | Disappears | Stays reusable |
| --- | --- | --- |
| `/app/actions`, `/app/actions/{id}` | Menu slot already gone; the journal page becomes a redirect to the unified task list filtered by «Ждут моего решения». | Capability registry, command ledger decisions, dry-run semantics and the pending counter. |
| `/app/followups` | Menu slot already gone; replace the remaining catalogue link in «Переписка» with the corresponding task-list entry. Redirect bookmarks to that same permission-filtered list after T15 and evidence reconciliation. | Quiet hours and imprecise-date detection used by the task deadline and reminder. |
| `/app/commands` approval inbox | The batch review surface stays while commands still need bulk approve/reject; it is the operator view, not a daily section. | The same ledger the task card calls; no second decision path is introduced. |

Every removed route must leave a redirect, keep its permission check (refusal, not a leak) and be listed in the reconciliation
report with the surface that replaced it.

Filter by approved commitment origin using T15 provenance. Reconcile historical follow-up snippets before redirecting. Preserve authorized evidence links for snippets without a
created task and keep the legacy read path available until those links work. A redirect creates zero tasks and reminders.

## Implementation sequence and handoff

1. Start with T06 reconciliation output. Pick a mixed workspace with legacy and new-only work, an outstanding approval and an active scheduled run.
2. Rehearse shadow read → catch-up → writer fence → switch → reconcile on isolated data. Rehearse recovery after a new-only write. Quantify mismatches by task, ACL, schedule and receipt.
3. Deliver the operator procedure with stop conditions, authoritative writer at each stage and recovery commands. Record separately the evidence and authorization for any public application.

## Acceptance

Before cutover, reconcile the all-connected sender view against the authorized accounts in Settings. Follow one verified sender across multiple accounts and channel families from the task receipt into «Переписка». Check original threads, newly connected accounts on the next run, duplicate-free replay and loss of access. Missing an eligible source family blocks correspondence cutover. [T10](p22-t10.md) · [T24](p22-t24.md)

Produce a per-tenant reconciliation and mismatch disposition, forward and rollback rehearsals with concurrent and post-switch writes, zero duplicate schedules and no increased visibility. A workspace can stay on the old path while mismatches are resolved. Separate irreversible removal/public application from the additive rollout under the database policy.

Exercise an isolated copy with mixed legacy data and new-only tasks. Record rollback cutoff and recoverable data path. Link task, migration and interface acceptance before removing old writers.
