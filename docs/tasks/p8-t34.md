## Selected scope and boundaries

The owner selected and scheduled a Yandex Disk read-only pilot in P12: one user-
selected folder, no write or delete. First develop a fail-closed folder policy
foundation and focused tests; then build the reviewed adapter, authorized connection
and safe read-only user flow in separately reviewable commits. A provider-wide
OAuth read grant is not equivalent to one-folder provider permission; disclose it
and enforce the root in the application. No provider credentials or live account
operations, external writes, deployment or public migration are authorized by this
claim. The unrelated credential-security task P12-T14 retains its own scope.

User-requested per-folder restrictions must protect against accidental mutation:
read-only is the pilot maximum; child folders may be made more restrictive, never
more permissive than their ancestors. Distinguish folder controls from later write
capabilities, which require a separate task, review and explicit enablement.

## Independent audit — 2026-11-03 (head `681cf525`, PR #313)

**Verdict: NOT ACCEPTED; task stays IN_PROGRESS and the PR stays a draft.**
Full report: [P8-T34 audit](../audit/p8-t34.md). Findings were posted as review
comments on #313. No merge is authorized by this audit.

Correctable findings, in the order they should be fixed:

1. **Blocker — HTTP/1.1 framing** (`yandex_http.py::_exchange`): the loop ends only
   on `h11.EndOfMessage`. A `chunked` response, or one with neither
   `Content-Length` nor `Transfer-Encoding`, is defined to end at connection close
   (RFC 9112 §4.4/§3.3.2), which the client never signals, so a valid provider
   answer degrades to a 15 s deadline and `provider_unavailable`.
2. **Non-200 responses are not consumed** — the `h11.Response` branch returns
   before the body is read.
3. **`test_tamper_and_other_cipher_purpose_do_not_validate` is order-dependent**:
   it alters a character that encodes Fernet padding bits for ~1/64 of random
   keys; 3 of 12 runs failed with `DID NOT RAISE`. The selector itself is intact.
4. Documented deadline mismatch (`TOTAL_TIMEOUT` vs the outer service timeout, and
   the caller `timeout` is discarded).
5. The exclusive connection lock held for the network read makes `disable`/re-save
   wait up to the full timeout; record the accepted latency instead of implying a
   normal-time path.
6. Provider errors render the browser template under 503 instead of a minimal
   error state.
7. A selector is not bound to the browse request and stays valid for its 300 s TTL
   across a restriction-only policy change (no UI consumer yet).
8. `pyproject.toml` gained `certifi`/`h11`, but `requirements.txt`,
   `requirements/constraints.txt` and every `requirements/*.txt` export were not
   regenerated: `scripts/packaging/dependencies.py check` FAILs on this head and
   PASSes on `origin/dev`.
9. The card's "172"/"195" test totals do not reproduce; record exact commands and
   numbers (128 selector/transport + 36 integration/setup on this head).

Verified as holding: DNS pinning and address validation, verified TLS with
`certifi` and the `SSLKEYLOGFILE` refusal, fixed endpoint and strict
request shaping, size/encoding limits, download-target validation, policy loaded
only from the stored connection, per-call owner/membership/state re-authorization,
revocation serialization, CSRF/session-bound browse form and private response
headers. Style checks and `git diff --check` are clean on the changed files.

**UNRUN:** live provider, browser E2E and screenshots, full suite, public
migrations, deployment.

  the close it already performs (RFC 9112 §4.4/§3.3.2), so a valid provider
  answer no longer degrades into the deadline. Covered by
  `test_unframed_body_ends_at_connection_close` and the existing chunked case.
- **Refusals (2).** Non-200 bodies are read to `EndOfMessage` and discarded
  instead of abandoned; `test_non_200_body_is_drained_not_returned` and the
  parametrised status test cover it.
- **Selector test (3).** The tamper case flips an authenticated ciphertext byte
  instead of the trailing base64 character, whose padding bits made it
  order-dependent. Sustained: 10 consecutive full runs of the selector and
  transport files, `130 passed` each.
- **Deadline (4).** The client no longer keeps a second timer; the reader's
  `_TOTAL_TIMEOUT` is the single budget and its value is now visible to the
  timeout test.
- **Disable latency (5).** Recorded in the reader docstring: disabling waits for
  at most one in-flight read.
- **Provider errors (6).** A 503 renders a minimal no-store page, not the browse
  shell; the assembled route test asserts the listing legend and sibling
  navigation are absent.
- **Selector policy binding (7).** `ReadOnlyFolderPolicy.binding()` is mixed into
  the derived key, so a restriction-only change also invalidates issued
  selectors; `test_reference_denied_when_restrictions_change` covers it.
- **Dependency exports (8).** Regenerated with the pinned `uv` compiler;
  `scripts/packaging/dependencies.py check` reports `Dependency parity PASS: 5
  profiles`.
