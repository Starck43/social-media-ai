## Scope

- Classify eligible, already collected social evidence into `needs_attention`, `can_wait` or `uncertain` with a short reason, evidence link, timestamp and bounded ranking. Show up to three highest-priority items, not an invented fixed quota; expose remaining items and allow correction. Scores or urgency are recommendations, never facts or automated incident declarations.
- Choose a deterministic baseline before any optional typed, bounded model-assisted ranking. Treat source text as untrusted data, never as instructions. Use a labelled representative fixture to measure ranking, false negatives and evidence coverage against the baseline; record chosen thresholds and failure handling. Low confidence, empty data, source denial, partial coverage and model failure are visible, not silent downgrades.
- Define the attention-item projection (provider, kind, authoritative reference, redacted title, reason, recommended priority and basis, due/expiry, owner state, allowed actions as links, boundary, freshness) as a typed read-time interface. It stores no copy of provider rows or bodies; per-actor dismiss/snooze/seen is the only new state, if any. The brief composes whichever providers are available and names the missing ones.
- Reuse existing report windows, source/actor/tenant authorization and delivery controls. Offer an on-demand preview and a user-configured morning schedule in the user's selected timezone, with explicit windows, quiet hours and deduplicated runs; do not create a second scheduler or sender. Delivery to Telegram/MAX uses the existing notification surface (D18) and links back to the web brief. A generated brief is not permission to send externally.
- Keep P15's metadata-only/no-body-cache decision and source boundaries intact; do not infer that VK/TG access to a community, account or search method is available. Apply payer/model budget checks, retention and redaction. Never forward local-only evidence to a cloud model.

## Acceptance and checks

- Representative labelled tests demonstrate the selected approach and publish baseline/result metrics, false-negative examples and limitations; no invented accuracy claims. Source links, reasons, dates and incomplete/denied sources remain visible. No cross-tenant or revoked-source evidence reaches preview or model.
- Test timezone/DST, scheduled retry/idempotency, quiet-hours behavior, zero/partial results, model error, override, budget denial and malicious source content. Existing delivery confirmation and notification behavior stay unchanged. Use mocked provider/model calls; no live test without separate owner authorization.
- Record focused commands, tested SHA, coverage/evaluation corpus and DB target/cleanup if applicable. Use existing services rather than a second report, notification or queue authority.

## Out of scope

Automated replies or crisis declarations, hidden suppression of low-ranked results, calendar/email aggregation, real-time paging, new API/provider scopes and unsupported global VK search.

## Design and implementation decisions

- Deterministic title-only baseline first; optional model refinement is deliberately
  disabled. No payer/model dispatch, cloud forwarding or new provider scopes exist.
  Bounded scores are ordering recommendations, not probabilities or incident facts:
  explicit risk marker 80, injection needing review 60, ambiguous title 50,
  informational marker 20. Unknown/low-signal results remain visible.
- Social results project existing daily AIAnalytics references. The date shown is
  the authoritative analysis/report date, not an invented post timestamp. Source
  eligibility and actor rights are rechecked before projection; access failures
  remain unavailable, not a fabricated empty success. All data is local-only.
- The first three sorted results are emphasized; every eligible result in the
  bounded selection remains available. Source (100) and row (500) caps are visible
  coverage limits, not claims of a global ranking. Email/phone details and known
  injection phrases are redacted from titles; HTML remains autoescaped.
- Corrections store only current actor/workspace/reference/category in the signed
  browser session, capped at 20 per actor/workspace. They are explicitly session-only;
  provider history is never overwritten. Rollback: restore the recommendation.
- Read-only preview has selected IANA timezone and explicit calendar-day window;
  fixed historical windows survive navigation and correction. «Сегодня» links to
  the same service, without touching P20-T13's shell files. Coordination:
  https://github.com/Starck43/social-media-ai/pull/473#issuecomment-6801745386.
- D18/D19/D20/D22 are already answered in Q-20: extend the shared notification
  surface, never create a second sender/outbox or quiet-hours policy; defer during
  quiet hours. That authorization applies to this new consumer. No renewed owner
  permission is needed merely to implement an additive provider/job handler.
  An initial concern about requiring another D18 decision was corrected by reading
  the accepted decision before any dispatch implementation.
- Schedule bindings must authenticate the configuring recipient and bind the
  workspace/task/recipient/window/timezone/cron. Admission must freeze scheduled_for
  for retries. External messages contain only a generic authorized brief link;
  generation alone grants no external send permission. MAX is unavailable unless
  the shared sender actually supports it; never report a successful MAX send.
