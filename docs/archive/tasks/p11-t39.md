# P11-T39 — Pre-existing red check inventory re-verification

Registry: [ROADMAP](../../../ROADMAP.md); parent: [P11](../../phases/p11-structure.md)
(accepted phase, this is a registered follow-up). No prerequisites.

## Goal

Replace the unverified "pre-existing red" list in local scratch with checked,
portable evidence: each known-red check either reproduces on current `origin/dev`
and gets its own registered row, or is shown to be green/environment-only and
dropped from the list.

## Why this exists

Agents currently carry a hand-maintained list of failing checks in
`.agents/tmp/state.json` (local scratch, never portable evidence, last updated
2026-11-13). It is used to argue "that failure is pre-existing" during reviews.
Nobody has re-run it since, so it can no longer support that claim: a stale
excuse is worse than no list, because it hides a regression behind a remembered
failure. The same applies to the companion note that a full
`scripts/ci/checks.py` run takes longer than the lane's time budget.

- Re-run each on a fresh `origin/dev` with the recorded environment and record
  pass/fail plus the failing assertion.
- Reproducible failures are real debt: register each cause as its own card/row
  (one cause per row, no umbrella "fix reds" card) and link it from here.
- Failures that need a missing service, schema or credential are environment
  gates, not product bugs: record the exact missing prerequisite so a later run
  can tell them apart.
- Follow [tests/AGENTS](../../../tests/AGENTS.md) for DB scopes, fixtures and
  synthetic-record cleanup. Serialize any shared DB work.
- Out of scope: fixing the failures (each gets its own row), changing the suite
  selection, and running the full suite — that stays an explicit owner request.

## Steps

1. Reproduce the five entries and capture the exact failing assertion or the exact
   missing prerequisite for each.
2. Decide per entry: real failure, environment gate, or no longer red.
3. Register rows for the real failures; record the environment gates with their
   prerequisite; delete resolved entries from the scratch list.
4. Replace the scratch list's role: the card (or the rows it links) is the durable
   answer to "is this failure pre-existing?".
5. Record the head SHA, date, DB target and cleanup for DB-touching runs.

## Acceptance

- Every entry has a reproduced verdict with its command and environment recorded.
- No "pre-existing" claim survives without a row, an environment prerequisite or
  a green rerun behind it.
- DB-touching runs leave no synthetic residue.
- The scratch list is emptied of resolved items; nothing durable lives only in
  `.agents/tmp/`.
