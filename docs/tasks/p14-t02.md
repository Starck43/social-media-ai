## Goal

Keep a tenant-scoped mirror of CRM entities and contact identities fresh every 15 minutes without exceeding provider limits.

## Baseline

- Runtime scheduler/jobs (`app/jobs/`); contact core from [CONTACTS](../CONTACTS.md) ([acceptance](../audit/p13-t07.md)).

## Plan

1. Model `crm_entities`: tenant, connection, entity type (`contact`, `company`, `lead`, `deal`), native ID, title/stage/amount/currency (deal), assigned user ref, encrypted personal fields, `custom_fields` (allowlisted, encrypted where personal), `date_modify`, `last_synced_at`, `deleted_at`; unique `(tenant_id, connection_id, entity_type, native_id)`.
2. Field mapping config per connection: which `UF_CRM_*` fields hold birthday/anniversary; defaults use standard `BIRTHDATE` for contacts.
3. Sync job `crm.bitrix24.sync` every 15 min per active connection: `crm.contact.list`, `crm.company.list`, `crm.lead.list`, `crm.deal.list` with `filter[>DATE_MODIFY]` watermark, `order[ID]`, `start` paging, `batch` grouping; watermark advances only after the page commits.
4. Map contacts/companies/leads to `contact_identities` (email, phone, bitrix24_* kinds) via the contact core; never auto-merge.
5. Deletion detection: optional `ONCRM*DELETE` event handlers (requires public callback, R-14) or periodic ID reconciliation; mark `deleted_at`, do not hard-delete.
6. `POST /api/v1/integrations/bitrix/contacts/sync` triggers a one-off job; status shows last run, counts, deferrals.
