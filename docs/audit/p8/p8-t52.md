## What was reviewed

The loss was in the shared staging guard, not in the VK mapping:
`app/utils/content_attachments.py::_staged_media_url` rejected every URL with a
query string, while modern VK photo CDN links are only fetchable together with
their `?quality=…&cs=…&u=<opaque key>` query. The VK client already picked the
largest `photo.sizes[]` entry through that guard, so no mapping code changed.

The owner chose option B (recorded in the card and ROADMAP). Implementation:

- `_PROVIDER_MEDIA_HOSTS = ("userapi.com", "vkuser.net")` with suffix-exact host
  matching; the query is preserved on those CDN hosts only. Every other
  restriction is unchanged: https only, no fragment, no userinfo, port 443/None,
  public host, no whitespace/control characters, 2048-byte bound. `vk.com` is
  deliberately excluded because it serves pages, and the analyzer fetches the
  media URL.
- New `tests/tooling/test_p8_t52_provider_media_query.py` (3 tests, registered in
  `.ci/offline-tests.json`), new `tests/collection/test_p8_t52_vk_media_reference.py`
  (4 tests) and one added case in `tests/collection/test_staged_attachments_contract.py`.
  No existing assertion was weakened; no historical backfill or live write.

## Review result

- Exact diff: 6 files, all inside the task's staging/code-and-tests scope. No
  secret value appears in the change (the query key is the literal `OPAQUE` in
  fixtures; the live record stores no URL text).
- Suffix matching cannot be bypassed by `userapi.com.evil.example`,
  `notuserapi.com` or `userapi.com@evil.example` (userinfo is still rejected);
  uppercase and trailing-dot forms of the legitimate CDN work as intended.
- Video previews stay `{"type": "video", "url": None}` by design; classification
  and snapshot shape contracts are unchanged.
- The card's option-B table listed `vk.com` among candidate hosts; the delivered
  allowlist is `userapi.com`/`vkuser.net` with the documented reason, and ROADMAP
  records exactly that choice. No accepted contract was altered.
