## Verdict

The change does what the card says, and the problem it removes is real: the
script passed `postgresql+asyncpg://…` to psycopg2, which rejects the SQLAlchemy
driver suffix as an invalid DSN, and the error reads like a demand for a
password. No secret is needed here — the database authenticates through libpq.

Verified on `327e42b6`:

- `tests/tooling/test_p11_t36_schema_inventory_dsn.py` — **4 passed** with
  `--noconftest`, and **4 passed** with the real conftest on a freshly built
  isolated schema (`p11t36_check`, dropped afterwards). The file imports no
  application module and touches no database.
- Live snapshot from the main checkout with `TEST_POSTGRES_URL` and
  `POSTGRES_URL` unset and `.env` unsourced: **succeeds**, `test_schema`, 104
  tables / 71 triggers / 37 functions / 328 indexes / 90 sequences / 113 types.
- Without any `.env` the error now names the fix and states that a password is
  not required.
- `snapshot()` keeps its signature; the in-test caller
  `tests/integrations/test_p12_t08_workspace_connections.py` and the CLI in
  `scripts/verify_p11_t29_offboarding.py` are unaffected.
