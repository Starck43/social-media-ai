# P11-T23 — Split agent-task documentation by reader

Registry: [ROADMAP](../../ROADMAP.md#p11). Parent: [P11](../phases/p11-structure.md) (navigation only).

## Scope, evidence and acceptance

**Evidence:** `docs/AGENT_TASKS.md` mixes three audiences that almost never read
each other: queue/runtime architecture, the owner-approved explicit task-plan
contract, and the "why not Celery" decision. Cross-document links concentrate on
one anchor, `#explicit-task-plans`, while a reader of the queue section loads the
plan contract it does not need. The file only grows: recent commits append new
sections and nothing is retired, so each new contract widens the read path for
every unrelated reader. Line counts and anchors are derived from the file, never
recorded here.
**Change:** split by reader into queue/runtime documentation and the task-plan
contract, keeping every existing heading and anchor resolvable from its new
location; leave a short pointer where a section moved. Compress duplicated
explanations only where the same rule is stated twice; do not summarise code
paths, schema fields or rejection semantics into prose that loses the checkable
detail.
**Acceptance:** every inbound link and anchor that previously resolved still
resolves; no rule, field name, status value, guard or rejection semantics is
lost, merged into an ambiguity or silently dropped; the queue section alone is
enough to operate and debug the queue; the plan contract alone is enough to
implement a task plan; move-only and wording edits are separate commits; a
link/heading check is recorded with its exact output.
**Dependency/risk:** P11-T16 (navigation contract) and P8-T40/P8-T41 (they cite
the plan contract as input). P8-T39 edits the surfaces the queue section
describes; do not split under an active journey edit. Editors, agent tools and
chat routing are not changed. If a section has to be rewritten rather than moved,
stop and ask the owner.
