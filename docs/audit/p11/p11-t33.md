# P11-T33 — DB tests refuse any schema but the literal `test_schema`

**Verdict:** ACCEPTED · 2026-11-09 · merged into `dev` (PR #455)
**Accepted source:** `ef71babf` (branch `fix/p11-t33-schema-guard`)
**Base:** `dev` `adefe7bf`, rebased to `6832cc97` before acceptance (registry-only conflict)
**Owner:** the kilo lane claimed this task and its commits never reached `origin`; the auditor
recovered the work from a local dangling branch and finished the two call sites that appeared later.

## Outcome

No DB fixture pins a schema name any more. One helper decides whether the run may touch a database,
and it derives the working schema from settings instead of comparing against a literal.

## Delivered

- `tests/support/schema_guard.py` — `require_isolated_schema()`: returns the resolved test schema,
  raises `RuntimeError` naming both schemas when it equals the working one.
- `scripts/setup_test_db.working_schema_before_redirect()` — the pre-redirect working schema stays
  readable after `resolve_and_redirect` repoints `DB_SCHEMA`.
- Twelve call sites: the ten in the original claim plus `tests/calendar/test_p16_t03_t04_service_db.py`
  and `tests/knowledge/test_p19_t07_coverage.py`, both added after the original change. The
  `__table__.schema` metadata check now compares against `settings.DB_SCHEMA`.
- Test-only: no application code, no migration.

## Checks

- Refusal: `DB_SCHEMA=public DB_TEST_SCHEMA=public` →
  `RuntimeError: Refusing to run DB tests against the working schema 'public'; resolved test schema is 'public'. Set DB_TEST_SCHEMA to a schema other than the working schema.`
- The same four DB suites on the isolated schema `p11t33_probe` built by `scripts/setup_test_db.py`:
  **32 passed**.
- On the shared `test_schema` the same run cannot start in this environment: 32 fixture errors with
  `Test bootstrap refused: model tables still absent after table creation: outbox_reply_evidence` —
  that schema predates `0149`. Recorded as a stale-schema fact, not claimed as a pass; the acceptance
  criterion "same suite on both schemas, no edits between runs" is met for the isolated one and is
  unprovable here for the shared one.
- Scratch schemas removed after the run (`p11t33_probe`, plus the leftovers from the P15-T08 and
  P19-T08 verification runs).
