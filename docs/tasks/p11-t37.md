## Context and defects

Four concrete issues were identified while bootstrapping and validating the full local development and `test_schema` environment at revision `0155`:

1. **`test_schema` guard omission for `0154_p2t17_service_plan_storage.py`**:
   Migration `0154` creates `service_plan_policy_immutable()` and four triggers (`service_plan_policy_immutable`, `service_plan_policy_no_truncate`, `service_plan_backfill_immutable`, `service_plan_backfill_no_truncate`), but `scripts/schema_guards.py` was not updated with those objects. Consequently, a metadata-built `test_schema` (`scripts/setup_test_db.py`) installs 75 triggers and 39 functions instead of `public`'s 79 triggers and 40 functions, leaving `service_plan_policies` and `service_plan_backfill_resolutions` unguarded in `test_schema`.
2. **AST parser failure in `tests/tooling/test_p11_t24_schema_guards.py`**:
   `0154` emits the two backfill triggers inside a tuple-target loop (`for event, level in (("UPDATE OR DELETE", "ROW"), ("TRUNCATE", "STATEMENT")):`) with an equality conditional (`trigger = "service_plan_backfill_immutable" if level == "ROW" else "service_plan_backfill_no_truncate"`). `test_p11_t24_schema_guards.py` only matched loops bound to `_TABLE_PARAMS` (`"table"`, `"stem"`) and only evaluated boolean literals or names in `_condition`, raising `ValueError: Cannot resolve migration call arguments for guard DDL in 'upgrade'`.
3. **Stale factory double in `tests/security/test_web_session_cookie_security.py`**:
   `app/main.py:create_application` calls `openapi_options(settings.ENVIRONMENT, settings.API_DOCS_ENABLED)`, iterates `BUSINESS_TAGS.values()`, and registers `AdminCSRFMiddleware` before `SessionMiddleware`. The AST-extracted harness in `test_web_session_cookie_security.py` lacked `API_DOCS_ENABLED`, `openapi_options`, `BUSINESS_TAGS` and `AdminCSRFMiddleware`, failing all 8 test methods (12 outcomes including subtests) with `NameError: name 'openapi_options' is not defined`.
4. **PostgreSQL 15 CIDR netmask and dormant `0155` seed in `scripts/migrations/q14_validate_baseline.py` (and `q14_rehearse_bridge.py`)**:
   `SELECT inet_server_addr()::text` returns `'127.0.0.1/32'` (or `'::1/128'`) on TCP loopback in PostgreSQL 15, causing `address not in (None, "127.0.0.1", "::1")` to refuse the authorized local target (and pass a CIDR string to `PGHOST` in `q14_rehearse_bridge.py`). In addition, after `command.upgrade(config, "head")` applies `0155` on an empty disposable `test_schema`, `tenants.plan_holder_user_id` becomes `NOT NULL`, whereas dormant ORM metadata (`Tenant.__table__.c.plan_holder_user_id.nullable == True`) and `_seed_reference_rows()` (`tenants.get_or_create_owner("owner")`) require the dormant nullable column when `USER_SERVICE_PLANS_ENABLED` is `False`.
