## What was accepted

`spool_revision` renders through `render_revision` and writes into the shared
transient spool under the **same `outbox_<id>` item id and the same
`(sha256, size, mime)` triple** that `outbox_store._load_attachment_payload`
reads. `SpooledExport` carries no path and no bytes, so the renderer keeps no
dependency on the outbox package and either branch could land alone.

Spool hardening: the disk payload is Fernet ciphertext under a purpose-separated
key, meta and token hash/size the **plaintext**, TTL is enforced twice (meta age
and token `ttl`), token size is bounded before decrypt, `put()` refuses an
occupied position, writes are all-or-nothing and owner-only. An edited body still
fails `revision_hash_mismatch` before anything is written; a purged export raises
`SpoolRejected("attachment_missing")` instead of silently re-rendering.
