**Implementation ownership.** Alembic expansion/backfill utilities, legacy planner/agent managers and writers, FK and route crosswalk.

## Deliverable

Inventory legacy IDs, link payloads, reminders, event and contact links, discovery ownership, job history, approvals, one-off keys, series and deep links. Map planner rows and standalone user agent tasks into canonical identities. For an explicit same-workspace planner link attach compatible automation to its task. Preserve multiple independent schedules as identified child tasks with execution-for links. Preserve original grant boundaries per attachment; if visibility or semantics cannot be preserved, retain distinct tasks with restricted links. Do not promote stale links or assign an invented human owner. Report unresolved records and keep them on their original path.

## Implementation sequence and handoff

1. Inventory all readers and writers before choosing migrations. Make a mapping table for planner-only, agent-only, linked pair, multiple schedules, stale links and system jobs. Include colliding IDs from two namespaces.
2. Backfill one workspace twice, replay concurrent edits from the watermark and compare scoped reads and receipts. Where merging would expand visibility, keep separate records and explain the exception.
3. Give T07 a resolver taking workspace, legacy namespace and legacy ID. Give T12 the resumable command, discrepancy report and a rollback example including writes after the initial copy.

## Acceptance

Collision of planner ID 7 and agent ID 7 is unambiguous on legacy URLs. Backfill distinguishes system jobs, reruns safely after interruption, catches concurrent edits and produces per-tenant reconciliation including coverage, content fingerprints, ACLs, links and counts. Old IDs, CLI requests and result receipts keep their meaning. Existing consumers have one writer per fact during coexistence.

## Verification at implementation

Rehearse upgrade/downgrade and resume in an isolated schema. Exercise duplicates, deleted references, legacy empty scopes, differing rights and one-to-many assignments. Document reversible stages, rollback with post-switch writes and forward recovery when a shape is not legacy-representable.
