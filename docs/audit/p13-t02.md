## Delivered

- `app/core/pii.py` — versioned ciphertext (`pii:v1:`), keyed HMAC blind index
  (`pii:idx:v1:<kind>:`), closed normalization kinds (email lowercase + IDNA,
  phone E.164 RU, username), `redact_pii` and `PIIRedactionFilter` for logs,
  fail-closed `PIIError` messages that echo neither a value nor a key, and
  refusal to reuse key material across credentials, encryption and index keys.
- `app/models/types/encrypted.py` — `EncryptedText` (no plaintext in `repr`,
  refuses literal rendering) and `set_pii_pair` so the encrypted/index pair
  cannot be written apart.
- `cli/commands/pii.py` — `pii rotate`: bounded batches, resumable via `--limit`,
  idempotent, dry run by default, index columns never touched. The guard checks
  the ciphertext **and** the mandatory monotonic marker
  (`ROTATION_MARKER_COLUMN`, default `pii_updated_at`) that writers bump; a table
  without it is refused.
- Settings, settings views (`sensitive`), `.env.example`,
  [docs/CONFIGURATION](../CONFIGURATION.md) and
  [docs/PII_PROTECTION](../PII_PROTECTION.md) with the registration contract,
  what is and is not protected, and the rotation procedure.
- `scripts/ci/pii_rotation_pg.py` — real PostgreSQL, two connections, disposable
  schema: clean run, rerun after retirement, different-value and
  identical-ciphertext races, missing marker refused.

## Audit findings and how they were closed

1. **Key separation (raised on #355).** `_index_key` validated encoding only. Fixed:
   byte-compared against `CREDENTIALS_KEY` and every encryption key; all three
   reuses refused.
2. **Reusable log filter (raised on #355).** Only `redact_pii` existed. Fixed by
   `PIIRedactionFilter` (messages, `%`-args, tracebacks, stack info); structured
   `extra` stays raw and the doc says so.
3. **Rotation concurrency (raised on #355).** Fixed first by a conditional update
   on the ciphertext; the audit then found that this cannot see a concurrent write
   storing byte-identical ciphertext, which also made the post-retirement rerun
   report rewrites instead of zero. Closed on #357 by the mandatory marker column.

## What this does not do

- No partial, fuzzy or range search over personal fields, and no protection against
  grouping by blind index — inherent to exact matching.
- Existing credential tables stay under `CREDENTIALS_KEY` (P12-T14).
- The blind index is not rotated; rebuilding it is a separate approved operation.
- The rotation registry is empty until a module registers encrypted columns
  ([P13-T07](../tasks/p13-t07.md) owns the first). Rotation was therefore not run
  against a project table — **UNRUN**, stated in #357.
