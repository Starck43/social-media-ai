## What changed

`scripts.setup_test_db` could not seed a schema built by `alembic upgrade head`:
`0155` makes `tenants.plan_holder_user_id` `NOT NULL`, the model metadata keeps it
nullable, and the bootstrap workspace was created without a payer, so the seed
died with `NotNullViolationError` after the guard objects were already applied.
Every isolated P22 schema needed a manual `alter table ... drop not null`, which
the next agent could not see.

- The bootstrap workspace is seeded with a plan holder: the active platform
  administrator, or `bootstrap_plan_holder` with the `admin` platform role when
  the schema has none. `get_or_create_owner` accepts `plan_holder_user_id`.
- The preflight compares column nullability with the metadata for existing tables
  and stays read-only: a live column that accepts NULL where the model forbids it
  is refused by name, and a live `NOT NULL` the model leaves nullable is refused
  unless `KNOWN_STRICT_COLUMNS` records the migration that owns it. Today that is
  exactly `tenants.plan_holder_user_id` → `0155_p2t17_service_plan_finalize`, the
  dormant relaxation `q14_validate_baseline.py` already tolerates (P11-T37);
  measured against `public` at head `0162`, no other column drifts either way.

   from `0156` and cannot restore them; registered as P11-T53 and untouched here.

   modules that create workspaces before a payer exists, so the preflight makes
   the live difference explicit instead.
3. The three `BootstrapOrderTests` failures above are pre-existing debt: they do
   not exercise the guards step at all.
