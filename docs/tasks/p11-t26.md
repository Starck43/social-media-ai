# P11-T26 — Remove legacy model import shims

Registry: [ROADMAP](../../ROADMAP.md#p11). Parent: [P11](../phases/p11-structure.md) (navigation only).

## Scope, evidence and acceptance

**Evidence:** canonical model declarations now live in domain packages, but root-level
single-model modules and older cross-domain package aliases keep duplicate import
paths alive. First-party tests and possibly runtime call sites still consume some
of these shims, obscuring the owning package for a model.

**Change:** migrate first-party imports to each model's canonical domain module,
then remove the redundant root-level model wrappers and legacy aliases in
`analysis.llm_*` and `scheduling.bot_action` / `scheduling.digest_run`. Keep the
intentional `app.models` facade and shared `base.py`, `bootstrap.py`,
`scenario_schema_guard.py`, and `managers/` infrastructure. Update the model
reference to state the resulting import contract. Do not change mapped classes,
manager binding, migrations, schema, or runtime behavior. Removing legacy import
and pickle lookup paths is intentional per the owner's request.

**Acceptance:**
- No first-party production or test import references a removed module path.
- Canonical model definitions and cross-domain ownership are unambiguous; the
  `app.models` facade and its existing class identities remain intact.
- Focused source/import/layout checks pass; no migration or schema changes occur.
- The model reference and PR evidence distinguish the removed legacy paths from
  the retained public facade. Rollback is a revert of the scoped branch changes;
  no DB rollback is needed.

**Dependencies/risk:** [P11-T14](../audit/p11-t14.md) and
[P11-T25](../audit/p11-t25.md) established canonical model imports and the
current layout contracts. Removal intentionally breaks third-party consumers,
old pickles, or data serialized with legacy module paths; no first-party consumer
may remain.
