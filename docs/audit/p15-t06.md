# P15-T06 audit — round 1

PR [#411](https://github.com/Starck43/social-media-ai/pull/411) (`feat/p15-t06-channel-senders`,
head `7c391f40`, base `dev`), transport-only sender package for
[P15-T06](../tasks/p15-t06.md) under D12/D13 and the [P14-T09](p14-t09.md) seam.

Verdict: **not accepted at `7c391f40`**. The structural rules hold — one request per call,
no queue, no migration, no route wired, every destination through the seam, customer
envelope only, default-off with per-bindings admission. What fails is the honesty of the
outcome: four paths report an outcome they cannot know, and one path loses the result
entirely after the message has already left. For a sender, an outcome is the product.

## Blocking findings

### B-1 — a delivered message can return no result at all

`app/channels/senders/bots.py:140` catches `ssl.SSLError, OSError, http.client.HTTPException`.
`getresponse()` also decodes the status line and reason phrase; a non-ASCII or truncated
reply raises `UnicodeDecodeError`, which is a `ValueError`, not an `HTTPException`. The
exception escapes `_send_bot` after the POST has already been written, so the caller gets no
`SendResult` and no receipt, records the attempt as failed, and re-dispatches a message the
provider has already delivered.

### B-2 — a 4xx after DATA is reported as "rejected"

`app/integrations/email/smtp_send.py:145` maps every `SMTPDataError` to
`rejected/smtp_rejected`. `451` and `452` ("try again later") arrive as `SMTPDataError` and
can describe a message already queued. Reporting `rejected` invites a retry and a duplicate.

### B-3 — a TLS failure is reported as a provider rejection

`bots.py:140` and `smtp_send.py:127` classify an `ssl.SSLError` as `rejected` whenever no
body was sent. A certificate mismatch is neither a provider refusal nor proof that nothing
happened — it is the one outcome that should raise a security signal, and it currently
looks like ordinary traffic.

### B-4 — the sender is limited to the mailbox owner

`app/channels/senders/activation.py:27` refuses any actor who is not `owner_user_id`.
D12/D14 treat sending as a *permission registration* (`comms.outbox` presets), so a manager
with rights over a shared team mailbox can never send from it. The card asks for a
capability, not an owner-only pipe. The caller's fresh authority plus the capability should
decide; the adapter should not add a rule the contract does not have.

## Non-blocking

- **N-1** `activation.py:31-39` reads `_KILL`, `_ENABLED` and `_BINDINGS` from the process
  environment. With more than one worker a kill on one process leaves the others sending, and
  binding revocation is equally eventual. Record it in `CHANNELS.md`, and let P15-T05 refuse
  new claims on a database-level revocation independent of env.
- **N-2** `PinnedHTTPSConnection` never calls `set_debuglevel(0)` (`network.py:31-38`), so the
  Telegram token in the request path stays out of logs only by `http.client`'s default.
- **N-3** `network.py:35-37` assigns `self._target` after `super().__init__()`. Harmless today
  because the parent does not connect, fragile the moment it does.
- **N-4** `SendResult.message_id` is set on `unknown` too, and the vocabulary has no
  "may have been delivered" marker. `unknown` is the only signal, and B-1/B-2 weaken it.
- **N-5** the weakest test is `tests/channels/test_p15_t06_senders.py:605`
  (`test_sensitive_inputs_not_in_repr`): it checks three hand-picked strings, so removing
  `repr=False` from `account_login`, `recipient` or `BotRecipient.user_id` keeps it green, and
  it cannot see leakage through exceptions or logs.

## Unconnected local work

While this audit was running, the task worktree gained uncommitted edits to `smtp_send.py`
and the test file (15:36, not in the PR). They add an admission re-check inside `DATA` and
reject non-ASCII app passwords. Both are reasonable, but the re-check raises `blocked` at a
point where `MAIL FROM`/`RCPT TO` have already been disclosed on the wire; that outcome is
`unknown`, not `blocked` (see N-4). Keep the edits, fix the outcome, and push them with the
round-1 fixes rather than leaving them local.
