## Goal

Suggest the best channel to reach a contact and explain why.

## Baseline

- —

**Channel choice is the agent's job here (D26 does not apply):** D26 governs calendars and
task systems — sources of the same capability connected side by side. A contact's channel
is decided by this agent per contact and per moment, from the signals in the plan below;
nothing about it is stored as a "main channel". The one hard constraint stays D15: the
agent may only reorder channels for which consent exists, and it never sends.

## Plan

1. Maintain `contact_channel_stats` (counts, last inbound/outbound, response latency) incrementally on ingest.
2. Deterministic score: manual preference > reachable/consented channels > recent inbound activity > frequency; confidence from score margin and data volume.
3. Optional LLM hint from conversation context (bounded, mocked in tests) that can only reorder already eligible channels.
4. API `GET /api/v1/communication/contacts/{id}/recommend-channel` returning channel, confidence, reasons.
