## Goal

Register `comms.outbox` in the central access catalog with a migration-free permission preset composition after the owner selects the D14 action and role matrix.

## Proposed decision — not approved

The existing D14 text names `VIEW`, `CREATE`, `APPROVE`, and `CONFIGURE`, but the current `ActionType` enum has no `APPROVE`, which would require a schema migration. The migration-free proposal is to use `VIEW`, `UPDATE`, and `CONFIGURE`:

| Role | Proposed actions |
| --- | --- |
| Owner / admin | `VIEW`, `UPDATE`, `CONFIGURE` |
| Manager | `VIEW`, `UPDATE` |
| Analyst / viewer | `VIEW` |

No role receives `CREATE` in this proposal. Do not implement or publish any composition until the owner explicitly approves or corrects it.

## Scope

- `app/core/access_catalog.py`
- A pure permission-policy test for the owner-approved action/role matrix

## Out of scope

- Alembic revisions or other migrations
- Database/bootstrap changes or database access by the executor
- Sender activation, transport behavior, or P15-T05 outbox implementation
- Adding `APPROVE` to `ActionType`

The owner will manually validate the selected presets against `test_schema` before code publication. The executor does not access or modify that schema.

## Acceptance

- Owner's explicit matrix approval is linked here and in the PR body.
- `comms.outbox` is registered in the central catalog with exactly the approved action and role presets.
- A pure policy test covers the approved matrix; no migration or activation change is introduced.
- Owner completes the requested `test_schema` and preset validation before publication.

## Required checks

- Black, isort and diff-check for the owned paths.
