## Finding

target `users.id=2` — the legacy personal-catalog owner of migration
`0109_personal_llm_ownership` (`CATALOG_OWNER_ID = 2`) — for every provider
and model row it inserts. After the P10-T29-compliant `--reset` the suite was

it requires the user to pre-exist and be active (its acceptance ran on an
isolated clone), and the documented create_all + `stamp head` test path never
executes migration data changes — the row only existed as stale local DB
state.

## Fix (`cd5f9596`)

`LEGACY_CATALOG_OWNER_ID = 2` and `_seed_legacy_catalog_owner()`, called last
in `_seed_reference_rows` (after the roles exist): idempotent on the id, the
`user` role (no admin/superuser elevation), `is_active=True` per the 0109
premise, the `synthetic-hash-never-a-credential` placeholder convention and
stable unique username/email. The module docstring and the seeded-rows
summary line name the fixture. No application code, no test file touched,
no assertion weakened; the card's suite-side option was recorded as not
chosen.
