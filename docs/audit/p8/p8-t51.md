# P8-T51 — Widen `job_type` so the bootstrap creates every default task

Verdict: **accepted** 2026-11-18, no correction. Source revision `f1efe064`
(«fix(p8-t51): widen job_type to fit the default task dispatch keys»), integrated
into `dev` by merge `4c15a235`.

## What was reviewed

`DEFAULT_TASKS` carries three keys longer than the old `varchar(20)` —
`comms.outbox.dispatch` (21), `documents.approvals.expire` (26),
`planner.reminders.dispatch` (26) — so `ensure_all_default_tasks()` stopped on the
fifth default task. The candidate widens both `agent_tasks.job_type` and
`jobs.job_type` to `String(64)` in the ORM and adds the matching migration
`migrations/versions/p8t51_job_type_width.py` (`down_revision = p12t15_policy_audit`,
`alter_column` per table with `settings.DB_SCHEMA`), plus a source-only regression
test. No dispatch key was renamed, which is what the accepted
`app/jobs/dispatcher.py` contract requires.

## Review result

- Six files changed, all inside the task's scope: two models, one migration, one
  test, the card and its ROADMAP row. Nothing else in the tree moved.
- Width is sufficient for the longest default key (26 ≤ 64) and both columns match;
  the owner's workspace rows still carry only the four short types, so no stored
  value can be affected by the widen.
- Job types are unchanged: `comms.outbox.dispatch`, `documents.approvals.expire`,
  `planner.reminders.dispatch`, `calendar.sync` are still the exact keys the
  dispatcher matches, and no handler becomes orphaned.
- Migration graph after the merge: single head `p8t51_job_type_width`, parent
  `p12t15_policy_audit`. The placeholder id was kept rather than renumbered; the
  card's handoff allowed exactly that, and the name follows the repository's
  existing `p12t15_policy_audit`-style convention, so the `public` stamp did not
  need a second edit.
- `public` state (read-only): `alembic_version = p8t51_job_type_width`, both
  columns `varchar(64)`, no row longer than 20 yet, which matches the card's claim
  that the migration creates no default tasks by itself. The owner's workspace
  currently holds 4 of the 10 defaults (created 2026-11-18 09:54, before this
  merge), which confirms the original defect was real and that the remaining six
  appear on the next normal startup.
- No residue: the task-owned `p8t51_schema` is gone, no `p8t51_*` schema remains,
  and no synthetic user/tenant/task rows exist in `public` from this work.
