not describe the current tree, and no task can present a green required check.

## Reproduction

```bash
python3 -m venv /tmp/gate && /tmp/gate/bin/python -m pip install --require-hashes -r .ci/requirements.txt
/tmp/gate/bin/python -m scripts.ci.checks
```

`Syntax`, `AST migration graph` and `Baseline inventory` print normally, then the ten
`New secret candidate` lines and exit 1. Reproduced on `dev` `f2fc677b` and `49b98ea3` and on the
P11-T44 branch, always with the same ten hashes.

## Expected change

1. Review each of the ten candidates and decide per candidate: register the reviewed rationale in
   `.ci/secret-baseline.json` (the P11-T38 pattern, one sentence per fingerprint) or remove the value
   from the file. `Basic Auth Credentials`, `Secret Keyword` in test modules and the `Hex High Entropy
   String` in a transcript are the expected outcome — a reviewed exception — but that is a decision to
   record, not to assume.
2. Re-run the gate and show zero secret failures and an unchanged scanner configuration.
3. Do not delete baseline entries for the 381 existing candidates and do not disable filters or
   verification policies; the check must keep failing on genuinely new material.

## Boundaries

Baseline and documentation only. No application code, no test relaxation, no scanner option change,
no secret value may be printed in the card, the commit message or the audit. Rollback: revert the
baseline edit; the gate returns to the current red state.
