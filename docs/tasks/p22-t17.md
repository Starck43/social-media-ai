# P22-T17 — Confirmed task closure, reopening and schedule lifecycle

[Phase](../phases/p22-universal-tasks.md) · [Target architecture](../product/UNIVERSAL_TASKS.md) · [Desktop reference](../product/prototypes/workspace.html)

Build on the accepted [human task](../audit/p22/p22-t01.md), [run admission](../audit/p22/p22-t04.md), [actions](../audit/p22/p22-t05.md) and [interface](../audit/p22/p22-t07.md) contracts. T08 consumes the actions.

- Preview the effects of closing the exact task version, require explicit confirmation and recheck the actor. Atomically record completion and disable future automation triggers. Preserve receipts and report any already admitted run separately. Guard concurrent scheduler admission and repeated confirmation.
- Keep completion of a recurring human occurrence available with its existing successor semantics. Explicit closure of scheduled work must not silently generate another occurrence. State the affected scope before confirmation.
- Reopening restores open work. Show an explicit choice before reactivating a paused schedule. Preserve the manual run action independently of scheduling. Use shared commands across web, CLI and agent tools.
- Accept with open, completed, overdue, recurring and scheduled tasks. Verify close vs scheduler race, stale version, replay, no duplicate successor or trigger, retained history and permission refusal.
