## Review verdict

The proposal identifies real duplication in runtime configuration and accounting
paths, but its target schema does not describe this repository. Existing canonical
tables are `llm_providers`, `llm_models` and `agent_scenarios`; tenant chat settings
remain on `tenants`. There are no separate text/image/social-network table families,
no modality-specific nullable columns named `aspect_ratio`, `top_k` or
`negative_prompt`, and no `ai_providers`, `ai_models`, `agents`, `usage_quotas` or
partitioned `ai_usage_logs`.

Confirmed gaps are: multiple model/temperature/max-token resolution paths;
free-string model evidence alongside FKs; runtime-only fallback; an effective
daily-cost read-then-compare cap; partly unwired dispatch receipts, outcome events
and budget reservations; process-local LLM delay; unwired provider rate-limit
foundation; scattered credential stores; and incomplete evidence that every
untrusted prompt path is framed before tool-capable execution. Existing prompt
framing, bounded agent iterations, encrypted credential responses and Fernet key
rotation must be preserved.

## Implementation order

`P21-T02` defines one internal dispatch seam first. `P21-T03` and `P21-T05` can
then wire admission and provider limits in parallel. `P21-T04` follows admission
for terminal settlement. `P21-T06` requires an owner decision if the accepted
credential/crypto boundary changes. `P21-T07` is an independent audit. `P21-T08`
is last because removing legacy columns or changing public configuration is
irreversible or user-visible.
