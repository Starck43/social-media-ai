# P21-T06 — Credential boundary and rotation hardening

Registry: [ROADMAP](../../ROADMAP.md); parent: [P21](../phases/p21-ai-operations.md).

## Goal

Verify and harden secret custody across LLM providers and social connectors,
including egress safety for user-supplied endpoints, while preserving the accepted
`CREDENTIALS_KEY` / `PII_ENCRYPTION_KEYS` separation (D8) and the existing rotation
tooling.

## Owner gate

Envelope encryption, AES-GCM adoption, key-family changes, table merges or a change
in who may decrypt are accepted crypto-contract changes - ask the owner first.
Otherwise this card limits itself to audit, tests, masking, SSRF hardening and the
existing rotation procedure.

## Corrected facts for this card

- Fernet is authenticated encryption (AES-128-CBC + HMAC-SHA256), not plaintext.
  AES-GCM is not required merely to be "safe", and one GCM nonce is not envelope
  encryption. A real envelope needs a wrapped DEK plus key ID/KMS - owner-gated.
- No incoming provider webhooks exist in the inspected source. Do not implement
  fictitious routes; a per-provider authenticity/replay check is required before
  enqueue only if such a route is separately assigned.

## Steps

1. Inventory every secret-bearing ORM field, serializer and admin projection.
2. Verify owner/tenant authorization before decrypt and redacted error handling;
   normal model metadata never returns secrets, ciphertext, IV, tags or ref
   internals.
3. Managed keys remain deployment allowlisted env/secret-store refs: no arbitrary
   env-name read. BYOK stays in encrypted domain stores, owner-scoped.
4. SSRF hardening for user `base_url`/`custom_endpoint`/`auth_header`: validate
   scheme/host, apply egress policy, deny private, loopback, link-local, IPv6
   special, redirected, DNS-rebinding and cloud metadata targets unless a
   separately approved self-hosted/local path exists - do not forbid accepted local
   deployments that carry an explicit mode.
5. Exercise `scripts/ops/rotate_credentials_key.py` on synthetic records with
   backup, writer stop, wrong/old-key rejection and zero-plaintext-log evidence.
6. Decide (recorded, owner-gated) whether versioned envelope metadata is needed; do
   not add a generic vault table to mimic an external proposal.
7. Add regression checks for API omission, admin masking, rotation failure,
   cross-owner denial and SSRF denials.

## Acceptance

- No public response or error contains ciphertext, plaintext, access/refresh token,
  API key, IV/tag or key material; UI receives only safe config metadata.
- Managed provider secrets stay allowlisted deployment secrets; personal/BYOK
  credentials remain owner-scoped and unreachable from a platform catalog path.
- User-supplied endpoints cannot reach denied targets; approved local deployments
  work only through their explicit mode.
- Synthetic rotation re-encrypts all supported stores, preserves data and rejects
  wrong/old keys per the documented cutover.
- D8 separation and the PII rotation path remain intact; tests synthetic only.
- No `.env*`, real credential or secret value read into evidence.

## Rollback and boundaries

Keep the old key and backup under the operator procedure until verification
completes. Do not delete old ciphertext, rotate production keys, or deploy a new
crypto algorithm from this card.
