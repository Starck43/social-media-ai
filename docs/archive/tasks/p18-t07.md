## Windows integration seam (not enabled)

The native adapter in `local_connector/packaging/windows_fs.py` is complete and
unit-checked against a fake Win32 table, but the connector does not use it
yet: the bootstrap still denies a normal Windows launch, and the POSIX-only
`paths.py`/`index.py` keep their fail-closed guard. Enabling it requires the
native Windows evidence below plus this coordinated change:

- `paths.SelectedRoot`: on `nt`, replace the POSIX `(st_dev, st_ino)` pair with
  `windows_fs.RootIdentity(volume_serial, file_index)`; `stat_device`/
  `stat_inode` already expose the signed 64-bit values SQLite stores exactly.
- `paths.open_selected_file`: on `nt`, serve the bytes from the single verified
  handle of `windows_fs.read_relative_file` instead of a POSIX dirfd walk.
- `paths.iter_files`: on `nt`, use `windows_fs.iter_root_files` with the same
  excluded names/paths, so a sensitive subtree is skipped before it is opened.
- `index.IndexStore`: on `nt`, create and validate the private cache parent
  with `windows_fs.ensure_private_directory` and open the database, its
  `-wal`/`-shm`/`-journal` sidecars and the lock file through
  `windows_fs.PrivateCacheRoot` (`open_file`, `child_path`), which proves the
  owner-only DACL of every object instead of relying on `chmod`.
- `packaging/key_store.py`: on `nt`, install
  `request_private_directory.handler = windows_fs.ensure_private_directory`,
  otherwise the TLS diagnostic refuses to write key material.

This seam touches `local_connector/paths.py` and `local_connector/index.py`,
which are outside this task's proposed paths and belong to the accepted P18-T03
contract, so it needs its own coordinated commit and its own native Windows
evidence.
