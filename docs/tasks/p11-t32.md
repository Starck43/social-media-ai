## Problem

During the P19-T03 acceptance the auditor hit a repeatable collection failure while measuring
coverage that should not depend on the project config:

```
ConstraintColumnNotFoundError: table 'bot_actions' … 'tenant_id'
```

Trace pointed at `tests/conftest.py:62` (`import app.models.managers.base_manager`) through
`app/models/actions/agent_action.py:17`, i.e. the `UniqueConstraint("tenant_id", "idempotency_key")`
of `BotAction` resolving against a table where the mixin's `tenant_id` was not registered. That
shape — a constraint referring to a column of a *second* copy of the class — is the classic
duplicate-module-import symptom, not a data or schema problem. It was worked around by using
`scripts/ci/package_coverage.py` for the acceptance instead.

**Not reproduced on `adf3160a`** with the current venv (python 3.14): both probes passed with
`--cov-config=/dev/null`:

- `pytest tests/tooling/test_p11_t24_schema_guards.py --cov=app --cov-config=/dev/null` — 15 passed
- `pytest tests/knowledge/ --cov=app.services.knowledge --cov-config=/dev/null` — 134 passed

So either the trigger was a specific invocation, venv or branch state, or the defect has since
moved. Registering it because an unexplained, non-reproducible collection abort in the acceptance
path will otherwise be rediscovered by the next auditor and charged to their task.

## Plan

1. Reproduce or close. Try the recorded acceptance invocation shape: a coverage run over a *broad*
   `--cov=app` target with `--cov-config=/dev/null`, plus a second python (the CI one) and a
   `-p no:cacheprovider -o addopts=` variant. If none aborts at content, close this card with the
   failed repro attempts pasted in.
2. If it reproduces: find the double import. Compare `id(Base)`/`id(BotAction)` and
   `sys.modules` keys for `app.models`, `app.models.base` and `app.models.actions.agent_action`
   between the aborting and the passing run; tests/CI may import models before `sys.path` settles
   (worktree root vs installed path, `tests/conftest_plugin` reload, `importlib.reload`).
3. Fix at the source (idempotent model registration or one canonical import path), not by pinning
   the coverage invocation.
4. Prove it with a run that previously aborted, and record the coverage percentage it now produces.
