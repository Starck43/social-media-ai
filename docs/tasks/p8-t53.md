# P8-T53 — Reviewed rotation-head layout for the widened `job_type` head

Registry: [ROADMAP](../../ROADMAP.md#p8); current status/owner/dialogue live there.
Parent: [P8](../phases/p8-first-value-ui.md).
Found while auditing [P8-T52](p8-t52.md): the offline lane on `dev` is red.

## Problem

`tests/tooling/test_p11_t45_rotation_heads.py` requires every Alembic graph head to
have a reviewed credential-rotation layout in
`scripts/ops/rotate_credentials_key.py::GENERATIONS`. P8-T51 merged the head
`p8t51_job_type_width` without adding that entry, so on `dev` the offline lane is
`165 passed, 1 failed` with `{'p8t51_job_type_width'} is not false`. The runtime
operator refuses an unsupported head for the same reason (`len(revisions) != 1 or
revisions[0] not in GENERATIONS`), so a rotation run would stop after this merge.

Nothing is wrong with the migration itself: it only widens two `varchar` columns and
creates no credential store, so its layout is identical to its parent
`p12t15_policy_audit` (`personal_connector_authorizations`,
`telegram_login_attempts`, `telegram_login_request_keys` all present).

## Scope and acceptance

- Add `p8t51_job_type_width` to the reviewed generation tuple in
  `scripts/ops/rotate_credentials_key.py`, sharing the parent's `(True, True, True)`
  layout. No other change: no new generation, no versioned-set edit, no rotation
  logic change.
- Accept when the offline lane is green at the merged revision (`scripts.ci.run_offline`,
  one head) and the formatting gate reports no violation for the changed file.
- No migration, DB access, schema change or credential operation is part of this task.

## Boundaries and rollback

Only the reviewed layout registry and its evidence. Rollback: revert the single entry;
the offline gate returns to red and the rotation operator stops on the new head again.
