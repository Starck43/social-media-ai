# P21-T14 — Provider rate limits and bounded backpressure

Registry: [ROADMAP](../../ROADMAP.md); parent: [P21](../phases/p21-ai-operations.md).

Prerequisites: [P21-T12](../audit/p21/p21-t12.md), [P21-T13](p21-t13.md).

## Goal

Apply one shared, cross-process provider rate budget (RPM/TPM and optional
concurrency) to LLM dispatch with bounded queue/backpressure and Retry-After
honoring, without a second scheduler or serialization system.

## Dependencies and scope

- Depends on P21-T12/P21-T13; specify an admission interface for P21-T15 so denial and provider
  throttling stay different outcomes.
- `provider_rate_budgets` is social-connection/tenant scoped (FK
  `workspace_connections`) and its rows cannot be reused for a shared LLM key.
  Reuse its token-bucket algorithm and `blocked_until`/Retry-After semantics only.
- Add dedicated `llm_rate_buckets` rows justified by a different quota-key scope:
  opaque credential ref + provider quota pool, optionally model family. User and
  workspace fairness are extra buckets, not the upstream pool.
- A credential-version change must NOT reset the upstream pool.
- Tariff tokens are the shared owner allowance in [P2-T17](../audit/p2/p2-t17.md)/P21-T15, not
  upstream TPM. Fairness may distinguish the actual actor/workspace, but the
  governing tariff/payer stays the host owner, including invited members.
- PostgreSQL implementation initially (Redis queue/scheduler stays frozen). DB
  serialization only - no locks held over HTTP. Distributed concurrency leases are
  admission leases, never the financial reservation expiry.

## Required storage contract

Publish a reviewed field/constraint/index mapping before adding `llm_rate_buckets`:
stable opaque pool identity, scope discriminator (upstream/holder/actor/workspace),
scope key, unit (request/token), optional model-family key, nonnegative available
units, refill state, aware update time and `blocked_until`. Uniqueness must handle
the optional family explicitly; NULL must not allow duplicate upstream buckets.
Do not hash plaintext secrets into evidence. Map credential refs that share an
upstream account to the same pool; rotation/version is not part of its identity.

Concurrency leases need a separate named dispatch-bound mutable relation with an
aware expiry and indexed bounded reclaim query. A token bucket alone cannot
recover crashed in-flight slots. No fixed table-count target overrides this need.

## Steps

### Executor sequence and handoff

Require P21-T12 seam and P21-T13 catalog/provider identity; reuse the social rate
manager's algorithm but not its tenant-owned rows. Deliver quota-key/lease DDL,
atomic acquire/release and Retry-After/cancellation behavior, plus a documented
lock order for P21-T15's token/USD UOW. Test limiter acquisition with an admission
double; every real attempt will receive T15's durable receipt before HTTP when
integrated. No live dispatch is enabled here. Load fixtures use mocked providers,
bounded queues and isolated rows; report contention rather than a capacity promise.

1. Define quota-key scope, request/token units, concurrency scope and the
   Retry-After floor; declare each atomic scope explicitly.
2. Wire acquire/release at the P21-T12 seam; pass only validated parameters and record
   a fresh receipt/admission before each attempt.
3. Classify 429, 5xx, timeout, auth, validation, budget, authorization and
   revocation separately; only transient classes may back off.
4. Implement bounded queue (bounded wait, max concurrency, Retry-After echo) and
   cooperative cancellation. Release unused acquisitions and reclaim concurrency
   slots safely; never refund upstream request/token units for a possibly sent
   request. Lease expiry alone must not pretend that an upstream call stopped.
5. Fail closed on limiter/store unavailability or lock timeout; never bypass spend
   or authorization checks.
6. Run a realistic mocked load check at hundreds concurrent (records throughput,
   wait queue, p95, lock waits, DB pool) - report configuration behavior, never a
   claimed capacity figure. Declare `LLM_REQUEST_DELAY` retained or retired from
   measurement.
7. Measure writes to `llm_models.use_count/fail_count`; consider a separate
   optional `llm_model_health` relation only if measured contention warrants it -
   it is not mandatory.

## Acceptance

- Concurrent callers cannot exceed the configured bucket in the tested window;
  Retry-After is a floor, never shortened by refill math.
- Credential rotation increments version without refilling the upstream pool;
  user/workspace fairness buckets are exercised.
- Bounded queue rejects or defers deterministically past its cap, and cancellation
  releases only proven-unused units and safely recoverable slots. Cancelled or
  unknown HTTP work cannot refill quota or release financial/token liability.
- Limiter outage/lock timeout fails closed or follows an explicitly reviewed
  bounded policy; spend/authorization are never silently bypassed.
- No duplicate runtime owner, Redis queue, or unbounded retry is introduced; new
  Redis infrastructure is owner-gated and not implied here.
- Focused multi-process and adapter tests, configuration contract, load-check
  artifacts and rollback switch recorded.

## Rollback and boundaries

Rollback restores the previous limiter/delay policy and fails closed meanwhile; it
does not delete bucket rows or records. No new table without a reviewed quota-key
contract; no health table without measurement.
