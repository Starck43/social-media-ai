## Delivered contract

- `scripts/schema_guards.py` is the single reviewed source of the 26 trigger
  functions and 42 triggers that exist only in migration history (0093–0109).
  Function bodies carry no schema literal: every table and function reference is
  `{s}`, substituted once at render time. `_schema()` quotes the identifier and
  refuses anything that does not match `^[A-Za-z_][A-Za-z0-9_]*$`. Trigger
  definitions keep the migrations' event order and row-level shape.
- `apply_schema_guards(conn, schema, text)` emits
  `CREATE OR REPLACE FUNCTION` plus `DROP TRIGGER IF EXISTS` / `CREATE TRIGGER`,
  so a second run is a no-op. It takes `sqlalchemy.text` from the caller, which
  keeps the module stdlib-only and loadable in the offline CI lane.
- `scripts/setup_test_db.py` applies the guards after `create_all`/stamp and the
  read-only catalog verification, and before `_seed_reference_rows`. A failure
  raises and stops bootstrap instead of leaving a schema that silently accepts
  evidence mutations.
- `tests/tooling/test_p11_t24_schema_guards.py` re-derives the guard inventory
  from the migrations by AST and fails when the module drifts. Registered in
  `.ci/offline-tests.json`.

## Residual work

  retired.
- `test_admin_model_billing_acceptance.py` still hard-codes its approved schema
  list, so any new isolated schema needs that tuple edited. Moving to a
  configuration-driven allowlist is not part of this task.
