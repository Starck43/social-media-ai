## Goal

Let a workspace manager connect a Bitrix24 portal and see an honest connection state.

## Baseline

- Catalog descriptor `BITRIX24` with an incoming-webhook method and icon (P12-T02/T10); `PlatformType.BITRIX24`; no adapter; not in `WORKSPACE_PROVIDERS`.

## Plan

1. Add the Bitrix24 OAuth method (local application: `https://<portal>/oauth/authorize/`, token exchange at `https://oauth.bitrix.info/oauth/token/`); keep the webhook method as an admin-only alternative if D2 says so.
2. Validate the portal domain (`*.bitrix24.ru|.by|.kz|.com|…` cloud domains; on-prem domains only via explicit allowlist); store `portal_domain`, `member_id` and scopes as non-secret config.
3. Implement `app/integrations/bitrix24/client.py`: REST call wrapper (`/rest/<method>`), `batch` support (≤ 50 commands), error mapping (`expired_token`, `QUERY_LIMIT_EXCEEDED`, `ACCESS_DENIED`), rate budget per portal.
4. Health check: `app.info`/`profile` read call; states `verified`, `reauth`, `error`.
5. Add Bitrix24 to `WORKSPACE_PROVIDERS` settings flow with operator instructions in CONNECTOR_CONFIGURATION.
6. API: `POST /api/v1/integrations/bitrix/connect`, `GET …/connections`, `DELETE …/connections/{id}` (adapted IDs = integer connection IDs).
