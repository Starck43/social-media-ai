# P20-T07 — «Сегодня»: read-time attention and decisions home

Registry: [ROADMAP](../../ROADMAP.md#p20); status, owner and dialogue live there. Parent: [P20](../phases/p20-proactive-assistant.md). Design: [WORKSPACE_UX](../WORKSPACE_UX.md). Request and owner decision: https://app.notion.com/chat?t=40fa7457748980d094a100a930619250

## Goal and dependencies

Make «Сегодня» the default landing page that answers *what needs me now*, as a read-time projection over owning modules; allow the user to choose a different start page in settings (O-2). Depends on P20-T06 (accepted, [audit](../audit/p20-t06.md)) for placement. Uses the attention-item contract from [P20-T02](p20-t02.md) and decisions from [P20-T03](p20-t03.md) when they exist; until then it renders only existing signals.

## Scope

- Default to «Сегодня» while letting each user choose the start page in settings. Preserve access to current dashboard sections; decide the route and migration details during implementation, without assuming a separate «Обзор» page was requested.
- First slice from existing data: pending actions, failed/unknown deliveries, connections needing reauthorization, budget limits, follow-ups due, latest results and upcoming runs.
- Section order and empty/unavailable states per [Today page](../WORKSPACE_UX.md#today-page). Each provider is optional, permission-filtered and bounded; one failing provider shows its reason and never blanks the page.
- «Моё / Команда» switch within existing roles. Per-actor dismiss/snooze/seen is the only new state, if any; no copy of module rows, bodies or approval state (D23/D24, D11).
- Later providers (inbox triage, planner, calendar, brief) plug in through their own tasks, not by widening this one.

## Acceptance and checks

- Tests: cross-tenant and permission filtering per provider, provider failure isolation, stale/unavailable markers, empty workspace, bounded queries, and that every action links to its owning route.
- Verify the default and saved start-page selection, permission checks and a safe fallback if a selected page becomes unavailable.
- Record any persistence as a reviewed migration on an isolated test schema; prefer none where possible.

## Open doubts

Implementation of the per-user setting, route and migration requires design; rollback restores the dashboard template and default routing.
