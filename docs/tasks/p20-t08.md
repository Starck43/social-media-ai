# P20-T08 — Chat workspace: context panel, inline cards and chat dock

Registry: [ROADMAP](../../ROADMAP.md#p20); status, owner and dialogue live there. Parent: [P20](../phases/p20-proactive-assistant.md). Design: [WORKSPACE_UX](../WORKSPACE_UX.md). Request: https://app.notion.com/chat?t=40fa7457748980d094a100a930619250

## Goal and dependencies

Make the chat page a clear working surface: context is visible, decisions and results are cards linked to their authorities, and the agent is reachable from every object page. Extends the existing `_chat_workspace.html` panel and the [P12-T06](p12-t06.md) handoff; reuses the one web/Telegram/MAX conversation ([AGENT](../AGENT.md)).

## Scope

- Layout per [chat page](../WORKSPACE_UX.md#chat-page): boundary badge, removable context chips, quick actions, tabbed right panel «Контекст», «Ждут решения», «В работе», «Материалы» (drawer below `lg`).
- Typed inline cards (plan preview, decision, progress, result, draft, brief) rendered from owning services, refreshed on open, linking to the authoritative record. A card never performs an action the owning service has not admitted; decision cards appear only after [P20-T03](p20-t03.md).
- «Спросить агента» dock on object pages opening the same conversation with the object as a context chip; preserve the boundary rules (local-only refused before send).
- Keep the existing task picker behavior and permission gates; extend context types only where a reader with permission checks exists.

## Acceptance and checks

- Tests: context revalidation on every send, chip removal, stale card refresh, denied/changed access, local-only refusal, keyboard/focus/escape for panel and dock, 360px layout, no raw payloads or credentials in cards.
- Bot transports keep receiving plain-text equivalents; no behavior change to Telegram/MAX.
