## Acceptance

A note can be created, dated, assigned, shared, completed or cancelled with no execution profile. A recurring completion creates at most one successor. A watcher cannot acquire private visibility by subscribing. Team filters, counts and pagination never reveal an inaccessible item. Two writers using one revision cannot silently overwrite each other.

Import `task_service` from `app.services.planner.canonical_tasks` with the existing tenant and permission scopes. `create(CreateTask(title=...))` creates a private task. `get(id)`, `list(view="mine" | "team")`, `update`, `reschedule`, `set_participant` and `complete` use canonical IDs. Canonical deletion via the confirmed T05 command and calendar/reminder FK remapping through T06 remain later work.

| Actor with matching workspace grant | Read | Edit content | Share or assign |
| --- | --- | --- | --- |
| Task owner | Own task | Yes | Yes |
| Assignee | Assigned task | Yes | Through owner or team manager authority |
| Collaborator | Shared/workspace task | Yes | Through owner or team manager authority |
| Watcher | Existing visibility | Via independent edit rights | Via independent share rights |
| Workspace owner/admin/manager | Shared/workspace and own access | Same | Shared/workspace and own tasks |
| Other active member | Workspace-visible tasks | Via assignment/collaboration | Own tasks |

Assignments explicitly grant visibility. Watchers never confer it. Range/list filtering applies visibility in SQL before pagination. Occurrence participation is copied to the next eligible generated item with active memberships; private transitions clear participation on the edited item. Read tenancy roles, canonical aggregate/keys, planner contracts/services and the existing planner migration to preserve authority and recurrence.
