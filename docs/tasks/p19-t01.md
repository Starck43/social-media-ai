## Goal

Extend the existing document store to business documents (R-04).

## Baseline

- `knowledge_documents` + `document_revisions` (0122) with content hash, version, status and approval
  invalidation (P12-T03/T11). `0122` also installs `guard_document_revision_content()`, which refuses
  in-place content changes; extending the model means appending revisions, never rewriting a stored
  body (audit F-5 of [P13-T01 accepted](../audit/p13-t01.md)).

## Plan

1. Add to `knowledge_documents`: `document_type` (`letter`, `claim_response`, `contract`, `memo`), tags, contact link, case link, owner, `current_revision_id`; to `document_revisions`: structured content JSON or markdown, author user ID, change description.
2. Status machine `draft → in_review → approved | rejected | revision_requested`. Preserve `draft_invalidated` in storage and translate it at read time to `draft` + invalidation flag (option A; owner instruction [2026-11-07](https://github.com/Starck43/social-media-ai/pull/433#issuecomment-6707574724)). In revision `0142`, widen the check constraint while retaining manager append behavior and translator compatibility; do not rewrite revision history. Downgrade must refuse unsafe data loss if new statuses or other new data cannot be represented.
3. Model `document_templates` (tenant, name, type, content, variables schema).
4. API `/api/v1/documents` CRUD over the extended model; `/app/documents` updates.

## Open doubts

- **Deletion of a linked contact, case evidence or author:** default in draft `a721f995` clears the corresponding link rather than preventing privacy erasure; existing revision content remains unchanged and the author-ID guard permits null only when the referenced user is actually deleted. Confirmation needed because link disappearance is subscriber-visible. Alternative: reject deletion while linked, preserving the link but impeding the existing contact-erasure path. Reversal before integration: revise `0142` and its ORM constraints; after new data exists rollback must first preserve/export it. PostgreSQL trigger behavior and races are unverified and must be tested locally.
- **Case identity:** no persisted case model was found; the draft uses a tenant-scoped `knowledge_snippets` case-evidence reference. The eventual API must verify context type and actor ACL, not merely tenant FK. Confirm that linking case evidence rather than an entire case is acceptable; otherwise defer the case association until an authoritative case store exists.
