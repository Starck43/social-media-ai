## Finding and fix (`cbf74977` + `1f816ce2`)

`refresh_user_token` logged raw exception text on provider failure, and
`_mark_refresh_failed` logged its bookkeeping failure with `exc_info=True`
(traceback) — both could disclose private exception/request/DB context. The
accepted scoped fix (owner-selected bounded logging contract) reuses the
existing `credential_exception_status` classifier: each failure path now emits
only fixed event text, a strict positive-integer `user_id` (otherwise `None`)
and one bounded category. The classifier formats no exception message, args or
traceback (isinstance/MRO checks only; unknown types map to
`error: integration_error`). No other behavior changed: a failed refresh still
records `refresh_failed_at` and returns `None`, bookkeeping stays best-effort,
and rotation/expiry/absence-handling/cancellation semantics are untouched; no
credential-resolution, grant, migration, model or UI change.
`docs/COLLECTION.md#vk-oauth-refresh-log-privacy` documents the bounded
contract with its explicit scope limit.
