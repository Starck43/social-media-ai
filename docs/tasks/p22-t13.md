# P22-T13 — Jira issue adapter and Slack task context

[Phase P22](../phases/p22-universal-tasks.md) · [Design](../product/UNIVERSAL_TASKS.md) · [Queue](../../ROADMAP.md#p22)

**Dependencies.** [P22-T11](p22-t11.md)

**Implementation ownership.** tracker and communication adapter modules, catalog descriptors and shared external-task contract.

## Deliverable

Supply two distinct integration roles. Jira provides authoritative issues and allowed workflow transitions. Slack supplies selected conversation/message context and explicit task creation or issue linking from that context. Reuse scoped installations, grant/reauth flows, source references and existing command admission. Select concrete supported deployment/auth profiles and official operation scopes in the card before adapter work. Keep credentials, attachments and bodies out of local task records.

## Acceptance

A permitted issue is readable in the common Tasks list; a user previews and submits an allowed transition and sees the refreshed provider result. A permitted Slack reference can initiate a local task or link to a Jira issue. Permission loss hides protected content, and equal IDs or display names across sites never merge. No Jira transition or Slack send is enabled from read scope alone.

## Verification at implementation

Use provider contract doubles for paging, restricted channels/projects, retries and version conflicts. Record live-read/write availability separately when an authorized sandbox is available. This extension can ship independently of local task cutover.
