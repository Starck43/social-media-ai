## Deliverable

Deliver the user's read → group by sender → save in Messages journey over at least one implemented mailbox reader and one authorized messenger reader. Resolve exact channel/account permissions and supported windows. Where a selected channel lacks a reader, implement the bounded adapter or return an explicit capability gap and record the unmet acceptance case. Upsert via UnifiedMessage/MessageThread managers. Preserve source threads, verified contact identity, metadata retention and actor-filtered result links.

## Implementation sequence and handoff

1. Trace app/services/communications/ingest.py from a real supported mail reader and messenger reader. Choose the pair by verified ingestion and authorization capabilities.
2. Process a bounded window through existing ingestion. Group first by verified contact and otherwise by account-scoped sender identity. Preserve original threads and attach an authorized Messages view to the run.
3. Give T12 a two-channel example containing equal display names, a verified common contact and a replay. Report source counts and unavailable channels independently.

## Acceptance

Repeating a run produces no duplicate messages. Same display names across accounts never merge identities. A verified contact can group permitted items across channels. Unreachable channels appear as partial coverage; an empty successful read is distinct. No body/attachment copies enter task rows or prompts. User can open a sender group in Messages and reach permitted originals.

## Verification at implementation

Use synthetic multi-account messages, duplicate IDs across channels, ambiguous contacts and revoked access at result-read time. Acceptance requires the two-channel vertical through Tasks and Messages; configuration-only descriptors are insufficient.
