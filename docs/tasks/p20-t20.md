# P20-T20 — Unified Today actions and full-width daily brief

[Registry](../../ROADMAP.md) · [P20](../phases/p20-proactive-assistant.md) · [P20-T16 audit](../audit/p20/p20-t16.md) · [P20-T19](../tasks/p20-t19.md)

Owner-directed execution: changes are made directly on `dev` in the primary checkout,
not on a dedicated task branch/worktree. This is an explicit deviation from the
standard task-branch rule, recorded at the owner's request; no other agent's work
is staged or committed.

## Scope and acceptance

- Combine the former Today sections «Ждут решения» and «Ждут ответа» into one
  `needs_action` section. Each item keeps its authoritative route and gets an
  explicit per-kind button («Решить» or «Ответить») plus the existing chat,
  postpone and remove controls.
- Render the brief as a full-width card built from already authorized Today
  projections: social results for the reporting window, the current plan, the
  combined action queue and attention items. Keep it deterministic and read-only:
  no model call, no persistence and no new permission surface.
- Keep read-only `by_key` aliases for `decisions` and `awaiting_reply` so current
  callers do not break; the rendered page has one combined card.
- Preserve permission filtering, tenant isolation, bounded providers, per-actor
  dismiss/snooze state, CSRF and the shared confirmation dialog.
- Update focused Today unit/browser assertions and verify responsive rendering.
  Record exact checks and limits below before READY.

## Out of scope

- Real LLM generation of the brief text, stored digest records and public
  delivery. Those need a separate product/data-contract decision.
- Chat, Inbox and Tasks surfaces owned by P20-T19.
