## Scope, evidence and acceptance

The accepted contract slice defines the event envelope and safeguards; it did not ship runtime behavior. This owner-authorized follow-up implements the remaining scope: tenant-scoped append-only persistence, transactional success evidence, distinct safe denied/rollback and unknown paths, tenant-filtered read-only support views/export, finite retention enforcement, and the Alembic migration.

Acceptance requires all of the following:

- Successful action admission and its audit row commit or roll back atomically; replay does not duplicate the event.
- Denied/rolled-back attempts and unknown outcomes use separate safe logging categories; unknown outcomes are recorded distinctly when persistence is possible.
- No secrets, raw tool arguments, provider text, arbitrary exception strings, or raw untrusted identifiers enter audit/log output. Logs are not payment or delivery receipts.
- Support read/export is authorized, tenant-first, bounded by time/page limits, and emits only the documented allowlist.
- The audit event is append-only under supported application/database permissions, with retention cleanup tied to the existing workspace plan policy; reuse billing, job and delivery identities rather than creating another ledger.
- Migration is generated and applied/validated only against `test_schema`; no production/public-schema apply or backfill is authorized.
- Required database integration tests, including migration, tenant fencing, rollback, retention, immutability and cleanup, pass against the isolated test schema before READY.

**Dependency/risk:** P11-T04/03; maps to PRD-02/06/08 without claiming those broader gates passed. The accepted contract and its limitations remain documented in [the audit record](../audit/p11-t12.md).
