## Goal

P19-T03 shipped version history, diff and restore behind `web` and `/api/v1` only. The owner's
surface-parity contract asks for one permission-checked service behind several surfaces: `CLI` for
operator, bulk, automation and every recovery operation, and a chat tool wherever an agent can
usefully read, preview or draft. The remote lane named exactly this gap for P19-T03:

> «P19-T03: сделать CLI и проработать безопасный вариант доступа из чата.»

## Baseline

- `app/services/knowledge/versions.py` — history/diff/restore service (100% covered, accepted).
- `app/api/v1/endpoints/documents.py` — the `/api/v1` surface.
- `cli/main.py` — Typer app with namespaced sub-apps (`roles`, `credentials`, `llm`, `chains`, …).
- `app/agent/tools.py` — the chat-tool surface.

## Plan

1. **CLI** — `cli/commands/documents.py`, registered in `cli/main.py`:
   - `documents history <document_id>`, `documents diff <document_id> <from> <to>`,
     `documents restore <document_id> <revision_id> [--dry-run]`.
   - Operator/bulk/recovery semantics only, per the CLI contract in `cli/main.py`; reuse
     `versions.py` unchanged, resolve tenant and actor through the existing CLI helpers
     (`cli/_tenant.py`), never open a raw session.
   - `--dry-run` prints the revision that would be created and changes nothing.
2. **Chat tool** — read and preview only: history and diff return typed data the agent can render;
   a restore request returns a preview plus the owning approval link. No write path from chat; the
   approval stays in the web decision surface as the parity table requires.
3. **Safe access** — both surfaces go through the same permission check as the endpoint; a caller
   without document access in that tenant gets the same refusal as on the web. Add one test per
   surface proving the refusal, not just the happy path.
4. Do not duplicate business logic: if a surface needs a check `versions.py` lacks, add it there and
   cover it once.

## Acceptance

- CLI history/diff/restore work against `test_schema`; restore without `--dry-run` creates a new
  revision and never rewrites history.
- Chat tool returns history/diff and a restore preview that links to the approval surface; it has no
  writing path.
- Cross-tenant and missing-permission calls are refused on **both** surfaces, with a recorded
  command per surface.
- `/api/v1` and web behaviour unchanged: `pytest tests/knowledge/ -q` stays green.
