# P10-T29 — test-schema reset for migration-aligned schemas

**DONE — accepted by the owner 2026-10-26** (owner-authorized direct merge into
dev, no PR). Solution integrated at `3e95acc8`
(fast-forward of `fix/p10-t29-reset-guard-triggers` onto dev). Parent:
[P10](../phases/p10-audit-hardening.md).

## Finding

`python -m scripts.setup_test_db --reset` aborted with
`Budget reservation is immutable` when the redirected test schema carried the
migrations 0093–0100 `BEFORE TRUNCATE` guard triggers (for example
`llm_budget_reservations_no_truncate`): `_truncate_all` issues one
`TRUNCATE` for every base table, and the guards refuse it. Schemas built from
`create_all` alone carry no triggers, so the failure only appeared on schemas
aligned through `alembic upgrade` in a session. Observed during the P8-T37
closeout on 2026-10-26 on the shared local PostgreSQL `test_schema`.

## Fix (`3e95acc8`)

`_truncate_all(schema=None)` — the optional parameter exists for the regression
suite — now finds every user-defined TRUNCATE-firing trigger in the target
schema (`pg_trigger` with `tgtype & 32`, `not tgisinternal`) inside the same
transaction, disables it, issues the `TRUNCATE ... restart identity cascade`,
and re-enables it before the commit. A failure anywhere on the path rolls back
both the disable and the truncate; system triggers and constraints are
untouched, and after the commit the guards are installed as found, so readers
such as `LLMBudgetManager.reserve_receipt`'s `GUARDS` check are unaffected.
