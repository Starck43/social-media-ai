# P22-T18 — Task filters, calendar and rolling run results

[Phase](../phases/p22-universal-tasks.md) · [Target architecture](../product/UNIVERSAL_TASKS.md) · [Desktop reference](../product/prototypes/workspace.html)

Extend the [canonical task interfaces](../audit/p22/p22-t07.md) and [run receipts](../audit/p22/p22-t04.md). T08 and Today consume the authorized queries.

- Apply all active predicates before pagination. Keep Mine/Team scope independent. «Все» clears predicates. Define «Важные» using existing high/critical priority, «Просроченные» from the open task deadline, and commitments from approved proposal provenance supplied by T15. Use workspace-local day boundaries for deadlines and completion. A date-only deadline expires after that day.
- Distinguish deadline, scheduled occurrence and upstream event in calendar results. Include today’s pending occurrences even before a run exists. Personal work completed today belongs on Today even with an older deadline. Use the recorded completion time.
- For the rolling 24-hour view, return authorized run time, source, admitted plan revision/scenario, observed counts, coverage and outcome. Keep failed and partial results visible. Unknown counts stay unknown. A manual run preserves the scheduled occurrence. Use existing provider results where available and expose unavailable execution paths explicitly.
- Accept with overlapping filters across page boundaries, timezone midnight, multiple entries on one day, scenario edits after a run, denied upstream access and a 24-hour window spanning two dates.
