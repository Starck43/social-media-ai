Two distinct causes, so two distinct decisions:

1. **Capability usage without a job.** After the P15-T06 transport work, a
   capability call requires a persisted execution job. Either the bot-action
   tests must create that job (test defect) or the production path has a hole
   (product defect). Determine which **before** editing anything, and say
   which in the PR.
2. **`TelegramClient._collect_mtproto`.** The rate-limit tests double a client
   attribute that no longer exists. This is a test double drifting from the
   library, almost certainly a test-side fix — confirm the library version does
   not expose it under another name.
