## Accepted implementation and consolidated evidence

### Solution

- Added `KnowledgeSnippet`, `KnowledgeDocument`, `DocumentRevision`, explicit
  managers and Alembic `0122` (parent `0121`). No demo/backfill rows are inserted.
- Knowledge/document pages read persisted workspace records, with explicit tenant
  predicates even under operator data bypass. Revision-to-document binding uses a
  composite tenant/document foreign key. PostgreSQL checks the full SHA-256 and
  rejects changes to an existing revision's content; the append manager locks the
  document and serializes revision versions. Appending resets approval on the new
  revision without rewriting historical approval evidence.
- Existing source-resource membership grants are reused: `source.view` is the
  baseline gate; each row's `acl_scope` is a canonical permission key, e.g.
  `collection.source.export`. Unknown legacy scopes are denied, not translated
  into invented rights. Legacy `public` means readable **inside this workspace**,
  after the source-view gate. There is no `user.scopes`, platform-role fallback,
  implicit wildcard, or cross-workspace lookup in interactive reads.
- Boundary destinations: cloud reads only cloud; company reads company/cloud;
  local reads all authorized classes. Unknown boundaries fail closed. Prompt
  assembly separately applies the boundary gate.
- Communication/follow-up/case source evidence is indexed as typed knowledge
  snippets. These read-only catalogs are **not** new outbox, reminder or procurement
  workflows. They no longer present examples as verified/sent/approved records.
  Pure outbox/follow-up/financial/approval functions remain; unused demo pools and
  template record fallbacks were removed. Test examples live in tests only.
- Shared row markup emits every requested `data-evidence-*` field plus compatible
  `data-context-*`. The drawer displays escaped stored metadata, avoids rebinding
  itself on metadata clicks, and reveals its handoff only after a record is selected.
  URLs carry type, persisted ID (revision ID for documents), and actual boundary.
- Chat GET and POST resolve the stored object under current tenant/ACL rights;
  client title/ref/boundary cannot grant access. Cloud turns receive actual stored
  context. A signed session selector survives stripped POST fields and background
  transcript refresh; changing workspace or losing access cannot reuse it.
- **Deliberate fail-closed limit:** the existing runtime has no end-to-end local or
  company execution guarantee. Such evidence can be inspected, but its chat send
  returns 403 **before** `handle_web_message`. The UI no longer falsely promises
  a local model. A normal full GET `/app/chat` explicitly detaches the selection.
  Source ingestion and a local/company LLM route remain outside this task.
- No changes relative to current dev in `app/integrations/catalog/`; accepted
  P12-T10 was inherited unchanged, not edited.
