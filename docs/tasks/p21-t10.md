# P21-T10 — Prompt and tool safety coverage audit

Registry: [ROADMAP](../../ROADMAP.md); parent: [P21](../phases/p21-ai-operations.md).

Prerequisites: none.

## Goal

Produce a source-backed coverage matrix for untrusted social, file, web and user
content entering prompts, especially paths that expose write/publish tools.

## Dependencies and scope

- Independent read-only audit; findings feed P21-T12 and later implementation.
- Inspect `prompt_sanitizer`, `frame_untrusted_text`, prompt builders, agent
  runtime/tool specs, research delegation, drafting, learning and attachment paths.
- Include role separation, delimiters, tool confirmation, tenant/actor recheck,
  max iterations and timeout behavior.
- Include [P2-T17](p2-t17.md)/P21-T12 host-owner sponsorship as a target control:
  prompt/tool input cannot change the plan holder, payer or catalog. Test attempts
  by invited broad-role users to manage the host tariff/models or expose BYOK;
  distinguish current coverage from future migration requirements.

## Steps

### Executor handoff

Start at `app/agent/` tool dispatch and the source callers of `prompt_sanitizer`
and `frame_untrusted_text`, not the helper definitions alone. For each entry point
record trusted/untrusted roles, truncation, allowed tools, confirmation and the
actual execution authorization call. Use synthetic input only; mark missing
current controls as findings, not as implemented P2-T17 behavior. Deliver exact
caller references and a prioritized remediation list to P21-T12. This audit can
finish independently of tariff storage and makes no schema changes.

1. Enumerate every external-text source and prompt entry point.
2. Mark each path as framed, sanitized, role-separated, tool-capable and bounded.
3. Identify gaps where external content can influence a write-capable tool call.
4. Reproduce only with synthetic malicious strings; do not use live provider data.
5. Write prioritized findings with minimal remediation cards or explicit accepted
   residual risk.

## Acceptance

- Matrix covers social posts/comments, web research, files, messages and user
  input, including empty/oversized/malformed content.
- No claim relies on the existence of a sanitizer without a caller-path check.
- Tool-enabled paths prove confirmation plus fresh permission/identity checks and
  bounded iterations/timeouts.
- Findings name exact files/lines, severity, reproduction and rollback; no secrets
  or live external content are included.

## Boundaries

This card does not redesign prompts, add a model, or reopen the accepted P5 phase;
implementation findings become separately scoped tasks.

- Fresh authorization per invocation: `tools.py:150` `_invoke` re-checks
  `has_permission_by_codename(get_current_user())` before the handler; `execute`
  `:176` maps failures to JSON error codes.
- Confirmation: `app/agent/confirmation.py` `make_pending_intent` (authorization v3:

  `refresh_runtime_identity` (`:1042-1046`); tenant daily USD cost cap (`:1047`,

### Findings (prioritized for P21-T12)

**F1 — High. Learned/legacy facts enter the tool-capable system prompt unframed.**
`runtime.py:1311-1319`. Learned fact values are free text (≤500 chars); manual
`memory_set` (`toolset/system.py:36-54`) bypasses that learned-fact contract and
does not request confirmation (R16, a >500-char value reaches the mocked write
through real dispatch). Persisted instructions can steer later tool selection
for the same actor. The memory manager binds personal facts to actor/tenant;
legacy facts are owner-only, so this is not proof of cross-actor memory poisoning.
R12 injects a synthetic stored fact, not an end-to-end successful learning attack.
Current mitigation: fresh tool permissions and confirmation for tools explicitly
declared `confirm=True`; not every durable write is confirm-gated. The RU inbound
gate does not stop the planting text (F4). Reproduction: R12 — real `build_system_prompt` renders a
planted fact value verbatim and unframed; R2/R8 show the gate does not stop RU
planting text. Remediation: frame each fact value with
`frame_untrusted_text` plus a data-not-instructions header. Rollback: revert the
prompt-only commit.

**F2 — High. Tool results are appended to the loop raw.**
`runtime.py:1117-1118`. Only `web_fetch_page` self-marks its body; its title/excerpt,
`web_research` summary/search hits, source names, memory values and document revisions/diffs are unframed, and document content is
user-uploaded text. A poisoned document or name can instruct the model mid-loop.
Reproduction: R13 — the real `_run_tool_loop` appends a poisoned tool result to
the model messages raw (no framing). Remediation: frame all tool results at the single append
choke point (keep the web marker). Rollback: revert.

**F3 — High. `<attached_document>` delimiter breakout.**
`chat_attachments.py:1688-1693` inserts extracted text raw; a file containing
`</attached_document>` closes the block and injects instructions into the user
message of the tool-capable loop; no sanitizer on this path. Reproduction: R4
(closing-delimiter count=2). Remediation: escape the closing delimiter exactly as
`prompt_sanitizer.py:44-45` does, or frame the extracted text. Rollback: revert.

**F4 — Medium. EN-only injection patterns.**
`prompt_sanitizer.py:12-24` and the inbound gate `runtime.py:375`. RU equivalents
and EN paraphrases pass (R2/R8) in a RU-first product. Defense-in-depth only:
framing and confirmation remain the primary controls, and pattern lists are
inherently bypassable. Remediation: add RU patterns, treat the gate as a signal
not a boundary, record residual risk. Rollback: revert.

**F5 — Medium. Custom-template payload/scope variables unframed.**
`prompts.py:89` substitutes without `untrusted=`; `_build_payload_instruction`
`:267-313` renders brands/competitors/hashtags/etc. as plain instruction text
(R6; R15 now calls real `PromptBuilder.get_prompt`, not a mirrored substitution);
`:503-504` interpolates `source_type`/`platform_name` raw; `_with_task_goal`
`:99-112` only json.dumps-quotes the goal. One-shot analyze, no tools; output
contracts bound the result. Remediation: pass `untrusted=` for payload vars on the
custom path or frame the instruction values. Rollback: revert.

**F6 — Low. LLM-suggested base_prompt hardening.**
`scenario_prompt_suggest.py:43` sends the description unframed; raw model output
is returned. The tool returns only a ≤400-char preview
(`toolset/scenarios.py:271`); persistence happens solely via confirm-gated
`scenario_create`/`scenario_update` with argument preview. Reproduction: R14 —
captured suggester messages carry the description unframed. Residual: injected
suggestion becomes one-shot analysis config. Remediation: frame the description;
show the full suggested text at confirmation. Rollback: revert.

**F7 — Low. Stale test double blocks the p11_t09 real-toolset check (dev HEAD).**
`tests/security/test_p11_t09_tool_registration.py:311-330` registers `app.models`
as a plain module without `__path__`; the real chain
`app/agent/toolset/communications.py` → `app/services/communications/inbox.py:25`
imports `app.models.communications.message` → `ModuleNotFoundError` (11/12 pass).
Test-only; no production impact. Remediation: give the stub `__path__` or register
an `app.models.communications` double. Rollback: revert. Separate implementation
task.

**F8 — Low. Stale `app.agent` double blocks the confirmation suite's real-dispatch
cases (dev HEAD).** `tests/chat/test_runtime_confirmation_authorization.py:128`
registers `app.agent` as a plain module without `__path__`; `app/agent/tools.py:17`
imports `app.agent.tool_contracts` → `ModuleNotFoundError` (19/26 pass; 6 errors +
1 fallback-reply failure, all one root cause). Test-only; blocks runtime proof of
the dispatch controls listed above. Remediation: give the stub `__path__` or
register an `app.agent.tool_contracts` double. Rollback: revert.

**F9 — Low. Incomplete reporting double in the output-boundary suite (dev HEAD).**
`tests/ai/test_ai_output_boundaries.py:256` supplies only `ReportAggregator` and
`normalize_digest_axis`; `app/services/digest/builder.py:19` also imports
`ReportScope` → `ImportError` in 28/49 cases (21 pass). Test-only. Remediation:
add `ReportScope` to the double. Rollback: revert.

Systemic note: none of the three bare-python suites (p11_t09, confirmation,
output_boundaries) is listed in `.ci/offline-tests.json`, so CI never runs them
and the double drift went unnoticed; they are not `__source_only__`, so a pytest
run would demand a real test schema. Remediation should repair the doubles and
then register the suites for offline CI.

Remediation order for P21-T12: F3+F1+F2 (tool-loop framing choke points) → F4 →
F5 → F6 → F7+F8+F9 (test-double repairs, then offline-CI registration).
