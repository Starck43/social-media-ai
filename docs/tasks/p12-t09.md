# P12-T09 — Activate the P12 Wave 2 routers and navigation

Status: IN_PROGRESS · owner: opencode · branch `p12-t09-activate-routers`

## Why

P12-T03 (PR #300), P12-T04 (PR #301) and P12-T05 (PR #302) each shipped a
FastAPI router and template, and each PR states "`app/web/nav.py` and
`app/web/__init__.py` remain 100% untouched" as a **Zero-Conflict Rule**. The
consequence was never checked: `/app/knowledge`, `/app/documents`,
`/app/communications`, `/app/followups` and `/app/cases` return 404 in the
running application because no router is included, and the five `NavItem`
entries are `ready=False` with `href="#"`.

Their tests call the page coroutines directly with double-substituted
`app.web.deps` and `app.services.*` modules, so a green suite observed the
handler function, never the application's route table. P12-T05 goes further and
asserts the gap (`assert "cases_router" not in init_text`).

## Scope

- Include the five routers in `app/web/__init__.py`.
- Point the five `NavItem` entries at their real paths and set `ready=True`.
- Replace the two zero-conflict assertions in the P12-T05 test with a contract
  that the routers *are* reachable.
- Add a cross-cutting test that asks the assembled application for each path, so
  a handler that only renders in isolation can never pass again.

## Out of scope

Handler behaviour, services, acl rules, the evidence drawer (`P12-T06`).

## Checks

- New `tests/web/test_p12_routes.py` (application-level reachability).
- `tests/unit_web/test_p12_t0{3,4,5}_*.py`, `tests/web/test_web_ui.py`.
