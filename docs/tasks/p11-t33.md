# P11-T33 — DB tests refuse any schema but the literal `test_schema`

Registry: [ROADMAP](../../ROADMAP.md#priority-p2); current status/owner/dialogue live there.
Parent: [P11](../phases/p11-structure.md)

- **Priority / complexity:** `P2` · `C2`
- **Depends on:** nothing
- **Owner decisions:** none. The safety intent below must survive the change.

## Problem

Local PostgreSQL tests hard-assert the literal schema name before touching data:

```
tests/knowledge/test_p19_t01_db.py:40     assert settings.DB_SCHEMA == "test_schema"
tests/knowledge/test_p19_t03_db.py:33     assert settings.DB_SCHEMA == "test_schema"
tests/knowledge/test_p19_t06_search_db.py:42  assert settings.DB_SCHEMA == "test_schema"
tests/planner/test_p16_t01_db.py:34       assert settings.DB_SCHEMA == "test_schema", "planner integration is test_schema only"
tests/communications/test_p15_t05_db.py:82  assert settings.DB_SCHEMA == "test_schema", …
tests/files/test_p12_t12_migration.py:150,178,197
tests/migrations/test_q16_shared_platforms.py:20
tests/models/test_p11_t13_postgres_boundaries.py:39   (checks `__table__.schema == "test_schema"`)
tests/ai/test_personal_catalog_postgres_acceptance.py:320 / test_llm_cli_catalog_acceptance.py:335
```

The intent is right — these tests write and truncate, so they must never run against the working
schema. The mechanism is wrong: an auditor who builds an isolated probe schema (as P11-T30 did with
`DB_TEST_SCHEMA=p11_t30_probe`) gets a hard stop, so the only way to run DB tests is to share the one
`test_schema` and serialize with every other agent. That is exactly the coupling the isolated-schema
bootstrap exists to remove.

## Plan

1. Add one shared helper, e.g. `tests/support/schema_guard.py`:
   `require_isolated_schema()` refuses to continue when `settings.DB_SCHEMA` equals the schema the
   working database is configured for (derived from settings, not a literal), and returns the
   schema otherwise. Fail closed, and keep a message that names both schemas.
2. Replace each literal assertion with the helper; keep the assertions that check *metadata*
   (`__table__.schema`) consistent with `settings.DB_SCHEMA` instead of the literal.
3. Do not weaken the guard: a run with `DB_SCHEMA=public` must still stop with the same class of
   message. Prove it with a one-line recorded command.
4. Keep the change test-only; no application code, no fixture behaviour change.

## Owned paths
