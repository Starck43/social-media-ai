## Scope and acceptance

Implement the general capability mechanism, not final product packaging. Each
subsystem owns namespaced keys and requirement derivation; generic entitlement
code must not know social sources. Catalog v1 grants `*` without daily quotas to
all three existing plans; unknown capabilities/plans still fail closed. Leave
`Tenant.PLAN_LIMITS` and `effective_limits()` unchanged.

Add nullable workspace plan expiry and durable per-job capability usage via
Alembic. Use the same decision for preview, task admission and job execution,
including legacy sources, already queued jobs and staged-only analysis. Expose
inspection on existing settings/admin, API and CLI; previews in API/CLI/chat show
required keys and denial reasons. Preserve source authorization, personal LLM
payer consent, balances, spend caps, provider scopes and the deployment-wide
`MAX_WORKSPACE_MEMBERS` ceiling as independent restrictions.

Acceptance requires focused policy/surface tests, migration validation,
workspace isolation and concurrent quota/idempotency evidence plus independent
audit. The owner resumed validation on 2026-11-11 and reassigned it on
2026-11-12. A published draft or static syntax checks alone do not satisfy these
criteria. The current source contract is [ENTITLEMENTS](../ENTITLEMENTS.md),
integrated into dev on 2026-10-27 as merge `67acbd53`; see the
[P2 phase plan](../phases/p2-usage-spend.md). The earlier PR source/handoff and
Integrated sections below are historical. The resumed validation record at the
