## Delivered behavior

The platform superuser deletes one workspace through **Удалить с аудитом**,
with an allowlisted reason, retention choice, preview and explicit checkbox
confirmation. A signed 15-minute review binds actor, target/version, policy,
reason and operation UUID. Session CSRF and fresh active SU checks run at
execution. Legacy SQLAdmin CRUD/bulk DELETE is disabled; full non-SU grants do
not confer deletion or platform-journal read/export.

The service locks the workspace and rechecks state, retained audit and protective
financial references. Retained task audit always blocks deletion. Default mode
preserves all audit; explicit expire-elapsed may remove only records already
outside the current plan retention window, bounded to 5000 per operation.
Expiry, deletion and a successful platform receipt share one transaction. Failure
rolls all three back. Same-review retries return the same receipt; competing
reviews serialize and cannot produce duplicate workspace deletion.

`WorkspaceOffboardingEvent` keeps only numeric identities, UTC time, UUID,
allowlisted reason/policy, expired count and success. No subject/actor FK means
it survives their deletion. UPDATE/DELETE/TRUNCATE are guarded; access validates
the enabled trigger definitions and actual function body. Records are retained
indefinitely with no application purge/edit route. HTML/CSV are SU-only and bounded
to 100/1000 records. Existing tenant task-audit rights/allowlists remain unchanged.

Alembic 0119 adds the journal/guards/catalog references. Missing/mismatched guards
fail closed (including metadata-created tables). Normal non-empty downgrade
refuses retained evidence; explicit disposable test-only teardown is guarded to
loopback social_manager/test_schema. Public migration was **not applied**.
