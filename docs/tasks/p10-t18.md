# P10-T18 — repair the workspace-access contracts broken by the authorization split

Registry: [ROADMAP](../../ROADMAP.md#p10); current status/owner live there.

## Scope and acceptance

Repair the seven pre-existing failures in
`tests/web/test_web_settings.py`, `tests/security/test_workspace_member_roles.py`
and `tests/security/test_inactive_workspace_access.py` found during P10-T01/T04
acceptance. Accept: each failure is classified as a stale expectation or a product
defect; product defects are fixed, stale expectations are updated to the current
deliberate contract; the three suites pass and the neighbouring permission,
identity and API suites keep passing; no schema, migration, delivery or
production change. Owner: opencode.

## Context

The failures were reproduced on dev `c1069ef` (baseline `0997534`); they are not
caused by P10-T01/P10-T04 (verified by stashing that branch's wiring during
execution).

- Classification of the seven failures:
  1. `test_unknown_tab_falls_back_to_workspace` — **stale expectation**: the global
     `platforms` tab was added after the exact-set assertion (`3226b40`); it is
     hidden from non-operators by `_visible_tabs`, so the tuple legitimately has
     eight entries.
  2. `test_workspace_models_are_the_tenant_scoped_ones` — **stale expectation**:
     `tenancy.workspace` (`tenant`) became a workspace-scoped resource in
     `eb6cad6`; workspace settings need it. `llmmodel`/`llmprovider`, `platform`,
     `user` and `role` stay outside.
  3–4. `test_member_role_is_the_only_workspace_authority`,
     `test_member_role_can_grant_more_than_the_platform_role_inside_the_workspace`
     — **stale expectation**: the personal LLM catalog (`e14c395`) deliberately
     grants `llmmodel`/`llmprovider` to the acting user for their own rows, never
     through a workspace role or another user's identity. The tests now pin that
     contract instead of the pre-catalog denial.
  5. `test_workspace_owner_gets_workspace_rights_but_platform_admin_does_not_bypass_membership`
     — **product defect**: `permission_scope(is_owner=True, member_grants=...)`
     only substituted the owner preset when `member_grants` was `None`, while its
     docstring says an owner ignores the argument. A caller that passed an empty
     set (defensive default) silently stripped the owner of workspace rights.
  6–7. `test_deactivated_workspace_blocks_web_and_api_access`,
     `test_api_tenant_header_cannot_select_a_deactivated_workspace` — **product
     regression**: `eb6cad6` added an early `/api/v1/users/me` bypass that skips
     `_resolve_tenant`, undoing the fail-closed check introduced by `8e5fd3c`
     ("Refuse web and API access through memberships of deactivated
     workspaces"). `/users/me` now resolves the caller's active memberships and
     the `X-Tenant-Id` header again; `/auth/change-password` stays account-level
     (a password change must remain possible for an account whose workspace was
     suspended).
