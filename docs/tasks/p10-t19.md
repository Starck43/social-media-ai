- `pytest tests/api/test_http_user_response_privacy.py -q`: 47 errors at setup.
  The autouse guard `assert "app.core.database" not in sys.modules` cannot hold
  under the root conftest, which imports the application for every suite;
  `--noconftest` instead fails collection with
  `ModuleNotFoundError: source_import_isolation`, because the helper is only
  importable through the conftest `sys.path` insertion. The suite was authored
  for a standalone harness (P10-T02 evidence) and has not been runnable since
  the `d49c3ed` layout move.
- Two root causes are already known and do not need rediscovery:
  - 45 of the 46 `test_access_policy.py` failures are one parametrized
    assertion, `has_permission(actor, "llmprovider", "configure") is owner`,
    written before the personal LLM catalog made provider configuration a
    self-service capability of the acting user;
  - the 46th, `test_operator_http_identity_loss_fails_closed_even_with_data_bypass`,
    assumes a platform administrator reaches workspace models through the data
    bypass, which the split model deliberately forbids without a membership
    grant. Confirm whether the operator console still has a legitimate
    workspace path before rewriting it: this one may be a real defect rather
    than a stale expectation.
- The remaining suites are unclassified: each failure must be read individually,
  the largest suspects being the permission-scope and self-role-guard cases that
  predate the platform-owner role.
- Also unresolved: `docs/tasks/p10-audit-hardening.md` lists
  `docs/validation/http-user-response-privacy.md` as owned and accepted evidence
  for P10-T02, but the file does not exist on `dev` (removed in `eff1fdb`
  during the P10-T17 docs compaction).
- Not claimed here: suites outside the two paths above and the full test run —
  those need an explicit owner request.
