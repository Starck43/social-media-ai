# Q-19 — Local connector protocol: independent security review and real-provider evidence

Standalone owner-opened question; status/owner: [ROADMAP](../../ROADMAP.md#questions).
Raised at the owner's request while accepting [P18-T01](../audit/p18-t01.md) (2026-11-03).

## Why this exists

`docs/LOCAL_CONNECTOR_PROTOCOL.md` was accepted as the contract P18 implements
against. Acceptance covered the document, not a security verdict, and no line of
it has been exercised by a running system. This question keeps those gaps visible
until a second party closes them, so "accepted" is never mistaken for "verified".

## What is already done

A first-party review by the accepting auditor, against the eight questions that
were published as the review brief. Results are in [the P18-T01 audit](../audit/p18-t01.md#independent-review-of-the-eight-questions).
That review is a reading of the text: it finds the obligations that a later
implementation would have to meet, it cannot show that any of them holds.

## Open items

| # | Item | Closed by |
| --- | --- | --- |
| R-1 | Second-party security review by someone other than the accepting auditor | reviewer reply recorded here and in the P18-T01 audit |
| R-2 | Canonical encoding, signature suite, trust anchors, key lifecycle and replay-ledger bounds are explicitly deferred - they are **not** approved by omission, each needs its own owner decision when P18-T02 reaches them | P18-T02 design note before implementation |
| R-3 | Pairing races, code expiry, key substitution, cross-tenant denial, allowlist and size boundaries, local-only non-egress, live and offline revocation, replay/crash recovery, traversal/symlink races, hostile content and log redaction | P18 implementation test evidence |
| R-4 | No real provider, real certificate authority, real device key store or real file corpus has been exercised | P18-T03/P18-T07 evidence on real platforms |
| R-5 | The `LOCAL_GATEWAY` catalog entry is a descriptor with a certificate-fingerprint field; nothing proves enrollment or certificates exist | P18-T02 implementation |

## Boundary

Nothing here blocks P18 implementation from starting: the protocol is accepted as
the design. It blocks treating the protocol as security-verified, and it must be
resolved before any connector is enabled for a real user.
