# Q-15 — Documentation currentness and behavior consistency audit

Parent: none (standalone cross-cutting documentation audit).

[Active queue](../../ROADMAP.md#p2).

## Scope and acceptance

Audit all tracked Markdown documentation against the current `origin/dev` source
and repository lifecycle rules. Include root guidance, canonical subsystem
contracts, phase plans, active task cards, skill documentation and generated
reference indexes. Find broken local references and statements contradicted by
current code or accepted behavior; make only evidence-backed corrections.

Preserve historical audits as historical evidence. Repair a historical link
only when it is broken or non-portable, retaining its meaning and date. Do not
silently rewrite past test results, product decisions or source observations.
No application behavior, schema, credentials, live providers or production data
are in scope.

Accept with a concise inventory of the checked documentation, each confirmed
drift and its code/source evidence, exact fixes, a complete internal-link check,
applicable documentation lint/checks, and a clean diff. Record unverified or
owner-dependent claims as open rather than guessing.

## Ownership and dependencies

Owner and dialogue live in `ROADMAP.md`. Source baseline is refreshed `origin/dev`.
