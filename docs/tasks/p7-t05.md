# P7-T05 — prepare an isolated staging contour and database recovery path

Registry: [ROADMAP](../../ROADMAP.md#p7); current status/owner live there.

## Scope and acceptance

Prepare repository-level assets for an isolated staging contour that can later
support [P4-T01](p4-t01.md), [P7-T02](p7-t02.md), and the deploy-gated
[P6-T01](p6-t01.md). This task prepares configuration and operator procedures;
it does not provision a host, access production, copy a live database, or run a
migration against a shared/public schema.

- Provide a distinct staging Compose project/configuration, isolated volumes and
  loopback-only host ports, with no implicit reuse of the development `.env`.
- Provide a staging environment example with conspicuous non-secret placeholders
  and documented staging-only key/password generation.
- Provide a protected logical backup path and a guarded staging-only restore path;
  verify the archive before restore, require explicit confirmation before
  replacing staging data, preserve old backups, and never embed credentials or
  production endpoints in scripts.
- Document staging setup, approved/sanitized database-copy workflow, migration and
  rollback boundaries, backup/restore validation, and cleanup. Production data
  remains out of staging until the owner approves the source and sanitization.
- Validate shell/YAML/configuration statically. Runtime Compose, host provisioning,
  database restore, and live deploy evidence remain unrun until Docker/host access
  and an approved database copy are available.
