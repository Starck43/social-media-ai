Registry: [ROADMAP](../../ROADMAP.md); parent: [P21](../phases/p21-ai-operations.md).

## Goal

Own the one normative resolution contract: every actual LLM HTTP attempt passes a
single preflight/dispatch boundary that resolves identity, access, credential,
payer and capacity, reserves durably, re-checks freshness, sends, and records
terminal evidence. Existing adapters, tenant ownership and journal evidence stay.

## Identity and invitation contract

Resolve `actor_user_id`, `tenant_id`, `plan_holder_user_id`, `catalog_id`,
`credential_owner_user_id` (personal only), `funding_class`, trusted payer binding,
delegation/consent version, plan-policy version and credential version separately.
Actor, plan holder, credential owner and payer are not interchangeable.

Per the owner decision in P2-T17, invited members use the workspace owner's
configured models and enabled modules, intersected with their own permissions.
Their own plan/catalog cannot expand host access. Delegated BYOK use needs explicit
owner consent; the seam decrypts internally, never exposes a key to the invitee.
Even an invited administrator cannot manage host tariff, models/providers/keys or
defaults. Legacy task payers stay unchanged until an explicit approved rebind.

## Normative resolution contract

Ordered; each step fails closed and stops before HTTP:

1. Authenticated actor + verified workspace/execution rights. Arbitrary tenant or
   actor IDs supplied in payload/params never authorize. Resolve the workspace's
   verified plan holder; enforce that user's active tariff/module rights (P2-T17).
2. Owner-configured execution model choice (which model/provider this attempt uses).
3. Explicit catalog access + plan grant for that row; access is never inferred from
   a writable model ID. Managed grants use the holder's tariff; personal eligibility
   uses holder ownership plus explicit delegated-use consent, not the actor's row.
4. Credential source per funding class (matrix below).
5. Trusted payer/usage context derived server-side, not from caller input.
6. Validated params (including per-model capability fit), shared owner token
   allowance eligibility (P2-T17/P21-T15) + provider rate capacity (P21-T14).
7. Durable atomic reservation/receipt (P21-T15); fresh authorization + credential
   key-version check immediately before HTTP.
8. Terminal accounting (P21-T16): settle actual, release remainder or retain unknown
   liability.

No DB lock spans HTTP. Reservation and receipt commit before the request; evidence
after it.

## Funding-class matrix

| Class | Catalog | Credential | Payer |
| --- | --- | --- | --- |
| Platform | holder's plan-granted row | deployment allowlisted secret ref only | shared holder allowance + trusted payer binding |
| Personal | holder's own row | encrypted BYOK, owner or explicitly consented delegate | accepted personal payer consent; token-policy applicability per P2-T17 |
| Workspace | future, not activated | not selectable | not activated |

- Owner-sponsored dispatch admits a permission-scoped invitee or worker only with
  fresh delegated-use authority. This remains personal custody, not a workspace
  credential catalog or corporate payer account. An existing consent-bound job
  can continue on the legacy task payer path before its approved migration.
- Preserve explicit legacy personal bindings until a verified migration exists.
  No automatic change to NULL model selection.

## Fallback

- Fallback requires the same credential funding class AND the same trusted payer;
  no silent managed<->BYOK switch.
- Every fallback gets its own dispatch receipt/admission and compatible
  capabilities/params.
- Authorization, budget or revocation denials never trigger fallback.
- A cross-class switch needs separate informed selection/consent and new
  admission - it is not ordinary automatic fallback.

## Acceptance

- Every observed provider attempt enters the seam exactly once, in the stated
  order; missing/ambiguous actor, grant, credential or capacity denial happens
  before HTTP and cannot fall through to another model or payer.
- Row matrix classes are covered or excluded with a reason (tool, image, analysis,
  digest, learning, prompt-suggest, admin probe); fallback carries a new identity.
- Prove owner-pool attribution across spaces, host-policy enforcement for invitees,
  broad-role management denial and queued membership/consent/plan revocation.
- Errors contain no raw provider body, prompt, credential or token; focused tests,
  route matrix and tested SHA recorded - no production activation or migration.

## Rollback and boundaries

Keep adapter compatibility shims until all callers migrate; rollback is a revert of
the seam wiring. No second scheduler, no table rename, no personal-billing or
production-admission enablement here.
