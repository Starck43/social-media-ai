# P21-T04 — LLM settlement, reconciliation and liability closure

Registry: [ROADMAP](../../ROADMAP.md); parent: [P21](../phases/p21-ai-operations.md).

## Goal

Complete terminal accounting after an admitted provider attempt: settle known
outcomes, release unused reservations, retain uncertain liability and make all
transitions idempotent and auditable.

## Dependencies and scope

- Depends on P21-T02 and P21-T03; supplies implementation evidence to P2-T09.
- Reuse immutable receipts/outcome events and existing Decimal USD policy.
- Cover success, provider error, validation failure, timeout, cancellation,
  process loss, missing usage, unknown price and cost-above-ceiling outcomes.
- Do not rewrite old journal rows or use mutable analytics/model counters as the
  authoritative ledger.

## Steps

1. Map every terminal state to receipt/event/reservation transitions.
2. Implement atomic, idempotent settlement and unused-reservation release.
3. Add bounded reconciliation for uncertain commits/outcomes using the same
   event identity; never resend an LLM request as accounting repair.
4. Preserve unresolved liability across UTC-day rollover and cap changes.
5. Add isolated PostgreSQL concurrency, replay, conflict and guard-trigger tests.

## Acceptance

- Every admitted attempt reaches a terminal or explicitly unresolved state.
- Duplicate settlement is a no-op only for exact evidence; conflicting evidence
  is visible and cannot re-price history.
- Unknown/timeout/cancellation liability blocks capped admission until reviewed;
  no TTL is treated as proof of no charge.
- Provider-reported USD cost arbitrates tariff fallback according to the accepted
  three-state policy; no amount is silently rounded to free.
- Receipt/event/reservation guards remain installed after the migration cycle.
- Evidence records tested SHA, DB target, cleanup and all unrun production gates.

## Rollback and boundaries

Use a reversible rollout switch before activation. Preserve receipts and events;
ordinary downgrade or destructive ledger cleanup is outside this card and needs
an owner-approved retention/rollback decision.
