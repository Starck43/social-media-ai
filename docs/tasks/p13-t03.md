## Goal

Give every business adapter one outbound budget per provider account, shared by the API and runtime processes, with honest deferral instead of errors.

## Baseline

- `app/services/social/rate_limit.py`: bounded wait/deferral for social collection reads only.
- API-process request throttling in `app/main.py` (inbound), not outbound provider budgets.

## Plan

1. Define `RateBudget(provider, account_key, rate, burst, window)` registry with defaults: Bitrix24 2 req/s burst 50 per portal; 1C 10 req/min per connection; Google Calendar and CalDAV conservative per-connection defaults; overridable only via code-owned catalog values.
2. Implement a PostgreSQL-backed token bucket (single row per budget, `SELECT … FOR UPDATE` with short transactions) so API and runtime share state; add an in-process fast path only behind the DB check.
3. Expose `async with acquire(budget, cost=1, max_wait=…)`; on exhaustion either wait within `max_wait` or raise `ProviderDeferred(retry_after)`.
4. Parse provider signals (`429`, `Retry-After`, Bitrix24 `QUERY_LIMIT_EXCEEDED`, 1C `503`) into a common `ProviderLimitSignal` that updates the bucket.
5. Retry policy helper: idempotent reads retry with jittered backoff and a bounded budget; writes never retry automatically and surface `unknown` to the caller.
6. Migration for the bucket table (next free revision after rebase); tests with a fake clock and concurrent acquirers on test_schema.
