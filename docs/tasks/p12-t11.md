## Why

Two gaps showed up while reviewing the finished P12 wave, both visible to the owner
in the running application:

1. **The pages show invented records.** `/app/knowledge` renders three hardcoded
   snippets from `CANONICAL_SNIPPETS` in `app/services/knowledge/retrieval.py` plus a
   duplicate fallback list inside `app/web/templates/web/knowledge.html`;
   `/app/documents` does the same with `versioned_documents`. None of it comes from
   the database — there is no knowledge index, no document model and no migration
   behind these pages. Contract-like text ("Рамочный договор … ДП-2026/114", prices,
   legal deadlines) is presented as found material. The "Черновик-шаблон" badge is the
   only signal that it is not real.
2. **The ACL check never ran.** `app/web/knowledge.py` reads `getattr(user, "scopes", None)`,
   but the `User` model has no `scopes` attribute, so the fallback
   `["public", "contracts:read", "procurement:read"]` applies to every user. Every
   snippet is then permitted, and the page reports the ACL check as passed.
3. **The evidence drawer has nothing to open it.** P12-T06 shipped the
   `#context-panel` dialog, `app/static/js/context_panel.js` and the chat handoff
   (`/app/chat?context_type=…&boundary=…`), but the JS listens on
   `[data-evidence-trigger]` / `[data-evidence-ref]` and **no template emits those
   attributes**. "Обсудить в чате с контекстом" in `knowledge.html` links to a bare
   `/app/chat` without parameters, so the handoff contract is never exercised from a
   real row.

## Scope

- **Real data:** persist knowledge snippets and document revisions (models, managers,
  Alembic migration, tenant scoping) and serve the pages from them. Remove
  `CANONICAL_SNIPPETS`, `versioned_documents` and the template fallback lists; the
  demo fixtures may live only in tests.
- **Honest empty state:** with no indexed records the page says so and links to the
  ways to add sources, instead of showing fabricated entries.
- **Real ACL:** derive permitted scopes from the workspace role/permissions the caller
  actually has (reuse the existing grant machinery, do not invent a `user.scopes`).
  `local_only` material must never reach a `cloud`-boundary view or a cloud-bound
  chat call.
- **Evidence triggers:** emit `data-evidence-*` (`title`, `ref`, `hash`, `anchor`,
  `boundary`, `context-type`, `context-id`) from real rows on knowledge, documents,
  communications/follow-ups and cases, so `context_panel.js` opens with true values.
  Replace the bare `/app/chat` link with a real handoff carrying the same context.
- **Cross-workspace isolation** on every read, and the drawer must not reveal rows the
  caller cannot open.

## Out of scope

Connector/settings behaviour (P12-T08), the chat transcript itself, outbox dispatch,
any cloud-drive or mailbox ingestion pipeline beyond what is required to store and
display already-available records.

## Acceptance evidence expected

- Focused tests: ACL per role (including denial), `local_only` vs `cloud` boundary,
  tenant isolation, empty state, and a DOM-level assertion that a rendered row exposes
  `data-evidence-*` and that the handoff URL carries `context_type`/`boundary`.
- An application-level check through the ASGI stack, not only the handler coroutine —
  the P12-T09 lesson.
- Migration validated on the isolated test schema and applied to `public` only with
  separate owner authorization, after a backup.
- No fabricated content reachable from the running app; verify by requesting the pages
  with an empty database.
