## Accepted behavior

- Web task edit/run surfaces omit legacy force controls, discard legacy force values on edit, and enqueue the default skip-by-context policy. API and web payload boundaries do not let a submitted force flag bypass durable receipts.
- Analysis identity is a versioned fingerprint of the resolved scenario/output schema, semantic trigger configuration, and semantic task targets. Receipts are keyed by tenant/workspace, source, content hash, and fingerprint. Lookup errors fail closed; receipts are written only for persisted successful coverage in the analytics transaction.
- Receipts have no expiry, remain after analytics deletion and normal raw cleanup, and are not backfilled from unattributed legacy analytics. Daily rollups and analytics uniqueness include the fingerprint. Raw cleanup preserves rows needed by other active contexts in their date window; a new context introduced after cleanup must recollect.
- Existing web source-job admission serializes overlapping source runs. Concurrent direct CLI runs are not globally serialized by this feature; this remains an explicit limitation.
- Both individual-analysis and whole-chain delete routes call `guard_web`, and their forms use the same workspace permission check.

## Audit resolution

The recorded blocker was not a production permission bypass. The test compared a workspace owner’s missing **platform-role** `aianalytics.delete` right with workspace access, while the fixed `owner` workspace-role preset grants every registered workspace action, including analytics deletion. The shared access catalog and workspace-role tests define that behavior. The regression now verifies that an owner can delete through the workspace grant even without the platform-role permission; a viewer has neither delete form and crafted POSTs to both routes are refused. Production guards were reviewed and did not need changing.

The receipt-only handler test also called `handle_analyze` without the persisted execution job now required by entitlement admission, so it failed before receipt logic ran. Its test now stubs that separate admission boundary and exercises the intended no-action-replay behavior. No production source was changed in this closeout.
