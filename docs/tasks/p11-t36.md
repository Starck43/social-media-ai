# P11-T36 — `schema_inventory.py` accepts the application DSN

[ROADMAP](../../ROADMAP.md) · [Parent P11](../phases/p11-structure.md)

## Scope

`scripts/ci/schema_inventory.py` read `os.environ` only and passed
`postgresql+asyncpg://…` straight to psycopg2. psycopg2 rejects the SQLAlchemy
driver suffix as an invalid DSN, and the failure reads like "you must supply a
password", which invites passing database credentials around to run a read-only
layout snapshot. This environment authenticates through libpq, so no secret is
needed.

Owned paths: `scripts/ci/schema_inventory.py`,
`tests/tooling/test_p11_t36_schema_inventory_dsn.py`, this card, `ROADMAP.md`.

## Acceptance and checks

- The DSN's driver suffix is stripped before connecting; credentials and query
  strings survive.
- `.env` is read from the working directory as well as the script location, so a
  plain invocation works from the main checkout.
- The failure message names the fix and states that a password is not required.
- Unit test for the normaliser (no DB). Live snapshot proven once against
  `test_schema`.

## Decisions and rollback

Revert the commit; the script has no runtime consumers. `snapshot()` keeps its
signature, so the in-test caller in `tests/integrations/test_p12_t08_*` is
unaffected.
