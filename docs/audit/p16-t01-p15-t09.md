## P16-T01

The executor delivered the branch as a git bundle (base64 in PR comment
6659814726) because its environment has no git credentials; the auditor
reconstructed `bd482023`, then published it with a scoped
`--force-with-lease` after one acceptance fix.

**Acceptance fix `781010bf`.** A task created without a description stores
`NULL`, while `TaskOut.description` is a string field inherited from
`TaskCreate`, so `_projection()` raised `ValidationError` on every
`create`/`get`/`list`; five of six DB scenarios failed on exactly that.
`_projection()` now returns `""`, an empty description is stored as `NULL`
rather than a ciphertext of nothing, and `description_encrypted` is nullable in
the model and in `0140`. The scenario that asserted all three encrypted columns
carry ciphertext now asserts the empty description is `NULL`; the code was not
bent to the test.

## P15-T09

Executor is Codex; the owner approved the matrix in PR #417. The auditor
answered the scoped question on PR #421 (comment 6660060082): **PASS on both
counts**.

- Presets: owner `VIEW UPDATE CONFIGURE`, admin the same, manager `VIEW UPDATE`, analyst `VIEW`, viewer `VIEW`. The resource declares `VIEW UPDATE CONFIGURE` with no `CREATE`/`DELETE`.
- `UPDATE` does not grant `APPROVE`: `approve` is not among the resource's actions, so `has_permission`, the codename lookup and `member_decision` all fail closed.

**Merge and the catalog baseline.** After `dev` carried P16-T01, the branch's
frozen post-0096 expectation no longer matched the runtime catalog, and
`test_migration_catalog_and_presets_match_runtime_without_database` failed with
`planner_tasks` missing from the baseline. The merge resolved the viewer preset
to keep both `comms.outbox` and `planner.task`, and the test now declares the
`0140` planner resource and its role matrix exactly as the migration grants it
(owner/admin/manager view+create+update+delete, analyst view+create+update,
viewer view). The test was not loosened: it still compares complete sets.

- `pytest tests/security/test_access_policy.py -q` → 80 passed.
- `pytest tests/security/test_access_policy.py tests/planner/ -q` → 187 passed.

**Schema state.** `test_schema` is at `0140`/`0141`-era catalog but has no
migration that registers `comms.outbox` (P15-T09 is catalog-only). The auditor
inserted the single `comms.outbox` model type and its three permissions into
`test_schema` so the suite's read-only reference check can pass; this is the
accepted gap the card names — the storage task (P15-T05) carries the migration.

**Recorded design gap, not this task's scope.** `ActionType` has no `APPROVE`
value, and the existing decision endpoint (`app/web/actions.py`) gates approval
on `VIEW + UPDATE` of the agent-action resource. When the outbox gains storage
and the D14 approval flow (P15-T05), approval must be gated on `CONFIGURE`
explicitly rather than inherited from `UPDATE`.
