## Findings

1. **Blocker — the pinned transport violates the HTTP/1.1 framing rules it
   relies on (`yandex_http.py`, `_exchange`).** §4.4/§3.3.2 require the
   connection to be closed after `Transfer-Encoding: chunked` and, when
   `Content-Length` and `Transfer-Encoding` are both absent, to read until close.
   The loop ends only on `h11.EndOfMessage`; a chunked response needs an EOF the
   client never sends, so it waits for the 15 s deadline and the caller receives
   `provider_unavailable`. Fix: advertise `Connection: close`, and on `Response`
   either close the writer immediately for `chunked` or satisfy the message with
   `protocol.send(h11.ConnectionClosed())` after requesting close — then the
   `EndOfMessage` arrives; keep the cursor for an unframed body. Not observable
   today only because the fixed endpoint answers with `Content-Length`.

2. **High — non-200 responses are returned without being consumed
   (`yandex_http.py`, `_exchange`).** `return _Response(status, b"")` at the
   `h11.Response` event skips the body, so a `401/403/429` with a body never
   reaches `EndOfMessage`; the caller then closes a mid-message connection. That
   happens to work here (close is unconditional) but it is incorrect framing and
   the error-path claim "bounded, single-use exchange" is not true for that path.

3. **High — the selector round-trip test is load-bearing on a 1/64 lease and
   already fails in some orders.** `tests/unit_services/test_p8_t34_file_reference.py::test_tamper_and_other_cipher_purpose_do_not_validate`
   flips the third character from the end, which is padding bits for ~1 in 64
   random keys (the last base64 character of a 292-character Fernet token carries
   padding, so 16 of its 64 values re-decode to the same bytes). Reproduced: 3 of
   12 consecutive runs of the five selector/transport files fail with
   `DID NOT RAISE`, and the file alone fails deterministically under
   `--noconftest` with the shared key. The selector itself is intact (version+timestamp
   are authenticated by the HMAC), but the test is nondeterministic and a green
   run cannot be claimed for it. Fix: mutate an authenticated ciphertext byte and
   assert rejection, and key the fixture deterministically.

4. **Medium — the transport deadline is not what the card describes.**
   `YandexMetadataClient.TOTAL_TIMEOUT = 15 s` restarts inside the client, while
   `list_owned_folder` wraps the call in its own 15 s `asyncio.timeout`, so the
   outer service deadline governs (an inner wait may be cancelled by the outer
   one after it has been running, not from the client's start). More
   importantly, the client discards the caller's `timeout` and cannot honour
   `list_folder`'s `httpx.Timeout(10.0)`; the effective budget is the outer
   15 s. Either drop the dead inner constant or align both and document the
   single budget.

5. **Medium — the disable path has unrecorded latency.** `list_owned_folder`
   holds a shared lock on the actor/membership and an **exclusive** lock on the
   connection for the whole bounded network read (up to 15 s). Any other
   operation on that connection (disable, re-save) waits for the full timeout.
   That is a deliberate revocation serialization per the card, but the user
   action "disable" has no UI hint about the wait and the route returns 503 with
   a generic browse error; the card should record the accepted latency instead of
   implying a normal-time disable.

6. **Low — provider failures render as a full folder page under 503.** The
   `MetadataError` branch renders `web/yandex_file_browser.html` with
   `status_code=503`, so a provider outage replaces the listing with the browser
   template carrying only the alert and no navigation; refused input already uses
   distinct 400/403 text responses. Consistency nit: keep 503 for provider
   unavailability but render a minimal error state rather than the browser shell.

7. **Low — the selector binds `session_id` but not the browse request**, and a
   replayed selector remains valid for the full 300 s even after the user
   navigates away or the connection is re-rooted: only a changed policy root
   invalidates it (tested, `test_reference_denied_when_root_changes`). Because no
   UI consumes selectors yet, this is a forward risk, not an exploit.

8. **Low — generated dependency lock is stale.** `requirements.txt`,
   `requirements/constraints.txt` and every `requirements/*.txt` export predate
   the two new direct pins in `pyproject.toml` (`certifi==2026.10.23`,
   `h11==0.16.0`); `python scripts/packaging/dependencies.py check` returns
   `Canonical declarations changed; regenerate constraints/exports` on this head
   but PASSes on `origin/dev`. `requirements.txt` contains the pins only because
   it was generated for a later state, so the exact CI check fails. Regenerate and
   commit the profile exports with the `h11`/`certifi` pins; `.ci/` has no h11
   pin, but the runtime profile authors it.

9. **Low — the card's test totals do not match this head.** The card lists "172
   address tests" for the first review and "195" for the last slice. On this head
   I can account for `128` selector/transport tests (or `127+1` per finding 3) and
   `36` integration/setup tests, and no run reproduces either total. The card
   must record exact commands and numbers, not a moving total; see the checks
   section below.
