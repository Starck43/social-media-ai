# P8-T44 — Photo and document attachments in the shared chat

Registry: [ROADMAP](../../ROADMAP.md). Parent: [P8](../phases/p8-first-value-ui.md).
Dialogue: `codex resume 01a18973-e01e-7861-b0a0-143e9678824f`.
Status: `IN_PROGRESS` · Owner: `ai-studio-p8-t44` · Branch: `feat/p8-t44-chat-attachments` · Base: `748bc6b6` (`origin/dev`).

## Scope and microplan

- Inventory existing inbound messages, model capabilities, storage and usage
  accounting before choosing an attachment representation. Coordinate P8-T43
  media-reference work; social post media links are not uploaded chat files.
- Define supported image/document types and bounded per-file, total and page
  limits. Validate actual content, reject unsupported/encrypted/malformed files
  explicitly, and state what was extracted or omitted.
- Introduce a shared attachment contract for web chat and the agent turn, with
  explicit current tenant/actor authorization on upload, read and deletion.
  Preserve payer/model capability checks, usage evidence and confirmation gates.
- Design private storage, retention, deletion and cleanup after cancellation or
  failed sends. Do not expose filesystem paths, provider keys or public file URLs.
  Any schema change follows Alembic and database policy.
- Wire the paperclip to selection, removable attachment previews and progress,
  preserving drafts, retries and a clear distinction between selected, uploaded
  and processed content. Make photo/document capability limits visible.
- Delegate focused tests for MIME/content/size boundaries, unsupported models,
  cross-tenant access, cancellation/failure cleanup and Safari interactions.
  Mock paid providers and external writes; run required shared chat checks.

## Acceptance

A supported file can be attached, removed, sent and processed by a compatible
model with honest UI status and usage evidence. Unsupported content fails safely.
Attachment bytes and extracted content remain private to the authorized workspace,
with documented cleanup/retention. Text-only chat and confirmations remain intact.
No upload support is claimed by P8-T42's availability dialog.
