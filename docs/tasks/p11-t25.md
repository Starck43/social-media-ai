## Scope, evidence and acceptance

**Evidence:** on `dev` at `367f7ed2`, `tests/collection/test_collection_model_layout.py`
reports 5 failures and `tests/security/test_tenancy_model_layout.py` reports 5, and the
identical 10 also fail on a clean `origin/dev` checkout with no local edits.

- `CollectedItem.as_agent_item` reads `self.content_type`, added to the model together
  with the typed collected identity (`8c80d458`), but the layout-test rows are built as
  `SimpleNamespace` objects that never gained the field.
- `test_existing_declarative_schema_expressions_are_unchanged[Tenant]` compares a
  recorded fingerprint against the current `Tenant` class; the recorded value and the
  file disagree. The test computes the fingerprint identically under CPython 3.12 and
  3.14, so the interpreter is not the cause.

Neither file is in the offline CI manifest, so hosted required checks stay green while
the behaviour they guard is unverified.

**Change:** decide per failure what is authoritative — the model or the fixture — and
make them agree, or move a genuinely obsolete assertion to its owning task. Where the
row builder drifted, prefer constructing model instances over adding fields to an ad-hoc
namespace. Update the recorded fingerprint only with the model change it certifies, in
the same commit as that change.

**Acceptance:** both files pass from a cold checkout; each fingerprint change lists the
model change it records; the decision for every failure is written in the task card,
including any assertion deliberately dropped and the task that replaces it.

**Dependency/risk:** do not loosen assertions to make the files green. If a failure
reveals a real model regression rather than fixture drift, that is a separate correctness
finding and must be filed before closing this task.
