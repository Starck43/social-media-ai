### Architectural Decisions
1. **Extend `Platform` (`platforms`), Do NOT Rename:**
   - Keep `Platform` (`app/models/collection/platform.py`) as the global catalog of external systems (`Q-16`).
   - In `app/types/enums/platform_types.py`, extend `PlatformType` (using the 3-tuple `(db_value, display_name, emoji)` format) with:
     - `EMAIL = ("email", "Почта IMAP/SMTP", "✉️")`
     - `BITRIX24 = ("bitrix24", "Битрикс24 CRM", "🏢")`
     - `ONEC = ("onec", "1С:Предприятие OData", "📊")`
     - `YANDEX_DISK = ("yandex_disk", "Яндекс.Диск", "☁️")`
     - `MAILRU_CLOUD = ("mailru_cloud", "Облако Mail.ru", "🌩️")`
     - `LOCAL_GATEWAY = ("local_gateway", "Локальный шлюз", "🖧")`
   - In the same file (`app/types/enums/platform_types.py`), extend `SourceType` with:
     - `DRIVE_FOLDER = ("drive_folder", "Папка облачного диска", "📁")`
   - Extend `_BOOTSTRAP` in `app/services/social/platform_config.py` with canonical non-secret defaults (`api_base_url`, `auth_type`, `category`, `capabilities`, `write_capabilities`) for all 6 new platform types.
2. **Per-User, Per-Workspace Credentials (`UserCredential.meta`):**
   - Store workspace scoping (`"tenant_id": tenant_id`) and non-secret connection parameters (`portal_url`, `odata_url`, `imap_host`, `account_login`, `data_boundary`) inside `UserCredential.meta` (JSON) so each user configures connectors isolated to their active workspace without requiring a destructive public-schema migration.
3. **Cloud Drive & Document Connection Flow (`SourceType.DRIVE_FOLDER`):**
   - Provide a helper in `app/services/social/connections.py` to build/validate mounted folder descriptors (`SourceType.DRIVE_FOLDER`, `external_id="disk:/Договоры 2026"`, `params={"credential_id": ..., "allowed_extensions": [".pdf", ".docx", ".xlsx"]}`) and return `workspace_connectors: list[dict]` for `/app/settings?tab=connections`.
