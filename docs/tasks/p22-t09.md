# P22-T09 — Admin connector setup and task operations

[Phase P22](../phases/p22-universal-tasks.md) · [Design](../product/UNIVERSAL_TASKS.md) · [Queue](../../ROADMAP.md#p22)

**Dependencies.** [P22-T02](p22-t02.md), [P22-T05](p22-t05.md), [P22-T07](p22-t07.md)

**Implementation ownership.** app/admin/, existing operator settings and redacted task/run diagnostics.

## Deliverable

Give an operator a single catalog-driven setup view per installed service with field ownership, missing configuration, supported methods, activation and rotation instructions. Reuse existing secure deployment configuration for shared VK app and bot tokens. Expose workspace grants only within scope. Show task state, pinned plan, run evidence and pending action references with redaction. All mutating admin operations go through the same command service.

## Acceptance

An operator configures permitted non-secret settings once, sees shared credential presence and diagnoses which layer is missing for two separate accounts. Secret values and replayable tokens never render. Generic model CRUD cannot bypass preview, permissions or confirmed deletion. A Platform deactivation cannot cascade-delete sources through this interface.

## Verification at implementation

Review scoped admin roles, allowlisted response fields, safe updates and audit logging with masked examples. Keep legacy admin readers available until canonical parity is shown.
