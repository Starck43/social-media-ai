# P21-T16 — LLM settlement, reconciliation and liability closure

Registry: [ROADMAP](../../ROADMAP.md); parent: [P21](../phases/p21-ai-operations.md).

Prerequisites: [P21-T15](p21-t15.md).

## Goal

Close each admitted attempt: settle known outcomes against the T03 reservation,
release only the proven-unused remainder, keep unknown possible charges as
liability, and detect/reconcile orphan state boundedly - all idempotent and
auditable.

## Dependencies and scope

- Depends on P21-T15; supplies evidence to P2-T09.
- Reuse immutable receipts, reservation and outcome events and the existing Decimal
  USD policy and price/cache snapshots; do not rewrite journal rows or use mutable
  analytics/model counters as the ledger.
- [P2-T17](../audit/p2/p2-t17.md) supplies allowance definitions;
  [P2](../phases/p2-usage-spend.md#remaining-allowance-activation-gates) retains
  unresolved periods/counting gates. P21-T15 supplies owner-scoped
  token reservations. Settle token usage and USD liability separately against the
  admission snapshot, attributed to its original holder/workspace/actor.
- Receipts are preparation evidence protected against UPDATE/DELETE; they have no
  terminal status or lease column. Reuse `personal_llm_reservation_states` for the
  personal USD path. Define any missing tenant USD state and token settlement/
  reconciliation state from P21-T15; do not weaken immutable guards or invent a second
  ledger for the same unit and payer.
- Owns the reconciler's bounded batch/time/retry policy, run under the EXISTING
  `app.runtime` owner (no second scheduler). Operator signals use the existing
  logging/notification seam - no new webhooks or senders.

## Steps

### Executor sequence and integrated gate

Require P21-T15's tested reservation/UOW/state contract; do not redesign its units
or payer identity. Implement atomic settlement and a bounded reconciler inside
the existing runtime, then connect the P21-T12 terminal interface. Extend personal
USD state without rewriting immutable history and consume the delivered token/
tenant state schema. Add crash points before/after request and commit, exact replay,
conflicting evidence and queued owner-policy revocation tests. Finally run the
phase's integrated mocked route matrix against the real T11–T15 components.
Record unresolved liabilities and explicitly unrun activation/live-provider gates;
a mocked phase pass never authorizes production activation or public apply.

1. Map every terminal state (success, provider error, validation failure, timeout,
   cancellation, process loss, missing usage, unknown price, above-ceiling) to
   receipt/event/reservation transitions.
2. Implement atomic idempotent settlement (reserved -> actual, release remainder)
   and the retain-liability transition.
3. Detect orphan state after a crash in bounded time: a dispatch with a non-terminal
   mutable execution/reservation state and expired aware `lease_until` is picked
   up on a bounded scheduled pass. Name its indexed state/lease query; the receipt
   itself is never updated to terminal or leased.
4. Reconcile the SAME dispatch/event identity; never resend the model request as
   accounting repair. An expired lease/expiry is observation only - it proves
   neither a refund nor that no request was dispatched.
5. Preserve unresolved liability across UTC-day rollover, cap changes and restart;
   reconcile it later from provider/usage evidence when available. Token rollover
   uses the P2-T17 period policy, not an assumed daily reset; plan changes and new
   spaces cannot release or transfer old usage. Unknown usage retains the token
   reservation until evidence proves a release is safe.
6. Add isolated PostgreSQL concurrency, replay, conflict, rollover, unknown-price
   and guard-trigger tests.

## Acceptance

- Every admitted attempt reaches terminal or explicitly unresolved state.
- Duplicate settlement is a no-op only for exact evidence; conflicting evidence is
  visible and cannot re-price history.
- Unknown/timeout/cancellation liability keeps the possible charge reserved until
  reconciled; no TTL is treated as proof of no charge.
- Token settlement and USD settlement are separately idempotent and jointly
  recoverable after a crash; duplicate fallback/observation events never recount
  usage. Invitee activity stays attributed to the sponsoring holder pool.
- An accepted explicit UNDEFINED-price policy is not blocked wholesale: the
  documented FREE/PRICED/UNDEFINED contract governs admission, and reconciliation
  records the unresolved amount instead of forcing free.
- Provider-reported USD cost arbitrates tariff fallback per the accepted policy;
  nothing is silently rounded to free.
- Reconciler has bounded batch/time/retry, idempotent state, and runs inside
  `app.runtime`; cache/price snapshots are preserved and tested through rollover and
  unknown cases.
- Guard triggers remain installed after the migration cycle; evidence records tested
  SHA, DB target, cleanup, unrun production gates.

## Rollback and boundaries

A reversible rollout switch freezes new admitted work before activation. Rollback
preserves receipts/events and never releases unknown liabilities merely by
disabling a flag; destructive ledger cleanup needs owner-approved retention.
