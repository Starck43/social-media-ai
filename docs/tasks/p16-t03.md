## Goal

Mirror events from a selected Google calendar and push planner tasks as events, with explicit conflict handling.

## Baseline

- —

**Source authority (D24, [Q-21](../audit/q-21-source-authority.md)):** the calendar owns event times,
recurrence, attendees and which calendar an event belongs to. We keep the link, the
per-connection consent (D4) and the per-event audit; we never re-compute the calendar's
schedule or serve it from a local copy when the provider answers.

**Orchestration (D25, [Q-21](../audit/q-21-source-authority.md)):** `calendar_events` keeps what we
decided about the object (origin, planner link, sync state, conflict record), while the
`(connection_id, external_id)` identity is held by the shared source registry. Adding a
second calendar provider must not change the event model or repeat its conflict rules.

**Overlap and choice (D26, [Q-21](../audit/q-21-source-authority.md)):** when a second calendar
provider is connected, the product asks which one to use and states what is currently
used; the answer is recorded as our decision. It never switches silently, never picks
by connection order, and does not fall back to another provider because the chosen one
went offline.

**No premature registry (D25 sequencing):** build the connection-scoped identity this card
already specifies (`(tenant_id, connection_id, external_id)`) and do **not** generalise it
into a shared source registry. That table arrives with [P16-T04](p16-t04.md), the first
second-consumer, and moves this key rather than duplicating it.

## Plan

1. Google OAuth method (scopes `calendar.events`, read-only option), calendar selection per connection.
2. Model `calendar_events` (tenant, connection, external ID, etag, title/description/location encrypted where personal, start/end with timezone, all-day, origin `local|external`, planner task link, sync state); unique `(tenant_id, connection_id, external_id)`.
3. Incremental pull every 5 min using `syncToken` (410 → full resync); optional push channels later (R-14).
4. Push: task → event via `calendar.google.event_write.v1` with `If-Match` etag; approval per D4.
5. Conflict resolution: both sides changed since last sync → conflict record with both versions; user chooses; no silent last-writer-wins.
6. API `/api/v1/calendar/connect/google`, `/connections`, `/sync`, `/events`.
