## Context: why the migration needed an owner decision

Requested: apply the P12-T08 migration to the working `public` schema. It cannot be
done as a single-step, non-destructive operation:

- `public` is at **0119**; the migration the task adds is **0121** (parent 0120).
- Reaching 0121 therefore runs **0120 as well**, which rewrites the shared
  `platforms` table (merges rows, rewrites `sources.platform_id`, adds a unique
  constraint and writes a rollback snapshot into `platforms.params`).
- The task card states *"No production migration or live mailbox access was
  authorized"* and *"No public/work schema was changed"*; the 0121 review in that card
  covers an isolated `test_schema` at 0120, not a two-revision jump over real rows.

Current `public` state observed (read-only): revision 0119; 2 tenants, 2 users,
17 sources (15 VK, 2 Telegram) referencing platform ids 1 and 2; `platforms` holds
exactly the canonical VK/Telegram rows, so 0120 would merge nothing and rewrite no
`platform_id`, but it would still materialize `api_base_url`/`api_version` into every
platform row and store the archive snapshot. `workspace_connections` and
`workspace_connection_secrets` are absent. No other client backends are connected.

Each option below is atomic: 0120 and 0121 run in one transaction, so a failure rolls
both back and leaves `public` at 0119.

1. **Authorize 0121 only through 0120, on `public`.**
   Take a `pg_dump` of `public` first, then a single `alembic upgrade 0121` with
   `DB_SCHEMA=public`. Post-check: revision `0121`, both new tables empty, `platforms`
   rows carry the archive snapshot and `sources.platform_id` unchanged. Downgrade path
   documented (`0120` refuses to roll back once post-migration platform writes exist).
2. **Hold the migration until the rollout that owns 0120.** 0120 is a shared platform
   configuration step, not a P12-T08 deliverable; applying it here binds the connector
   task to a decision that belongs to its own release.
3. **Apply 0121 in an isolated clone of `public`** to prove the two-revision jump on
   real data copy without touching the working schema, and leave `public` at 0119 until
   option 1 or 2 is chosen.

Owner chose option 1; it is recorded above with its post-state.
