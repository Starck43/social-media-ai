## Goal

Store references to messages from all channels in one tenant-scoped model while originals stay in their systems.

## Baseline

- `app/channels/telegram.py`, `app/channels/max.py`, listener in `app.runtime`; personal Telegram runtime is OFF under P12-T14 hard hold.

**Source authority (D24, [Q-21](../audit/q-21-source-authority.md)):** the channel owns the message and
its body; we keep metadata, the original URL and the content hash. Losing the original
marks the reference unavailable instead of filling a local copy.

## Plan

1. Models `unified_messages` (tenant, contact, connection, channel, original ID, direction, sent/received at, original URL, content hash, thread ID, read/archived, `unavailable_at`; unique `(tenant_id, connection_id, channel, original_id)` — R-09), `message_threads`, `contact_channel_stats`. D3 keeps metadata only, so no
   `message_content_cache` table is created; adding one is a separate measured decision.
2. Ingestion service `ingest(channel, connection, native_message)` with idempotent upsert and identity resolution to contacts (exact identifiers only).
3. Adapters: bot updates from existing listeners (Telegram bot, MAX bot) where workspace bindings allow; email via [P15-T01](p15-t01.md); personal Telegram only after P12-T14 lifts its hold.
4. Threading: email by `References`/`In-Reply-To`, messengers by chat ID; deleted originals → `unavailable` (TZ 2.5).
5. Retention registration and offboarding for all new tables.
