# P11-T46 — Offline guard drift: helper-built triggers are invisible to the P11-T24 extractor

Registry: [ROADMAP](../../ROADMAP.md); parent: [P11](../phases/p11-structure.md). Registered while
closing [P11-T40](../audit/p11/p11-t40.md); the contract that needs the change belongs to
[P11-T24](../audit/p11/p11-t24.md).

- **Status:** READY (2026-11-17) · owner `freepi-p11-t46` · branch `feat/p11-t46-guard-extractor`
- **Priority / complexity:** `P2` · `C2` (ROADMAP is authoritative)

## Problem

`migrations/versions/0157_p21t15_atomic_admission.py` creates four immutable guards through a module
helper instead of inline SQL:

```python
def _immutable(table: str, trigger_stem: str, message: str) -> None:
    function = f"reject_{table}_mutation"          # helper-built function name
    op.execute(sa.text(f"CREATE FUNCTION {S}.{function}() …"))
    op.execute(sa.text(f'CREATE TRIGGER "{trigger_stem}_immutable" …'))
    op.execute(sa.text(f'CREATE TRIGGER "{trigger_stem}_no_truncate" …'))
```

`tests/tooling/test_p11_t24_schema_guards.py` extracts guard DDL statically. Its own comment says a
helper-built name hides the parameter, so the parameter is only usable "when every interpolation
mentions it directly" — here the trigger name comes from `f"{trigger_stem}_immutable"` and the
function from a derived local, so all four blocks are classified run-time-only and dropped.

`scripts/schema_guards.py` does declare the guards (`GUARD_TRIGGERS`, `GUARD_FUNCTIONS`,
`BULK_TABLES`), so the drift is a *verification hole*, not a missing guard: the four triggers are
never compared against the module, and the bulk map is reported as incomplete.

The offline lane has therefore been red since `0157` merged; the acceptance of that migration did not
run the manifest.

## Expected change

Extend the extractor so a same-module helper whose parameters reach the SQL through an f-string
identifier (`f"{stem}_immutable"`, `f"reject_{table}_mutation"`) expands over its literal call sites,
the way `_statements()` already does for loops and direct interpolation. Where that cannot be made
sound, record the helper form explicitly instead of silently dropping the blocks, so a future
migration cannot add an unverified guard again.

`0157` itself is applied history and must not be rewritten to inline SQL. The frozen baseline
snapshot stays frozen; only the extractor and the drift expectations may change.

## Boundaries and rollback

Test/tooling only: no migration, schema, application or guard DDL changes. Rollback is reverting the
extractor commit — the four guards already exist in the database and in `scripts/schema_guards.py`
regardless of what the parser can see.

## Result (2026-11-17, `dev` `5c2f49ed` + this branch)

`tests/tooling/test_p11_t24_schema_guards.py` only; no migration, guard DDL, baseline snapshot,
runner or manifest changed.

1. `_CREATE_TRIGGER` accepts a quoted name and keeps the quotes outside the group, so
   `CREATE TRIGGER "stem_immutable"` yields the same `(name, table)` pair as the unquoted form.
   The expansion itself already worked — `_statements()` resolved `_immutable(...)` over its two
   literal call sites — the quoted name was simply never matched.
2. `_FUNCTION_DEFINITION_STRING` reads a body written as a SQL string literal
   (`AS 'BEGIN … ''quoted'' …; END;'`) and unescapes the doubled quotes; `_function_definitions()`
   merges both forms for `migration_function_names()` and `migration_function_bodies()`.
3. `ONE_OFF_TABLES` now lists `llm_token_allowance_reservations` and
   `llm_dispatch_reservation_events` with the comment that they are immutable/no-truncate-only
   (0157 adds no `_validate` trigger); `BULK_TABLES` still mirrors the module's validators one-to-one.
4. New pinning test `test_quoted_trigger_names_and_string_literal_bodies_are_read`, and the module
   docstring records that quoting does not hide an object.
