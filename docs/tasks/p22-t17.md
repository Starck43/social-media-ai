# P22-T17 — Confirmed task closure, reopening and schedule lifecycle

[Phase](../phases/p22-universal-tasks.md) · [Target architecture](../product/UNIVERSAL_TASKS.md) · [Desktop reference](../product/prototypes/workspace.html)

Build on the accepted [human task](../audit/p22/p22-t01.md), [run admission](../audit/p22/p22-t04.md), [actions](../audit/p22/p22-t05.md) and [interface](../audit/p22/p22-t07.md) contracts. T08 consumes the actions. This card owns the additive change to those accepted contracts.

- Preview the effects of closing the exact task version, require explicit confirmation and recheck the actor. Atomically record completion and disable future automation triggers. Preserve receipts and report any already admitted run separately. Guard concurrent scheduler admission and repeated confirmation.
- Keep completion of a recurring human occurrence available with its existing successor semantics. Explicit closure of scheduled work must not silently generate another occurrence. State the affected scope before confirmation.
- Reopening restores open work. Show an explicit choice before reactivating a paused schedule. Preserve the manual run action independently of scheduling. Use shared commands across web, CLI and agent tools.
- Accept with open, completed, overdue, recurring and scheduled tasks. Verify close vs scheduler race, stale version, replay, no duplicate successor or trigger, retained history and permission refusal.

## Solution

`app/services/commands/task_closure.py` is the confirmed lifecycle command. A preview
returns the effects of acting on the exact task version (status change, successor
occurrence, stored and enabled schedules, admitted run, retained receipts) plus an
actor-, tenant-, version- and choice-bound signed token (600 s). Confirmation rechecks
the actor, locks workspace → task → trigger in the scheduler's own order, compares the
effect fingerprint and only then writes.

- **Close** sets `done` with `completed_at`, disables the task's triggers
  (`enabled=false`, `next_due_at=null`) and keeps every run receipt. An already
  admitted `pending`/`running` run is reported in the effects and left untouched.
- **Successor rule.** A close creates the next occurrence only for a human recurrence
  without any stored trigger; the reuse lookup makes a repeated close reuse the
  occurrence it already admitted instead of inserting a second one. A task under
  automation (armed or paused schedule) closes without a silent occurrence.
- **Reopen** restores `todo`, clears `completed_at` and takes an explicit
  `reactivate_schedule` choice that is bound into the token. Reactivation reuses the
  T04 arming path (`TaskTriggerService._arm`, extracted from `configure`), so the same
  published-revision, scheduled-principal and admissible-plan checks apply; an
  unavailable schedule refuses the whole reopening.
- **Replay.** A repeated confirmation converges: closing an already closed task only
  re-applies the trigger hold, reopening an already open task only re-arms when the
  choice asked for it. Neither bumps the version twice nor duplicates effects.
- **Race.** `admit_manual` and `_insert_run` refuse closed work with
  `TaskRunAdmissionError("task_closed")` (API `409`), and the closure fingerprint
  contains the trigger, active run and receipt count, so an occurrence admitted after
  the preview forces a re-preview instead of an unreported close.
- **Surfaces.** `/api/v2/tasks/{id}/close|reopen|schedule` (+ `/preview`),
  `worktasks close|reopen|schedule`, and five `work_task_*` tools call the same
  services; the parity test keeps the three surfaces identical. `canonical_task_actions`
  now offers `close`/`reopen`/`schedule` (with `enabled`) and keeps `complete` for a
  human recurrence without a stored schedule and `run` independent of scheduling.

Decisions made inside the executor's authority (with rollback): closing a task whose
schedule is paused also suppresses the successor (rollback: treat a paused trigger as
absent in `_state`); calendar-owned occurrences refuse the canonical command
(`task_closure_denied`) because their source still writes them.
