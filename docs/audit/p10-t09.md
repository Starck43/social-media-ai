# P10-T09 — Truthful Home pipeline counts and activity labels

**DONE — accepted by the owner 2026-10-26** (independent audit at

`94c559e1302174b6f9011cfd7afa8a2174784e86` (PR #250 head, included base

## Finding

The Home strip projected at most three pending/running jobs as if the
counters were queue totals, labelled every running non-collect job as an LLM
analysis (`Модель анализирует…`), called all stored CollectedItem rows
`ожидают анализа`, and promised pending jobs would start soon without
checking `run_at`.

## Solution

The existing bounded preview is retained, not replaced with total/eligibility
reads. `dashboard._pipeline` marks the projection an explicit preview
(`preview_limit = 3`), orders it stably (`created_at` desc, then `id` desc),
and derives both the running and pending counters only from that sample.
Activity labels are a fixed per-type map (collect, analyze, digest, prune,
learn, reflect) with a neutral label for unknown/null types; the raw
`job_type` is never interpolated into the template. The staged counter is
labelled the literal stored-material count (including already-analyzed
rows), the empty state names pending/running jobs, and the pending state no
longer promises an immediate start. [P10-T08](p10-t08.md) permission gates,
tenant filters and the `limit(3)` bound are unchanged. The card's
explicit-preview/literal-count acceptance alternative was chosen and is
documented in [API.md#web-home-overview](../API.md#web-home-overview).
