## Goal

Specify a secure, outbound-only protocol before any desktop code (R-05).

## Baseline

- Catalog descriptor `LOCAL_GATEWAY` (certificate fingerprint); local connector constraints in PRODUCT_PLAN; `local_only` boundary (P12-T11).

## Plan

1. Pairing: user starts pairing in Settings → one-time code (short TTL) → connector generates a key pair, sends CSR + code over HTTPS → server issues a device certificate / registers the public-key fingerprint bound to tenant + owner user.
2. Channel: connector keeps an outbound mutually authenticated WebSocket (fallback long-poll) to the cloud; requests are signed envelopes with request ID, actor, tenant, operation, limits, expiry.
3. Operations allowlist: `health`, `index.status`, `search`, `file.metadata`, `file.fetch` (explicit user request only), `index.delete`; everything else rejected by the connector.
4. Limits: response size, snippet length, result count, timeouts; cloud never receives full file content except via `file.fetch`.
5. Revocation: device disable in Settings; connector wipes local tokens on revocation notice; server rejects revoked fingerprints immediately.
6. Write `docs/LOCAL_CONNECTOR_PROTOCOL.md` with threat model (stolen device, malicious server message, path traversal, injection in file content).
