new `task-hub.css`, `task-editor.css`, `task-editor.js`); it does **not** close the
finding. `task_quick_create.html` still offers only title, description, due date/time,
priority, assignee and visibility.

**Blocker found while closing the finding.** The finding cannot be closed inside T08 as
scoped. `task_trigger_service.configure` arms only a schedule whose plan revision already
exists (`execution_plan_service._revision`, refusing `plan_revision_unavailable`
otherwise), and `execution_plan_service.publish` has **no caller in `app/`**: every
reference is a test. No web route, no API route, no CLI command and no agent tool
publishes a plan revision. The API exposes `/{task_id}/plan/preview` and nothing that
persists. Consequently a task created through any shipping surface has no revision, so
`canonical_task_actions` never offers `run` and never offers `schedule`; the «Выполнение»
section in `task_hub_detail.html` can only appear for a task whose revision was published
out of band.

This is a gap in the P22-T03/T07 delivery, not a T08 regression: T07's audit states the
API "resolves the published revision itself, so the caller never supplies a version to
run", which presumes a publisher that no surface provides. The prototype's automation
branch (sources → scenario → `Когда запускать?`) is therefore not a template detail that
T08 dropped; it is the missing authoring surface for execution plans.

**Consequence for the card.** The Acceptance clause "create a deadline note, a team
assignment and a scheduled collection" is unreachable until a plan can be authored and
published from a user surface. Two ways out, and the choice is the owner's:

1. Add plan authoring and publication (preview → publish → arm) as its own task, then
   return to T08 and wire the editor's automation branch to it.
2. Narrow T08's Acceptance to what the shipping stack supports, and record the
   automation branch as deferred to that new task.

**Not done here.** No template, service or test change was made in this round. Rendered
evidence stays waived by the owner. `pytest` cannot run in this worktree:
