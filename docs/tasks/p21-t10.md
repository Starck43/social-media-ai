# P21-T10 — Prompt and tool safety coverage audit

Registry: [ROADMAP](../../ROADMAP.md); parent: [P21](../phases/p21-ai-operations.md).

Prerequisites: none.

## Goal

Produce a source-backed coverage matrix for untrusted social, file, web and user
content entering prompts, especially paths that expose write/publish tools.

## Dependencies and scope

- Independent read-only audit; findings feed P21-T12 and later implementation.
- Inspect `prompt_sanitizer`, `frame_untrusted_text`, prompt builders, agent
  runtime/tool specs, research delegation, drafting, learning and attachment paths.
- Include role separation, delimiters, tool confirmation, tenant/actor recheck,
  max iterations and timeout behavior.
- Include [P2-T17](p2-t17.md)/P21-T12 host-owner sponsorship as a target control:
  prompt/tool input cannot change the plan holder, payer or catalog. Test attempts
  by invited broad-role users to manage the host tariff/models or expose BYOK;
  distinguish current coverage from future migration requirements.

## Steps

### Executor handoff

Start at `app/agent/` tool dispatch and the source callers of `prompt_sanitizer`
and `frame_untrusted_text`, not the helper definitions alone. For each entry point
record trusted/untrusted roles, truncation, allowed tools, confirmation and the
actual execution authorization call. Use synthetic input only; mark missing
current controls as findings, not as implemented P2-T17 behavior. Deliver exact
caller references and a prioritized remediation list to P21-T12. This audit can
finish independently of tariff storage and makes no schema changes.

1. Enumerate every external-text source and prompt entry point.
2. Mark each path as framed, sanitized, role-separated, tool-capable and bounded.
3. Identify gaps where external content can influence a write-capable tool call.
4. Reproduce only with synthetic malicious strings; do not use live provider data.
5. Write prioritized findings with minimal remediation cards or explicit accepted
   residual risk.

## Acceptance

- Matrix covers social posts/comments, web research, files, messages and user
  input, including empty/oversized/malformed content.
- No claim relies on the existence of a sanitizer without a caller-path check.
- Tool-enabled paths prove confirmation plus fresh permission/identity checks and
  bounded iterations/timeouts.
- Findings name exact files/lines, severity, reproduction and rollback; no secrets
  or live external content are included.

## Boundaries

This card does not redesign prompts, add a model, or reopen the accepted P5 phase;
implementation findings become separately scoped tasks.
