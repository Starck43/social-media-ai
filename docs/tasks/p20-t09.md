# P20-T09 — Inbox triage and agent-suggested replies

Registry: [ROADMAP](../../ROADMAP.md#p20); status, owner and dialogue live there. Parent: [P20](../phases/p20-proactive-assistant.md). Design: [WORKSPACE_UX](../WORKSPACE_UX.md). Request: https://app.notion.com/chat?t=40fa7457748980d094a100a930619250

## Goal and dependencies

Help a user work through correspondence: classify threads and propose the next step, while sending stays with the outbox. Depends on [P15-T04](p15-t04.md) (inbox) and [P15-T08](p15-t08.md) (reply path); reuses the [P20-T02](p20-t02.md) attention contract and baseline-first evaluation.

## Scope

- Classify threads «Нужен ответ», «К сведению», «Подождёт», «Не уверен» with a reason, using metadata and only content the actor may read under D3/D11; no body cache or index is added.
- Propose, never perform: a reply draft (enters [P15-T05](p15-t05.md) as an ordinary draft), a planner task, a follow-up or a document draft. Each proposal is editable and explicit.
- Provider for «Сегодня» and the chat «Ждут решения» tab; corrections by the user are recorded as our decision, not as a model fact.
- Team mailboxes: show assignee only if the inbox model supports it; shared-inbox assignment is an open doubt, not scope.

## Acceptance and checks

- Labelled representative fixtures with baseline/result metrics and false-negative examples; prompt-injection in messages; cross-tenant and revoked-connection threads; model failure and budget denial visible; no send without the outbox approval. Mock models and transports.

## Open doubts

Shared-inbox ownership and model cost per thread. Default: personal inbox only, deterministic baseline first, owner approval before paid model use.

## Execution record

Unclaimed.
