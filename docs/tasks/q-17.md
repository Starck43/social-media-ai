# Q-17 — Web test-suite debt in `tests/unit_web/`

**Status: OPEN · unassigned.** Raised while closing [P12-T16](../audit/p12-t16.md), where a
wide run exposed failures that reproduce on the clean base and have nothing to do
with that task.

A `pytest tests/unit_web/` run over `dev` at `1b470838` aborted during collection
(`ModuleNotFoundError: bs4`, one file) and left 28 failures plus 4 errors across
six files once collection was repaired. Each group has its own cause and none of
them is a product regression — they are tests that stopped tracking the code they
describe.

## Why this is not one bug

| File | Count | Cause |
|---|---|---|
| `test_assistant_shell.py` | 17 | Template fixture lacks `has_admin_access`, which the shell now renders. |
| `test_template_autoescape.py` | 5 | `TypeError: Object of type Undefined is not JSON serializable` — the template reads a key the fixture never sets. |
| `test_task_source_picker.py` | 4 (errors) | `NameError: name 'Path' is not defined` in the isolated loader — same shape as the `test_attention_feed` defect. |
| `test_workspace_access.py` | 3 | `NameError: name 'resolve_operator_identity' is not defined` — the function was renamed or moved. |
| `test_analysis_result_ids.py` | 2 | `TenantContextError: Entitlements require a concrete normal workspace scope`. |
| `test_p12_t10_provider_presentation.py` | 1 | Asserted copy changed in the rendered markup. |

Two of these carry security intent and are currently silent:
`test_template_autoescape` guards script-breakout in the task editor, and
`test_analysis_result_ids` exercises tenant scoping. A green run that skips them
is not evidence.

## Fixed on the way

- `tests/unit_web/test_attention_feed.py` kept hand-rolled loaders for `_context`
  and `_read_context`, deleted in `e875d9f1` (P4-T02/P9-T08). They could not run:
  the routes now use `Query()` defaults, and the functions no longer exist. The
  protection they aimed at lives in `app/web/middleware.py` (membership,
  `tenant_id`) and in `_active_user` + `ensure_csrf` on the routes, so the tests
  were removed rather than rewritten against a dead API. 42 passed afterwards.
- `beautifulsoup4` was never declared but `test_p12_t17_evidence_ui.py` imports it
  (that file lives on the P12-T17 branch, not on `dev`). It is now in the `dev`
  extra of `pyproject.toml` and the profile exports were regenerated; without it a
  single missing package turns the whole directory into a collection abort.

## Scope

Bring each file above back in line with the code it tests, preserving the intent
of the assertions. Where a guard genuinely changed, prove that the protection
moved (middleware, a renamed helper, a render-time default) before removing an
assertion — never weaken a test merely to obtain a pass.

Judgement on `pyproject.toml` dependency edits applies: `requirements/*.txt` are
generated by `scripts/packaging/dependencies.py export`, which requires the
compiler pinned in `requirements/tools.txt`; edit `pyproject.toml`, then
regenerate and let `check` confirm parity.

## Acceptance

1. `DB_SCHEMA=public .venv/bin/python -m pytest tests/unit_web/ -q -o addopts="" -p no:cacheprovider`
   completes with no collection errors.
2. Every remaining failure is either fixed or recorded with evidence that the
   guard moved, not vanished.
3. The run command and the tested revision are recorded in the closing evidence.
