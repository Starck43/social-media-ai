- Change: one global `login_attempts` row per key (`account` = casefolded
  identifier, `address` = client host). `guard_login` refuses when either key is
  locked, `record_login_failure` counts the failure atomically (upsert; the count
  restarts after `LOGIN_TIMEOUT_MINUTES`), `clear_login_failures` deletes the
  account row on a proven password. The account budget is `MAX_LOGIN_ATTEMPTS`,
  the address budget the new `LOGIN_IP_MAX_ATTEMPTS`. The console, `/app/login`
  and `POST /api/v1/auth/login` all call the same three functions, so a cleared
  cookie and a second process spend the same budget. `authenticate` now verifies a
  real placeholder bcrypt hash for unknown accounts (the previous literal
  `"dummy_hash"` failed before doing real work) and answers one generic detail for
  unknown, wrong-password and inactive accounts; the console keeps its
  "no console access" answer only for a correctly authenticated non-operator.
  The session-cookie counter methods are removed from `AdminAuthBuilder`
  (`track_login_attempt` / `check_login_lockout`); `DEBUG` no longer disables the
  limit.
