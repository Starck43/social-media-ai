## Goal

Close the four low findings the P17-T06/P17-T08 audits carried forward, so the 1C caches behave as their public surface promises and no request is spent before a refusal.

## Baseline

- [P17-T08 accepted](../audit/p17-t08.md): N1 (the catalog cache is never invalidated), N2 (insertion-ordered eviction), N3 (the catalog is fetched before the stored plan loads).
- [P17-T06 accepted](../audit/p17-t06.md): N1 (the same ordering, from the continuation path).
- [P17-T03 accepted](../audit/p17-t03.md): the T02 result cache is per service instance, so the API's `cache_ttl_seconds` has no effect between requests and the in-process query-history metadata never outlives one call.

## Plan

1. **Cache lifecycle.** Call the catalog invalidation from the paths that change a connection's endpoint, credentials or `metadata_sha256` pin, and prove it with a test; document the residual staleness (bounded by the TTL) for an edited connection whose pin does not change.
2. **Eviction.** Make the bounded catalog cache evict least-recently-used, or keep insertion order and record why 32 entries make it acceptable.
3. **Ordering.** Load the stored plan before the catalog in the query path, so a continuation with a foreign `history_id` is refused without any provider request or budget token.
4. **Request-cost surface.** Either share the read service so the result cache and the in-process query history work across requests, or remove `cache_ttl_seconds` from the public API and document that rows are not cached between requests. Record the choice; do not leave a knob that does nothing.

## Acceptance

- An edited connection never serves a stale catalog beyond the documented bound, and the invalidation is exercised by a test.
- A continuation with a foreign `history_id` spends no provider request and no budget token before the refusal.
- `cache_ttl_seconds` either works across requests or is no longer part of the public API — with the choice recorded in the card.
- No cache entry crosses a tenant or an actor boundary.
