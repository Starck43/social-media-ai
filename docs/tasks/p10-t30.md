# P10-T30 — committed catalog fixtures must survive test-schema reset

Registry: [ROADMAP](../../ROADMAP.md#p10); current status/owner live there.

Parent: [P10](../phases/p10-audit-hardening.md). Found during the P10-T16
audit on 2026-10-26 (`tests/models/` run at `7898e670`).

## Scope and acceptance

`tests/models/test_llm_models_manager.py` (26 tests) pins the committed
fixture `users.id=2` — the legacy personal-catalog owner written by migration
`0109_personal_llm_ownership` (`owner_user_id=2`) — as the FK target of
`llm_providers`/`llm_models`. `python -m scripts.setup_test_db --reset`
truncates every base table and re-seeds only the reference rows (roles,
permissions, platforms, bootstrap tenant), so after a reset the committed
catalog-owner fixture is absent from `test_schema` and the whole suite fails
with `ForeignKeyViolationError` before any of its assertions run. Schemas
aligned through real `alembic upgrade` execute the 0109 data change and keep
the fixture; the documented create_all + `stamp head` test path never had it
or loses it on reset.

Accept: after a fresh `--reset`, `pytest tests/models/test_llm_models_manager.py`
passes; the committed fixture is restored by the re-seed step (documented in
the script and in this card) or the suite creates and removes its own
isolated owner actor — no assertion is weakened, no record is left in
`test_schema` beyond documented committed fixtures, and `public` stays
untouched.

Owns: the re-seed path of `scripts/setup_test_db.py` and, only if the
suite-side option is chosen, `tests/models/test_llm_models_manager.py`.
