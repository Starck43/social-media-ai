# P11-T43 — Shared test_schema is behind the dev model metadata

Registry: [ROADMAP](../../../ROADMAP.md); parent: [P11](../../phases/p11-structure.md)
(accepted phase, registered follow-up from [P11-T39](p11-t39.md)). No prerequisites.

## Goal

Restore a validated test target that matches the current checkout so conftest-
based suites can run again. This is schema maintenance, not a product-code fix,
and a shared-schema change needs the owner's authorization before it is applied.

## Evidence (reproduced 2026-11-16 on `53d2b533`)

Every root-conftest suite stops in the session `_test_database` fixture before
any test body:

```
RuntimeError: Test bootstrap refused: model tables still absent after table
creation: llm_dispatch_leases, llm_rate_buckets. Stop; no reference rows
were seeded.
```

`scripts/setup_test_db.py:309` via `tests/conftest.py:144`, schema `test_schema`.
The two missing tables come from the accepted P21-T14 rate-control migration.

Observed impact:

  the manifest runner with `--noconftest` remains usable.
- `tests/tooling/test_p8_t41_surface_contracts.py`: 7 setup errors (root
  conftest); the source-only variant runs and exposes [P11-T41](p11-t41.md).
- `tests/tooling/test_q14_single_initial_revision.py`: 3 setup errors under root
  conftest, but **3 passed** with `PYTHONPATH=.:tests --noconftest` — no product
  debt, this entry is dropped from the red inventory.
- `tests/billing/test_budget_isolated_fixture_coherence.py`: 11 setup errors
  (root conftest); source-only runs and exposes [P11-T42](../../tasks/p11-t42.md).
- `tests/knowledge`: **374 setup errors**, all with the same bootstrap message.
  The old scratch claim of "7 environment failures" is not reproducible.

Schema-layout snapshots were taken with `scripts/ci/schema_inventory.py`
before and after the `tests/knowledge` run; the `--diff` reported no changes, so
the run left no residue. No public-schema writes were attempted.

## Scope and acceptance

- Record the exact failing prerequisite and the DB target/schema in this card.
- Bring a task-owned test target up to the checkout's model metadata, verify it
  with `scripts/ci/schema_inventory.py`, and re-run one conftest suite to prove
  the gate is gone.
- Shared `test_schema` migration/reset is an owner decision: changing it affects
  other active lanes. Do not reset, drop or repair it to make a suite green
  without that decision.
- Confirm no synthetic rows remain after any DB-touching verification.

## Rollback

Snapshots in this card are evidence only. A task-owned schema can be dropped;
the shared one is never rolled back without an inventory and the owner's choice.
