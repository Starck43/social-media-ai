# P15-T13 — Personal Telegram collect loses the source owner

Registry: [ROADMAP](../../ROADMAP.md#p15); status, owner and dialogue live there.
Parent: [P15](../phases/p15-communication-hub.md).
Found during the P15-T12 acceptance
([card](p15-t12.md#acceptance-2026-11-07)).

## Goal and dependencies

Make `app/jobs/handlers.py::_runtime_source()` preserve the source owner so a
personal Telegram collection resolves its pinned grant on the default path.
Depends on P15-T12 (accepted, `f3d28601`).

## Defect

`_runtime_source()` copies the wrapped `Source` into an in-memory
`SimpleNamespace` view and omits `owner_user_id`. Steps down the personal lane:

1. `collect_personal_telegram()` calls `source_grant_selection(source)`.
2. `source_grant_selection()` reads `params["token_owner"]`; when it is absent it
   falls back to `getattr(source, "owner_user_id", None)`.
3. On the handler's view that attribute does not exist, so `owner` is `None`,
   `SourceGrantSelection.__post_init__` raises `AuthorizationUnavailable`, and the
   run is recorded as `error` (`connection_unavailable`) instead of collecting.

`_runtime_source()` only adds `token_owner` for task-generated sources. An
existing selected source stored without an explicit `token_owner` therefore
never collects through the personal path, even though the persisted row has the
correct owner.

## Scope

- Carry `owner_user_id` in the runtime view so the documented fallback works.
- Do **not** widen the grant resolution: the pin must still come from the
  stored binding (`grant_id`, `authorization_revision`), and the owner must still
  be matched against the grant/authorization rows.
- Add a regression test that builds the handler's view from a real row with no
  `params.token_owner` and asserts the selection resolves and matches the
  persisted owner.
- Confirm no behaviour change for task-generated sources, which keep their
  explicit `params["token_owner"]` pinning (including the `0` sentinel for a
  missing owner).

## Out of scope

- The fail-closed policy itself, grant/authorization storage, and the Telegram
  runtime fence. P15-T11/T12 own those contracts.
- Any migration: this is an in-memory view fix.

## Acceptance

- New regression test fails before the fix and passes after it.
- `tests/channels/` and the P15-T11/T12 focused sets stay green.
- One real-DB check on `test_schema` at head `0141` proving a source without
  `params.token_owner` reaches the personal lane instead of `connection_unavailable`.
- No synthetic records or sources left behind.
