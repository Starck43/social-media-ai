## Delivered behavior and corrections

`POST /api/v1/documents/draft` generates typed paragraphs through the acting user's eligible LLM chat fleet, using typed templates, authorized case/knowledge snippets and allowlisted CRM contact context. Missing required variables prevent writes. Unsupported statements are highlighted; legal/financial statements require human review. Every generated revision starts as an unapproved draft.

The review corrected these concrete defects:

1. The original production path silently synthesized text without calling the LLM. Production now uses `chat_with_fallback`, existing model ownership/personal payer/admission and attempt-journal machinery, and the `document_draft` purpose. Workspace preflight includes captured drafting-purpose costs without double counting the legacy chat/digest/job projections. Exhausted positive caps or unresolved captured draft costs refuse dispatch; configured zero retains the existing unlimited meaning.
2. The original DB fixture used nonexistent `Contact.data_boundary`; its contact boundary gate also fell back to the requested value. Contacts now use tenant plus `contact.VIEW` authorization and only display name/channel, following the existing CRM drafting allowlist. Contacts have no invented clearance/hash/citation metadata. Knowledge snippets retain real destination-clearance predicates and must be source-readable before their text is copied into the new document.
3. A valid citation identifier alone could mark an unrelated claim supported. Automatic support now requires an exact normalized full-excerpt quotation. Paraphrases, negation changes, mixed/unrelated claims and fabricated citations remain highlighted for human review. JSON-schema properties omitted from `required` are optional. Common currency-symbol amounts trigger financial review.
4. Empty/malformed provider output could fall back to deterministic synthesis or cause an uncaught error. Strict nonempty typed JSON is required; provider unavailability or invalid provider output maps to sanitized HTTP 503. Permission/billing exceptions and cancellation preserve their behavior. Supplied source/template/CRM/request strings are marked untrusted in the prompt.
5. Document authorization held User/Tenant shared locks over provider I/O while personal billing needed update locks in a separate transaction. The service now commits a short authorized snapshot transaction, calls the provider outside DB transactions, then reauthorizes/reloads and compares the complete request/context fingerprint in a fresh persistence transaction. Changed context refuses storage. A production call cannot borrow a caller-owned session; the synchronous injected test seam preserves caller ownership.
6. Fresh dev was merged normally in `5773cbe2`; stale registry edits were reconciled to the separately published claim. No force-push was used. Later P17 registry and P11 notification-test changes affected no delivered application/knowledge/migration paths or knowledge-test imports.

Changes are in `app/services/knowledge/drafting.py`, the document API endpoint, generated route table and four `tests/knowledge/test_p19_t02_*.py` files. No migrations were added. Existing template CRUD and document approval/delivery contracts remain the integration baseline.
